# 科技：前置、尤里卡与直接解锁

需要规划科研、解释某科技能带来什么或核对锁定原因时读本页。具体名称、基础成本、前置、尤里卡及直接解锁在 [科技规则卡](../rules/technologies.json)。

## 前置与尤里卡

关系解释：`TechnologyPrereqs` 中同一科技的多条前置，在普通静态树中按共同条件核对。进入活动随机树时，实际前置可能与静态表不同；需要读取本局候选及前置，不能从离线树证明当前可研究。

`Boosts` 的科技记录保存尤里卡条件及原始参数。条件可能涉及单位、建筑、资源、数量、其他科技或需求集合；完整读取后再判断能否触发。`Boost` 值是源数据，最终效果还受规则与能力修正，不能将原始数字直接当作本局完成比例。

解释：比较路线时，同时检查研究本身的成本、尤里卡的额外投入和解锁后是否能立即利用。更早完成科技不自动代表更高收益；区域建设、战略资源与生产能力可能是后续瓶颈。

## 理解解锁范围

直接解锁根据对象的 `PrereqTech` 等明确字段提取。资源表中的科技关联可能表示揭示、开采或改良前置，需读取关联类型及原始字段，不能统称为「获得资源」。单位、建筑、区域、改良、项目和路线仍保留各自条件。

| 资料显示的关系 | 执行前还需核对 |
| --- | --- |
| 科技解锁单位 | 文明专属／替代、战略资源、城市生产和其他前置 |
| 科技解锁建筑或项目 | 区域、先行建筑、城市条件、费用与相关模式 |
| 科技解锁区域 | 人口容量、合法落位、文明特性及本局成本 |
| 科技关联资源或路线 | 关系字段的确切含义、已发现地块、建造／改良条件 |

通过 Modifier 或脚本产生的条件效果，本期不作为完整直接解锁清单求值。需要解释「完成后为何仍不可用」时，先核对目标对象的限制，再展开来源；缺少一条关联不是没有该效果的证据。

## 与当前游戏连接

`get_tech_civics` 提供当前研究、引擎研究费用与进度、尤里卡状态、候选和部分锁定前置。其展示范围不是完整科技树；市政预计回合与科技预计回合的计算也不应混用。具体生产使用 `get_city_production`，资源使用 `get_empire_resources`，可见地块使用 `get_map_area`。

以 `TECH_WRITING` 为例，规则卡可定位写作到学院的直接解锁；接着读 [区域建设](districts.md)，再用 `get_district_advisor` 查询某城市的可建位置。若目标受市政影响，转到 [市政](civics.md)。

完成研究选择后才使用 `set_research`（`category="tech"`），以提交回读确认实际研究目标；资料查询不会改变游戏状态。

## 需要深查时

```sh
python3 query.py show TECH_WRITING --level rule
python3 query.py show TECH_WRITING --level evidence
```

命令从知识目录执行。[快照](../sources/snapshot.json) 中的 `Technologies`、`TechnologyPrereqs`、`Boosts` 及各解锁对象表提供原始记录；`code_evidence` 的 `technology-live-prerequisites` 保留随机前置与原始数据的读取方式。关系定位与来源索引以规则卡为准。
