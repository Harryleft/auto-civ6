# 市政：前置、鼓舞与解锁

需要规划文化研究、政体或政策时读本页。具体市政的名称、基础成本、前置、鼓舞和直接解锁在 [市政规则卡](../rules/civics.json)；按稳定 ID 查询可避免译名差异。

## 判断研究路线

`CivicPrereqs` 将目标市政关联到其前置市政。关系解释：普通静态树中，同一目标的多条前置按共同条件核对；不要任选其中一条就判断已解锁。随机树等模式可能改变本局前置，资料中的静态关系不能重建活动随机树。

`Boosts` 中的市政记录描述鼓舞触发条件。读取条件文本时一起核对数量、对象、需求集合及其他字段；原始 `Boost` 值并不代表所有文明、速度和修正下的最终完成比例。是否已触发、剩余文化成本和当前候选需要实时查询。

解释：规划时可沿前置寻找距离目标最近的缺口，再比较鼓舞能否自然达成。为触发鼓舞额外投入的单位、生产和回合成本，应与提前解锁的收益共同判断；规则卡不提供统一的最优路线。

## 解锁不等于立即可用

直接解锁来自对象的 `PrereqCivic` 字段，包括政策、政体、单位、建筑、区域、改良、项目等实际采集对象。保留对象的原始限制：文明／领袖特性、科技前置、区域、资源和地块条件仍可能阻止使用。

政策解锁后还要核对本局政策槽位、现任政体、是否已经过时以及能否调整。政体解锁与更换政体是不同动作。通过 Modifier、脚本或条件需求产生的间接收益不等于直接解锁；本期没有完整展开这些链条，查不到时先看覆盖标记及原始证据。

市政影响区域建设或科技路线时，沿规则卡关系分别查 [区域建设](districts.md) 与 [科技](technologies.md)，只展开与候选行动有关的对象。

## 与当前游戏连接

| 需要的当前事实 | 现有 MCP 工具 | 使用边界 |
| --- | --- | --- |
| 当前研究、进度、鼓舞状态和展示的前置 | `get_tech_civics` | 输出会筛选候选与部分锁定条目；没有列出不等于永久不可研究 |
| 现任政体、政策槽位和可用政策 | `get_policies` | 以当前可用选项核对解锁后的使用条件 |
| 帝国与城市的当前需求 | `get_game_overview`、`get_cities` | 用于比较文化路线的实际价值 |
| 具体生产对象是否可建 | `get_city_production` | 进一步核对城市、资源和区域条件 |

完成选择后才使用 `set_research`（`category="civic"`）；政策和政体分别由 `set_policies`、`change_government` 提交。提交结果与后续状态回读确认实际变化，知识查询不执行这些动作。

## 需要深查时

```sh
python3 query.py show CIVIC_CODE_OF_LAWS --level rule
python3 query.py show CIVIC_CODE_OF_LAWS --level evidence
```

命令从知识目录执行。原始来源见 [快照](../sources/snapshot.json) 的 `Civics`、`CivicPrereqs`、`Boosts`，以及规则卡解锁引用指向的对象表。`code_evidence` 的 `civic-live-prerequisites` 说明静态树与活动随机前置的区分。具体引用索引以规则卡和快照为准；文本缺失、外部关联和未解释 Modifier 保留为覆盖缺口。
