# 游戏状态变更生命周期规格

**Status:** resolved

18 票已全部合入 `codex/mutation-lifecycle`。最终离线回归 3856 项通过，冻结提交 `c64201e` 的 Standards／Spec 独立复核均无实质问题；18 个实施工作树已清理。结果与审查记录见[全量验收](../../docs/acceptance/2026-10-19-mutation-lifecycle.md)。

## Problem Statement

当前项目声明 82 个 MCP 工具，其中 43 个能改变游戏、界面、存档或进程状态。已有动作、回合和外交所有者，但购买、治理、单位任务等仍有直接提交路径。回应丢失、延迟生效或调用被取消后，系统可能丢失原意图，重复花费资源、处理错误对象，或在操作未完成时继续推进。

使者试点已证明：问题能够通过保留原请求、单次提交、读取真实结果和阻止未决期间依赖操作来解决。现在需要把这一规则落实到全量审计中的其余入口，而不是继续增加局部补丁。

## Solution

所有受支持的业务变更都明确区分未提交、已确认、结果未知。未知时保留原意图；同意图再次调用只确认原请求；确认完成后，下一次独立调用才是新操作。消费操作核对资源与指定目标，目标状态操作核对实际目标状态，多步骤操作保留已完成部分，不整段重发。

继续使用现有 ActionLifecycle、TurnProgress、DiplomacyProgress 和显式存档／进程生命周期。以现有使者实现为样本逐项迁移，保持少量清楚的接口和领域专属证据。运行模型明确为单一 MCP 控制游戏；人工或第三方并发操作不纳入问题、设计、防御和验收。

## User Stories

1. As an 游戏代理, I want 超时后仍能看到原请求的未决状态, so that 我不会误以为操作没有执行。
2. As an 游戏代理, I want 重复同意图只读取原结果, so that 我不会重复消费资源。
3. As an 游戏代理, I want 不同意图等待当前未决操作确认, so that 操作结果不会相互覆盖。
4. As an 游戏代理, I want 查询在未决期间仍可用, so that 我能获得恢复和决策所需事实。
5. As an 游戏代理, I want 单位、城市和玩家绑定完整身份与世界, so that 陈旧 ID 不会操作新对象。
6. As an 游戏代理, I want 换世界或回合后不追认旧操作, so that 新状态不会冒充旧请求的结果。
7. As an 游戏代理, I want 收到明确原生拒绝时知道没有提交, so that 我能修正参数而不陷入不必要等待。
8. As an 游戏代理, I want 取消调用后保留可能已提交的请求, so that 中断不会解除门禁。
9. As an 游戏代理, I want 购买地块时同时核对指定地块与资源变化, so that 成功表示实际购买完成。
10. As an 游戏代理, I want 购买单位、建筑和支持的项目时确认精确目标, so that 旧有同名对象不会冒充新购买。
11. As an 游戏代理, I want 升级、晋升和删除绑定原单位, so that 消耗或实体替换不会导致重复操作。
12. As an 游戏代理, I want 总督任命、晋升与指派都有结果确认, so that 头衔和城市指派保持一致。
13. As an 游戏代理, I want 科研和市政选择等待实际生效, so that 一次旧读数不会触发另一通道写入。
14. As an 游戏代理, I want 政体和时代承诺确认实际选择, so that 回执不会被当作完成。
15. As an 游戏代理, I want 付费政策解锁和换卡保留部分进度, so that 未知结果不会再次付费。
16. As an 游戏代理, I want 自动探索、治疗、警戒、休眠确认原生任务状态, so that 后续回合依据真实就绪状态推进。
17. As an 游戏代理, I want 建造、维修、移除与道路操作确认单位和地块结果, so that 次数消耗与地块改变可以核对。
18. As an 游戏代理, I want 商路和商人转移绑定原单位及目的城, so that 延迟执行不产生重复路线。
19. As an 游戏代理, I want 伟人招募、赞助和拒绝绑定原 individual, so that 重复请求不会处理下一位伟人。
20. As an 游戏代理, I want 伟人激活和传教确认可测量的次数／实体／目标效果, so that 输出准确区分操作完成和未测量奖励。
21. As an 游戏代理, I want 占城决定绑定请求中的原城市与待决项, so that 重入不会处理队列中的下一座城。
22. As an 游戏代理, I want 间谍旅行和任务确认正确间谍的目的地与任务, so that 选择完成不被说成旅行或任务结果已发生。
23. As an 游戏代理, I want 万神殿与宗教创建保存阶段, so that 三个原生命令中部分完成也不会整段重发。
24. As an 游戏代理, I want 和平、友谊、使团、使馆、同盟、谴责和宣战保留原请求, so that 外交关系不会被重复改变。
25. As an 游戏代理, I want 宣战视图清理受原世界和会话约束, so that 延迟任务不会修改后来会话。
26. As an 游戏代理, I want 议会打开、分项投票和提交保留阶段, so that 已投票部分不会重新消费外交支持。
27. As an 游戏代理, I want 存档在取消或原生异常后保持未决, so that 未确认文件不会成为恢复检查点。
28. As an 游戏代理, I want 显式恢复继续受已确认检查点约束, so that 架构改造不损坏存档或暗中重启。
29. As an 嵌入调用者, I want 直接 GameState 调用遵守与 MCP 一致的门禁, so that 我不能从另一入口绕过未决状态。
30. As an 维护者, I want 每项迁移有公开入口故障注入测试和覆盖清单, so that 后续变更不会重新引入直接提交缺口。
31. As an 维护者, I want 任意 Lua 调试执行有明确边界, so that 系统不会假装能推断任意代码的业务完成条件。
32. As an 维护者, I want 所有工作项和审查修复汇入同一集成分支, so that 我能一次审阅完整实现与验证证据。

## Implementation Decisions

- 保持现有领域工具名称和参数；确有含混的占城意图改为核对传入城市 ID，错误对象在提交前拒绝。
- ActionLifecycle 仍是普通动作的唯一未决所有者。若多个真实动作需要相同协议，只扩展已有接口，避免每增加一个动作都复制共享状态机或增加分散的 kind 分支。
- 原意图包含动作类别、精确对象、影响结果的参数和原世界／回合／玩家。意图相等不比较观测缓存、请求 token 或展示文本。
- 在进入可能提交的 await 前保存未决；只有已确认效果或可证明的零提交结果才释放。取消、空回应、连接中断、原生调用后抛错都不能证明失败。
- 原生领域逻辑承担合法性和效果证据。资源消费、目标状态、多步骤协议不强行使用相同后置条件。
- 单一 MCP 串行控制为设计前提，不增加人工竞争探测、第三方并发仲裁或对应防御测试。
- 多回合过程区分本次命令的选择／启动与最终结算。政体无政府期、间谍旅行或任务等，只有可验证的请求受理和绑定的启动证据才能报告已启动；不能锁住推进等待数回合最终效果，也不能把启动说成最终完成。缺少证据仍保留未知。
- 已有动作、外交和回合所有者的可靠路径继续使用；迁移只补缺口，不重写已完成的协议。
- 议会沿用原生票单与阶段记录。Python 仅补原意图和门禁的领域桥接：已登记票单需要显式推进才能进入原阶段，已提交票单又会主动推进阶段／回合；不将这两种行为套入普通动作的严格同回合确认，也不复制原生投票状态机。
- 普通业务操作存在未决时先核对；纯查询保留可用；外交／议会／弹窗等解除回合阻塞的例外明确归属相应所有者，显式恢复沿现有规则。
- 移除基于一次旧状态读数而自动改通道或盲目发送的 fallback。缺少原生能力时返回明确未提交或未知，不绕过资格。
- 存档、进程和完整会话替换继续属于显式生命周期，不引入新通用事务系统。
- 任意 Lua 不自动包装成可证明完成的业务动作；它受已有未决门禁，不承诺业务确认。直接调用的未注册议会提交入口需纳入门禁或收敛到已有显式票计划。
- 不新增后台轮询、自动玩法、远程服务或跨 MCP 进程的意图持久化。日志不决定操作完成。
- 每个工作项独立提交并在自身工作树验证，再合入同一集成分支；不 push，不默认合入 main。

## Testing Decisions

- 主要 seam 沿用已经验证的公开 MCP／GameState 入口，执行真实 ActionLifecycle／领域所有者和生成的 Lua；只在原生引擎、连接、临时存档文件及进程 adapter 处模拟。
- 测试以业务结果、实际原生命令产生的状态变化和提交次数为断言，不复制自己的状态机，不以私有 helper 或源码字符串匹配代替行为。
- 每个消费或不可逆动作至少验证正常完成、原生延迟、执行后丢回应、重复同意图不重发、错误目标／身份、资格拒绝和未知门禁。
- 每类所有者补充取消、提交前世界变化、读回异常、部分完成和显式恢复测试；已覆盖的公共契约不在每个动作中机械复制。
- 目标状态操作验证已满足时的 no-op、异步生效和旧读数不触发第二写入；多步骤动作验证每个已提交阶段不会重复。
- 复用使者、Royal Society、单位 readiness、交易和保存测试中的 Lua 5.1／临时目录模式。使用已有规格作为预期结果来源。
- 每票运行相关测试，最终运行跨入口门禁、全量离线回归、语法和文档链接检查，再进行 Standards／Spec 双轴审查；修复实际发现后重跑受影响检查。
- 实机测试单列，不把离线通过写成游戏内通过；本次默认不启动、换档或修改当前真实对局。

## Out of Scope

人工或第三方并发操作；跨服务重启恢复未决意图；通用 exactly-once 基础设施；新玩法、策略优化、规则绕过；云服务、网页、后台监控；重写已有可靠的动作／外交／回合协议；自动 push 或发布；替用户更换当前真实对局。
