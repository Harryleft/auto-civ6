## 三、踩过的坑（按价值排序）

### 1. 游戏窗口失焦 → 游戏核心暂停 → 所有 Lua 超时（最隐蔽）

Civ VI 在窗口失去焦点时会暂停游戏核心。表现为：握手正常、125 个 Lua 状态都能列出，但 `GameCore_Tuner`/`InGame` 的 Lua **完全不执行**，报

```
CommandTimeoutError: ... without receiving the "---END---" completion sentinel
```

而**主菜单/前端状态仍能执行 Lua**，所以极易误判成"tuner 坏了"。我从终端跑脚本时终端抢焦点，就一直是这个症状。

判定方法（`probe_focus.py`）：连接后主动把游戏切回前台，同一份代码立刻通过：

```
focus_game -> True
GameCore attempt1: OK -> ['GC_PONG']
InGame   attempt1: OK -> ['GC_PONG']
```

最终解法是在守护进程里加 `FocusKeeper`：**每次工具调用期间**开一个线程持续把游戏抢回前台，调用结束就停（不影响日常使用）。单纯 `SetForegroundWindow` 会被 Windows 前台锁定挡住，需要 `AttachThreadInput`。

### 2. 世界议会（World Congress）会让 `end_turn` 永久停下

议会是在 **`end_turn` 执行过程中**才打开的。仓库文档写得很明白：

> If you don't call this, end_turn will pause at the World Congress session and return control to you for interactive voting.

而 MCP 是**串行**的——`end_turn` 挂着时其它调用进不来（实测 60 秒超时），所以**无法自恢复**，只能杀掉 MCP 进程重启。

修了两次都不对：事前调 `get_world_congress` 时看不到议案列表，拿不到哈希。最后读仓库的议会 Lua（`lua/congress.py`）才发现它支持 **`type`（议案类型名）作持久键**：

> This is the durable key: it is matched against the resolutions the handler actually sees when the session opens, so a policy registered **before** the session still applies to the real list.

且传空列表时退回默认策略（均分外交支持、投 A 案）。

**现在的做法：每回合无条件注册一次投票器**，有议案按类型精确投，没有就挂默认策略兜底。

### 3. 总控启动竞态（最蠢但最难查）

`start_daemon()` 读 `_daemon.log` 判断是否含 "MCP ready"。但守护进程启动时会**删除并重建** `_cmd.jsonl` / `_out.jsonl`。竞态链：

1. 总控读到**上一轮残留**的 "MCP ready" → 以为就绪，立刻启动执政官
2. 执政官把 `get_game_overview` 写进 `_cmd.jsonl`
3. 新守护进程这时才真正启动，**把 `_cmd.jsonl` 删掉重建** → 命令被抹掉
4. 执政官永远等不到结果 → 180 秒超时

因为恢复流程本身是好的，表现成"恢复成功 → 再失败 → 再恢复"的**完美死循环**，连吃了两轮才定位到。

### 4. 研究／市政断档检测不可靠

「停在选择研究」是真问题，根因是检测逻辑：

- `get_game_overview` 返回的是**中文文本**，解析不出 `turns_remaining` → 这条判断**永远为假**
- 改用 `get_turn_brief` 后，它的 `turns_remaining` 在科技刚完成时会**滞后**，仍会漏判

科技是在 `end_turn` 途中完成的，游戏弹「选择研究」并把右下角按钮从「下一回合」换成「选择研究」，而执政官看不到 → 回合停住。

**正解**：直接看 `get_tech_civics` 的 `current_research` / `current_civic` 是否为空（断档时是 `"None"`），不滞后、不依赖界面语言。

### 5. 外交弹窗没处理干净

印加的交易提议挡在回合前面。两个错：

- 只处理了「对话」（`get_pending_diplomacy`），没处理「交易」（`get_pending_trades`）
- `get_pending_diplomacy` 的返回字段是 `sessions`，我写成了 `pending`

### 6. FireTuner 经不起反复握手

每次「连接 → 断开」都在 4318 留 `TIME_WAIT`。连续几十次后 tuner 退化成「握手成功但状态枚举返回 0」或「状态能列但执行无输出」，**不自愈，只能重启游戏**。排查时我用脚本轮询把它打坏过两次。

**结论：对局期间只允许 MCP 这一个客户端。**

## 四、发现了仓库自身的两个问题

### 1. `web/src/lib/terrain-colors.ts` 的地貌 ID 映射是错的

它写 `0=FOREST, 1=JUNGLE, 2=MARSH, 3=OASIS`，但按本机游戏数据库加载顺序实际是：

```
0=FLOODPLAINS  1=ICE  2=JUNGLE  3=FOREST  4=OASIS  5=MARSH  6=BARRIER_REEF
... 18=REEF  19=GS 新增(草原泛滥平原) ...
```

四条独立证据（非猜测）：

1. 索引 **1** 共 526 格，**474 格在远洋** → 只可能是海冰，不可能是雨林
2. 索引 **19** 共 46 格，**全部草原且 46/46 带河流** → 正是草原泛滥平原的生成条件
3. 索引 **20** 共 19 格，**全部平原且 19/19 带河流** → 平原泛滥平原
4. 索引 **18** 共 24 格，**全在浅海** → 与 R&F 唯一新增的 `FEATURE_REEF` 一致

后果：网页版战略地图把**海冰画成绿色植被**，且索引 ≥7 的地貌（全部自然奇观、火山、地热裂缝、珊瑚礁）**完全没有叠加显示**。

### 2. `map/original/README.md` 说 `.Civ6Cfg` 能"恢复到游戏里"

三条路都试过，**都不行**：

1. FrontEnd API（`Network.LoadGame`）返回成功但游戏毫无反应；改名成 `.Civ6Save` 也一样
2. 游戏内「加载游戏」列表只列 `AutoSave_*`，没有 `ai-civ6-map-01`
3. 「创建游戏」界面只有「高级设置」，没有载入配置入口

文件头对比也能看出不是同类容器：`.Civ6Cfg` 偏移 8 是 `0x12`，`.Civ6Save` 是 `0x22/0x23`，且存档在偏移 28 有可读的 `GAME` 标记、配置没有。

**要玩那张地图，需要作者补传 `0_MCP_0141.Civ6Save`。**（配置本身是明文，我读出了盘古大陆／快速／远古／风云变幻、对手与 Mod 列表。）

## 五、止损坏在哪些决策上（我的问题）

1. **没有及早止损**：发现 `ai-civ6-map-01` 载不进去后，就该问你"要不要换一局"或"要不要自己开新图"，而不是继续在别人的存档上搭无人值守流水线。

2. **管道与对局本末倒置**：4.5 小时修管道、40 分钟打游戏。正确顺序应该是先手动打 5 个回合验证策略，再谈自动化。

3. **执政官策略过于幼稚**：只会"造建造者／造纪念碑"，**从不造开拓者、从不重建军队、从不反攻**。结果全程 1 座城、得分卡在 131，等于站着挨打。

4. **丢城的窗口期我在修管道**：第 129→132 回合苏美尔夺城时，我正忙着调议会投票。如果当时有军事策略，至少能守住。

5. **信念引擎降到 `observe` 是必要的，但我没提前说明代价**：`enforce` 下每改一次研究都要走「提案 → 议会 → 授权」三步，395 回合走不完。这是合理取舍，但应更早告知你。

6. **过度依赖"再修一个 bug 就好了"**：每个卡点修好后都以为稳了，结果下一个卡点立刻出现。应该在第二次崩溃时就停下来重新评估方案。

## 七、如果重来一次

1. **先问清楚"哪张图"**——`ai-civ6-map-01` 没有存档就直说，让你决定换图还是新开。
2. **先手动打 5 回合**，确认 MCP 工具链、回合流程、门禁行为都正常，再谈自动化。
3. **执政官要有最低限度的战略**：开拓者优先级、军队维护、被宣战时的防守与反攻。只会造建造者等于慢性自杀。
4. **把 `MaxJobThreads=4` 放进每次启动前**（游戏会覆盖 AppOptions），它是对付 TBB 崩溃的官方缓解措施。
5. **卡点第二次出现时就停下来重新评估**，而不是接着修第三个 bug。
6. 若要真正无人值守打到 500 回合，**应该用仓库原本设计的 `scripts/civ6_agent`**（需要源码版 DSH + LLM 凭证），而不是自己搭一套简化版。
