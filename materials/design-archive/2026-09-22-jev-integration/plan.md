## 1. 目标与范围

在现有运行体系上接入 Jev，使其选择能够直接驱动游戏执行。首批上线即自动执行，不以长期旁路建议作为交付目标；离线测试和受控存档实机验证仍是实施步骤。

当前交付是审查与实施计划。后续先完成现状审查、形成逐项证据和改造卡，再实施获授权的改造。保留有效的 MCP、FireTuner、Lua、存档和日志能力，不预设必须整体重构或新增某个框架。

暂定首批：城市生产、科技与市政、建造者、商路、城市工作重心、单位晋升、使者、时代奉献，以及支撑这些决策的优先级、计划有效性和共享资源协调。其余领域有明确后续位置，不默认首批全部实现。

## 2. “互斥”的具体规则

1. **问题归属互斥**：一个根因只有一个问题编号、一个主责工作包、一张改造卡。其他工作包只能引用依赖，不另开同义问题。一个文件可以涉及多项职责，按行为归属，不按文件强行拆分。
2. **最终决策权互斥**：同一个决策实例只有一个决策来源。Jev 直接选择、规划模型决策、确定性规则三条路径通过路由明确分配；接管或回退必须显式记录，不能同时覆盖对方。
3. **动作冲突互斥**：同一状态版本下，同一个单位的下一步动作、同一城市的下一项生产，只能选定一个。先后动作可以组成序列，执行一步后更新状态再继续。
4. **共享资源受约束**：金币、信仰、战略资源、外交支持、使者、政策槽位、地块不能被多个判断重复占用。不同城市可同时有生产任务，不因“互斥”被错误合并成全国只能生产一项。
5. **判断类型不能混淆**：多个风险、需求和评分维度可以同时成立，不强制互斥；一个 Choice 用于选定一个行动或分支。Score 用于程度，Noul 用于某个条件成立的概率。
6. **并行只用于独立问题**：依赖前一个答案的问题分阶段请求；同批问题不能假定读到了彼此的结果。模型判断可批量进行，改变游戏状态的调用按现有单连接约束串行执行。

示例：城市同时缺粮和受威胁，两种情况可以同时成立；下一项生产的候选为具体可执行项目，最后选择一个。不能用“缺粮/危险/扩张”这种会同时成立的分类代替最终动作。

## 5. 决策覆盖与接管边界

本表是领域覆盖视图，引用工作包，不另建重复工程任务。每行实施时都要补齐“状态字段 → 候选 → 问题 → 消费者 → 执行 → 后置条件”。

| 领域 | 暂定决策方式 | 触发时机 | 核心约束 | 批次 |
|---|---|---|---|---|
| 城市生产 | Jev 选具体项目；全国需求协调 | 空队列、完成生产或明确中断理由 | 城市生产位、已有订单、区域地块 | 首批 |
| 科技与市政 | Jev 在阶段目标内选择 | 完成研究、目标失效 | 两条研究轨道分别选择，避免反复切换 | 首批 |
| 建造者 | Jev 选单位—任务；程序按步骤执行 | 空闲、任务完成、目标失效 | 次数、地块、路程、支援和预留布局 | 首批 |
| 商路 | Jev 选合法目的地 | 商人空闲、路线结束 | 容量、全国需求、目的地与已知风险 | 首批 |
| 城市工作重心 | Jev 选重心或维持 | 增长/产出瓶颈变化 | 同城重心唯一、避免抖动 | 首批 |
| 单位晋升 | Jev 选合法晋升 | 获得晋升机会 | 单位职责、晋升条件、与本轮其他动作冲突 | 首批 |
| 使者 | Jev 选目标或保留 | 新使者、目标竞争变化 | 数量预算、宗主目标、必选事件分支 | 首批 |
| 时代奉献 | Jev 选合法奉献 | 时代转换 | 规则集、可选项、阶段目标 | 首批 |
| 优先级与计划有效性 | Jev 评价；规划模型更新复杂目标 | 关键事件、定期检查 | 多种需求可共存，目标变更后刷新相关判断 | 首批支撑 |
| 购买与升级 | Jev 评价需求并选方案 | 有需要且可支付 | 全国金币/信仰/资源预算 | 后续；首批保留原处理者并经过统一协调 |
| 落城与区域/奇观布局 | Jev 选候选或完整方案 | 移民任务、建设决策 | 位置、忠诚、布局冲突、机会成本 | 后续；首批涉及区域生产时必须有可用位置处理者 |
| 政体与政策 | Jev 评价合法组合 | 解锁、换卡机会、目标变化 | 槽位、重复卡、成本及组合效果 | 后续 |

| 万神殿、宗教、伟人 | Jev 评价，复杂组合由规划模型给方案 | 可创立、招募、激活或传播机会 | 信条关系、资源、合法激活地点 | 后续 |
| 探索与常规军队任务 | 规划模型给任务；Jev 可选下一步 | 空闲、发现信息、任务改变 | 可见地图、单位任务、移动与支援关系 | 后续 |
| 战争、多单位战斗 | 规划模型组织序列；Jev 评价局部候选 | 战场变化 | 预估、支援、前后依赖与状态刷新 | 后续 |
| 外交、交易、城市处置 | 规划模型组织方案；Jev 评价/有限选择 | 提案、外交事件、占城 | 关系、资源、条款、长期目标 | 后续 |
| 间谍与长期宗教布局 | 规划模型组织任务；Jev 评价选择 | 单位空闲、任务结束、被发现 | 旅行、任务条件、逃跑选项 | 后续 |
| 通知清理、合法性、回合推进与恢复 | 确定性程序 | 对应事件 | 真实状态与执行结果 | 始终保留在程序侧 |

不在首批的决策仍由 P3 指定的原处理者负责。遇到它们时系统继续通过该路径处理；不得因未接管而跳过必需决策。混合路径共享同一个执行和资源协调入口。

## 6. 清理清单：按责任归属，避免重复或误删

| 待清理对象 | 主责 | 删除或替换的前提 |
|---|---|---|
| 错误缓存、重复事实解析、推断混入事实 | P1 | 来源和消费者已迁移，未知/过期行为有验证 |
| 冗余候选、隐藏截断、自由生成执行参数 | P2 | 候选覆盖与执行映射已经验证 |
| 旧自动战略选择、双重决策、冲突提示词 | P3 | 新负责人已连接，未接管领域仍可处理 |
| 旧 Jev 接口、重复客户端、散落阈值 | P4 | 实际调用者已确认，替代接口通过真实请求验证 |
| 各自分配预算或重复领任务 | P5 | 统一协调已覆盖所有参与的决策者 |
| 未知结果重发、假成功、执行旁路 | P6 | 新状态/后置条件路径通过故障与恢复测试 |
| 不可关联日志、重复存储、伪造解释 | P7 | 新记录可以关联完整决策与结果 |
| 旧入口文档、失效配置示例与验收描述 | P8 | 唯一有效链路已验收，文档与实际一致 |

旧代码先确认引用和行为，再迁移、验证、删除。不要为了目录整齐删除备份、存档、已有日志或用户的未提交工作。

## 7. 实施顺序与里程碑

**M0：完成现状审查。** 完成 P0，审查 P1–P8 对应代码，交付单一问题台账与改造卡。此阶段只读审查及编写文档，不进行游戏操作或运行逻辑修改。

**M1：补齐数据和控制边界。** 先落实 P3 分工契约，再补 P1 状态、P2 候选；建立满足首批需求的 P5 协调与 P6 执行约束。P7 在同一流程上记录证据。

**M2：接入真实 Jev 并贯通一个领域。** 实现 P4，用城市生产走通完整链路；这是验证所有接口是否连通的实施切片，不将只完成城市生产视为首批交付。

**M3：完成首批八类及支撑判断。** 使用同一接口扩展，逐类验证；跨领域依赖继续由明确的原处理者接手，共享协调与执行。

**M4：集成验收与清理收尾。** 完成 P8 的受控实机闭环、恢复和证据检查；删除已被替代且无消费者的路径，交付启用范围、提交记录和限制。

**M5：后续领域。** 依据首批实际表现和剩余缺口，分别安排预算决策、布局、政策、议会、战争与复杂外交。未经扩大范围，不将这些自动算进首批实施。

依赖关系：P0 → P3 契约与 P1/P2 审查 → P4/P5/P6 实现 → P8 验收。P7 随实现加入。看似并行的问题只在不共享修改点、不依赖未确定契约时并行。

工期与文件级实施拆分在 M0 后估算；目前不根据未核实的历史架构给出虚假精确排期。

## 8. 单一问题台账与改造卡格式

每个问题只登记一次，必须包含：

| 字段 | 要求 |
|---|---|
| ID / 主责工作包 | 一个根因对应唯一 ID 和 P0–P8 中的一个主责 |
| 现状证据 | 已确认检出、文件/函数、可复现现象；没有证据写待核实 |
| 问题与影响 | 说明阻碍哪个用户结果，区分阻塞接管、影响决策质量、维护优化 |
| 处理方式 | 保留、修正、补齐、替换或删除；写出具体行为变化 |
| 修改范围 | 预计文件/函数与消费者，不提前创造无必要的新层 |
| 契约与互斥 | 输入、输出、决策者、冲突键、资源、状态失效条件 |
| 依赖 | 引用其他问题 ID；不复制其改造内容 |
| 验证 | 代表性输入、预期行为、离线检查和所需实机证据 |
| 撤回方式 | 停止接管、清理未执行决策、回归指定入口；游戏状态另按存档处理 |
| 状态 | 待核实、已确认、待实施、已实现、离线通过、实机通过、阻塞 |

审查完成时同时给出覆盖核对：每个启用领域均有完整链路，每个已发现根因均有唯一归属，未接管领域均有明确处理路径。互斥不意味着遗漏依赖或共同约束。
