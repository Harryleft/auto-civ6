# 开发与验证

修改、测试、审查或提交时读取本指南。实机验收另见本页对应章节；一般开发不需要加载游戏操作流程。

## 定位改动

先检查当前分支、工作树和本次目标。保留已有修改，按问题选择模块；涉及状态归属时再读[架构说明](architecture.md)，不要默认扫描历史设计。

| 修改对象 | 主要实现与相关验证 |
| --- | --- |
| MCP 参数、工具调度、整体串行和日志 | `server.py`；工具许可分类留在调度端，只消费公共未决事实。 |
| 领域准备、查询、完整存档替换 | `game_state.py`；通过真实 GameState／MCP 入口验证。 |
| 动作锁存、单次提交、回应与证据确认 | `actions.py` 的 ActionLifecycle；各动作保留自身原生见证。 |
| 推进请求、起始回合和差分基线 | `end_turn.py` 的 TurnProgress；报告读取失败不改变已确认推进。 |
| 当前外交语句、回应及交易阶段 | `diplomacy.py`、`lua/trade.py`；通过 GameState／MCP 与延迟原生事件验证，未知不重发。 |
| 原生菜单、文件事实、进程控制 | `game_lifecycle.py`、`game_launcher.py`；转换和进程结果用事实控制，不匹配展示文案。 |
| 检查点身份、指纹和测试轮次 | `checkpoints.py`；使用临时目录，保留文件与轮次约束。 |
| 游戏领域 Lua 构造与解析 | `lua/`；议会阶段与提案资格共用解释，纯查询不产生游戏操作。 |
| FireTuner 请求关联与上下文发现 | `connection.py`、`tuner_client.py`；单次执行、完整响应、超时隔离和无重放。 |

上述实现位于 `src/civ_mcp/`。保留领域工具名称和职责；优先集中重复知识，不以纯文件拆分或通用框架作为完成标准。

## 文档归档

| 内容 | 位置 |
| --- | --- |
| 跨对局的操作指南、架构说明、可复用技术结论 | `docs/` 中对应主题；入口为[文档导航](README.md) |
| 项目级工程规格与离线验收 | `docs/specs/`、`docs/acceptance/`，分别维护主题索引；成组的调研、规格和工作项放入 `docs/specs/<日期>-<主题>/` |
| 某局的回合记录、局面分析、实机验收、复盘与存档清单 | `games/<对局>/`，重新开局的测试轮次单独放入 `runs/<轮次>/` |
| 随某轮产生的修复规格、工作项和审查记录 | 所属轮次的 `changes/`；复用结论整理回当前指南或架构说明 |
| 原始日志、截图、存档副本等本地证据 | 所属对局／轮次的 `evidence/`；默认不提交 Git，报告记录位置与必要指纹 |
| 临时草稿、已移除功能的本地依赖与构建残留 | 草稿放 `.scratch/`，旧功能残留放 `.local/archive/<功能>/`；均不提交 Git，有长期价值的内容整理后归入上述资料目录 |

按[对局资料约定](../games/README.md)记录来源和轮次；相同文明、种子或保存名称不能替代轮次确认。历史原始证据保留原位置，整理文档时只更新引用，不覆盖存档、原始日志或原报告的结果与限制。混合了工程验证和实机过程的历史报告整体随局归档，当前文档引用其证据。

## 公开资料与隐私

公开副本中的个人主目录使用 `~`、`%USERPROFILE%` 或明确的示例路径；私有云文档链接、用户标识及资源 token 使用脱敏占位符。云端回读和制作脚本脱敏后只供历史查阅，不能直接用于操作原文档。保留游戏身份、回合、终局、原始存档指纹及原作者署名。

脱敏副本的文件字节可能改变，历史验收中的指纹仍对应当时的原始文件。原始证据与脱敏映射保留本地忽略目录，提交前检查本次暂存内容；凭证、本机配置与个人信息不进入新提交。Git 提交身份可使用 GitHub noreply 邮箱。

普通清理提交只更新当前版本。旧提交、托管缓存、分支或第三方副本中的信息，需要独立核对；历史改写和 force push 按明确授权执行。

## 离线验证

代码修改只运行受影响模块的测试；由改动范围选择文件，例如交易生命周期修改：

```bash
uv sync --locked
uv run --locked pytest -q tests/test_trade_progress.py
uv run --locked python -m compileall -q src tests
git diff --check
```

影响跨模块契约时补充直接相关的测试文件，不默认运行全量。复用同一受测版本的集成结果；仅在新改动、失败或未解决疑点需要时重跑或扩大范围。

现有测试采用 GameState／FakeConn、内存 FireTuner 流、Lua 5.1 执行、快照差分和临时存档目录；在这些位置验证可观察行为，不复制自有状态机，也不以源码字符串断言代替关键时序验证。

共享夹具定义在 [tests/conftest.py](../tests/conftest.py)，按待验证行为选择：

| 夹具 | 适用范围 | 隔离要求 |
| --- | --- | --- |
| `committed_knowledge_root` | 对已提交快照进行只读 CLI 查询，在一次 pytest 会话内复用完整构建 | 修改输入、损坏产物或迁移路径的测试使用独立临时目录；查询继续经过正式版本与指纹检查 |
| `fast_action_confirmation` | 使用脚本化回应验证多次观察、未决门禁和单次提交，显式缩短测试确认等待 | 验证截止时间或取消的测试自行控制预算与时序；游戏运行层默认等待不随测试优化改变 |

优化测试耗时时保留行为断言，核对参数展开后的用例清单，并使用相同计时口径比较结果。一次运行的耗时不作为固定性能门槛；已有实测与复现方法见[测试优化验收](acceptance/2026-10-20-test-efficiency-optimization.md)。

纯文档修改检查本地链接及锚点、命令与实现、关键约束覆盖和 `git diff --check`；不为排版重跑游戏流程或全量测试。开发依赖和版本以 `pyproject.toml`、`uv.lock` 为准。

`scripts/test_connection.py`、`scripts/test_game_state.py`、`scripts/test_queries.py`、`scripts/integration_turns.py` 会连接真实游戏，不能作为离线检查运行。

## 实机验收

只有任务已授权操作真实游戏时才进入本节。运行前核对[受信原始基准](../fixtures/saves/README.md)和[检查点规则](agent-recovery.md#检查点与测试轮次)，保护存档及已有证据。

`integration_turns.py` 通过 stdio MCP 调用同一工具实现。以下命令会替换当前对局；已有对局时，当前驱动会完整重启并加载原始基准：

```bash
uv run --locked python scripts/integration_turns.py --save benchmark_turn_1 --turns 10 --timeout 900
```

CLI 默认且仅允许 `benchmark_turn_1`，省略 `--save` 也从原始基准开始。当前驱动使用固定测试策略处理单位、科研文化和生产项；策略只属于测试驱动，不移入 Runtime。结果未知、挂起、不支持的阻塞或预算耗尽时退出，不自动恢复／重发。检查点续测和菜单换档验证通过相应 MCP 工具执行。

完成记录写入所属对局／轮次的 `reports/`，包含使用的存档及来源、实际动作、净推进回合、阻塞与恢复、结果文件及未验证项。旧验收不能替代本次实测；只做离线验证时明确报告未连接游戏。

## 提交与交付

- 按目的组织提交，只纳入本次改动；沿用当前任务分支。任务要求集成分支时，保留单项提交和依赖工作项。
- 远程写入、push、合并主分支和改写历史按用户明确授权执行；不为文档同步切换已有任务分支。
- 报告提交 hash、验证结果和剩余阻碍；如创建了实施工作树，完成合入和必要验证后清理，保留所需分支与证据。
- 本项目已有本地 Markdown tracker；规格、依赖和完成记录随相关工作项维护。查找特定规格或验收时，从[记录索引](README.md#规格与验收)选择对应条目，不默认读取全部历史。
