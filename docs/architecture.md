# 当前架构

修改状态归属或排查实现机制时读取本页对应章节。操作顺序见[游戏操作](agent-playbook.md)与[保存恢复](agent-recovery.md)，验证门槛见[开发与验证](development.md)。

## 调用关系

AI 只发现并执行 CLI；MCP 保留为内部适配层。`civ6 debug` 是前台 stdio MCP 客户端，一次会话保持一个服务进程；终端命令不会重建 GameState。`get_runtime_status` 在工具锁内仅读取服务 UUID／PID 和现有所有者的公开未决事实，不触发查询、确认、缓存刷新或门禁退役。CLI 保存的传输未知只用于阻止不安全续写和退出提示，不替代 Runtime 的动作所有者；进程退出后不提供未决意图恢复。

```text
AI → civ6 CLI（唯一公开操作面）
  │ stdio JSON-RPC
  ▼
server.py：参数、工具入口、结果文本
  ▼
game_state.py：领域 interface、查询、存档替换
  ├─ actions.py：动作提交与确认
  ├─ end_turn.py：推进请求与确认
  ├─ diplomacy.py：外交回应与交易阶段
  └─ congress.py：原议会票单与阶段门禁
  ▼
lua/：按游戏领域构造与解析 Lua
  ▼
connection.py / tuner_client.py：FireTuner 通信
  │ TCP 127.0.0.1:4318
  ▼
Civilization VI
```

游戏规则由引擎执行。GameCore 与 InGame 按原生 API 可用性读取／提交，FrontEnd 提供主菜单读档。FireTuner 的 read／write 名称选择上下文，不代表该 Lua 是否改变状态；晋升在 InGame 绑定原生可选项的 Index 并提交 PROMOTE，由引擎处理经验、恢复与行动力，同一动作所有者确认实际晋升及回读数值。领域查询和动作保持独立，工具返回必要事实和回读结果供模型决策。

## 动作确认

已纳管动作按「单次提交 → 有界只读确认」执行。`ActionLifecycle` 唯一持有未决动作，共用提交、回应解释、明确拒绝、未知保留和确认过程；GameState 负责领域准备与结果叙述。移动、攻击、建城、生产及城市射击保留各自证据，listener 仍核对来源并只清理自身。相关依赖操作、保存和推进先核对结果；读取旧状态或丢失回应不触发自动重发。兼容私有属性只代理同一份状态，不保留副本。

单位攻城以原 token、精确战斗参与者、范围和城市状态确认。普通近战占领仍要求原攻击者进入目标城；若提交前已核实无获胜队伍、本次占领后原生结果为本方队伍的征服胜利，且原攻击者有效并位于目标相邻格，则可输出带 `completion:terminal_conquest` 的完成回执。获胜队伍不能当作玩家 ID，结果未知、冲突或缺少见证均不能由终局覆盖。`get_units`／`get_cities` 可通过同一所有者只读确认旧动作，不提交新攻击，实体列表不伪造最终进城位置。领域查询可将此次已终结请求的回执交给可选回调，默认仍只返回实体；server 在本次结果末尾追加回执，不保存或重放确认状态，仍未决时不追加完成回执。原查询在首次提交时冻结；磁盘代码更新不热加载到存活的旧 owner，也不提供跨进程接管。

使者沿用同一所有者，`lua/envoys.py` 在 GameCore 冻结请求前的权威双侧计数，InGame 记录精确单次提交见证。确认同时匹配原 token、世界／回合／玩家、目标身份和原基线，只有 GameCore 可用使者减少一枚且指定城邦收到的使者增加才报告完成。InGame 影响力缓存可能在实际完成后仍保持旧值，不作为完成依据；城邦查询也用 GameCore 计数与宗主信息，UI 仅提供其独有的派遣资格。查询不会确认或退役请求。同目标重入只确认原请求；世界变化、取消、丢回应与不完整证据保留未决。MCP 的其他变更先经过该全局消费门禁。运行模型为单一 MCP 控制游戏；本项目不处理人工并发操作，不提供跨服务重启的意图持久化。

购买、治理、单位任务、地块操作、伟人、占城决定、间谍指派、宗教及关系操作均已纳入已有所有者。普通动作保留完整对象与原意图；多阶段仅原入口可继续尚未进入的步骤。所有 scoped pending 读到任一有效的世界／回合／玩家字段不匹配即锁存失效，其他字段未知不能遮蔽该变化，返回原值不能追认；只有完整有效且匹配的范围才允许确认结果。2026-10-19 的入口覆盖基线及任意 Lua／显式生命周期边界见[覆盖基线与离线验收](acceptance/2026-10-19-mutation-lifecycle.md)；[原始审计](specs/2026-10-19-mutation-audit.md)保留迁移前基线。

MCP 与直接 GameState 都先保护 save／load、外交、推进、议会及普通动作未决。原所有者先匹配同意图，确认旧请求后本次调用结束；纯查询、归属明确的阻塞解除和已确认检查点恢复保留通路。旧动作与新迁移动作共享该规则，普通进程启动／关闭或任意 Lua 不再绕过门禁。

单位护卫编队及军团／集团军合并通过 `get_unit_formations`／`set_unit_formation` 使用原生候选和命令。GameState 将完整双方、动作与世界范围绑定到同一 ActionLifecycle；只读候选不退役请求。Lua 记录精确参与者事件，结合实际编队状态或一方消失、另一方达到目标编制确认；丢回应不重发，不以本地 setter 组成编制。新生成第三个替代单位 ID 的结果保留 unknown，不能从数量变化反推归属。详见 [单位 CLI 说明](specs/2026-10-25-unit-cli.md)。

## 回合推进

`TurnProgress` 唯一持有未决推进、原世界身份、起始回合和原始差分快照，通过明确的 `TurnContext` 协作获取事实与报告，不读写 GameState 的任意私有字段。原身份包含文明、种子和本地玩家；确认回合增长或终局前直接核对原生身份，不依赖普通查询先刷新缓存。身份未知时保留未决，缺少原绑定不能用当前世界追认；观察到不匹配后锁存来源失效，显式受保护的会话替换才可退役。

普通概览更新观察缓存不会替换原请求基线；陈旧或未来快照不得生成错误差分，报告读取失败也不重新发送已确认推进。`turn_pending` 提供只读门禁事实，普通身份刷新不释放它。

`end_turn` 只检查阻塞、发起推进并确认结果；需要生产、科研、外交、占城或议会决策时，由模型调用相应工具。无需反思 payload 或日记前置步骤。回合数字变化后还需确认本地玩家可操作；外交回应后继续确认原来的推进请求。

`get_turn_status` 与推进共用原生阶段解释，分别保留本地活动、完整性、UI 消息处理及 complete／可提交事实。首次提交时间、最近观测与阶段变化属于同一个 `TurnProgress`；查询可更新观察事实，但不退役请求。等待预算与真实读取失败分开，时长不承担死锁判定。

## 外交与交易

`diplomacy.py` 的 `DiplomacyProgress` 持有当前语句见证、单次回应及交易尝试；`lua/trade.py` 负责准确原生上下文中的准备、事件匹配和提交。观察器只记录本世界的公开外交事件，不替模型回应。原生选项由当前会话语句解析，缺少见证保持未知，不以文本不变判断 goodbye。

交易先空条款打开会话，确认原生界面就绪后再发送，并以 nonce、世界、参与方、session 和 action 匹配响应。既有主动提案的最终接受与反提案沿其明确提交流程确认；已知零发送失败只终结本次会话。来约评估复用同一观察器，以世界、原生会话、双向条款及资格阶段指纹绑定单次 `INSPECT`／`EQUALIZE`，不重开会话、不自动接受或关闭。丢回应或取消后只确认原尝试；绑定的原生 `ZERO` 回执及零提交终结均确认后，才返回未提交并退役。外交所有者独立锁存已观测的世界不匹配，不依赖是否存在推进请求；身份未知保留未决，返回原身份不能解除已锁存失效。原生 `AcceptDeal` 资格与双向条款相等共同约束最终接受，拒绝后的相等条款不能冒充已谈妥。交易结果、会话结束与界面清理分别确认，取消或丢回应不重发。未决事实保护推进、保存及普通换档；显式受保护替换沿既有恢复边界处理。

## 会话替换与检查点

GameState 拥有完整会话替换；`game_launcher.py` 负责原生进程操作，`game_lifecycle.py` 负责原生菜单、加载和文件事实。MCP 只调度和展示，不写入私有门禁、重置会话或清理索引。菜单路径与完整重启复用同一加载确认。入口、时限和完成条件见[保存与恢复](agent-recovery.md)。

`replacement_pending` 只表示替换未知，保存未知由 `save_pending` 提供。保存进入可能提交的 await 前即设门禁；取消、原生异常、文件或最终身份验证不完整时保持未知。重复保存不重发，长期未知沿显式检查点恢复处理。`reset_session` 在显式受保护替换中退役旧动作和推进，但保留替换门禁；普通身份刷新只清观察缓存，保留未决请求。旧保存列表索引随显式替换清理。

`NativeTransition` 提供原生转换状态，`ProcessResult` 提供进程事实，展示文案不承担完成判断。原生加载调用已进入后抛错只能得到 unknown；前置条件能够证明未调用时才允许 not_submitted。重连用于发现和回读，不重放已发出的块。

`checkpoints.py` 把原生保存完成证据、精确文件指纹、身份回合和本轮标识组合成检查点记录；只有完整加载确认后才释放替换门禁，加载原始基准时才建立新轮次。操作规则集中在[检查点与测试轮次](agent-recovery.md#检查点与测试轮次)。

## 通信与验证职责

日志仅用于本地问题追踪，不参与玩法决策或回合放行。服务不启动网页、云同步、后台镜头、弹窗轮询或终局监测任务。

离线测试只收集 `tests/`，通过隔离夹具验证执行、回读与生命周期；新实机验收由模型通过同一命名 CLI 会话逐回合决定动作并保留确认和检查点。旧固定策略驱动及其专属导入测试已移除；现役入口与边界见[开发与验证](development.md#实机验收)。

## 世界议会

`open_world_congress` 独立于纯查询，在已确认的原生投票阶段、存在可投选择且本阶段未提交时，执行 Intro 的 DequeuePopup → ShowWorldCongress 开始路径。开始前记录文明、种子、回合及阶段；已请求或丢应答只核对可见状态，不重复事件。原回合推进请求未决时可以打开议会，其他未决动作、保存及加载门禁保持。无选择或未知提案不走开始路径，以免原生 UI 自动提交与显式票计划重复。

议会查询、显式打开和显式票单共用原生阶段与提案可投资格解释。`proposal_status` 的 `CHOICES` 表示存在可投提案，`EMPTY` 表示没有可投提案（可能仍有禁投行），`UNKNOWN` 表示资格未核实；resolutions 另行按当前阶段处理，Stage2 不重投旧决议。共享解释不合并三种操作，也不引入默认投票。


`CongressProgress` 只保存原意图、token、原世界／回合与观测结果，票单和 entered／returned 阶段仍在原生 Lua。`open_world_congress`／`queue_wc_votes` 原入口匹配后只确认旧请求；直接分项 vote／submit 入口收敛为完整票计划。投票、提交、继续任一原生调用 false 或异常即停止后续步骤，部分完成不重放。

已登记 REGISTERED 票单可由显式 `end_turn` 触发；只有该入口允许最新可信登记状态保留计划并放行。阶段继续以原生阶段／回合变化确认，不照搬普通动作严格同回合规则。`WC_STAGE_FINISHED` 只表示原阶段结束，分配数只表示请求的票单，不表示实付外交支持或议会结果。

## CLI 只读验收与领域命令

`city_yields.py` 首先通过一个有界 InGame 请求读取自有城市的区域收益及当前理性主义规则图；`lua/city_yields.py` 沿用原生 CitySupport 的区域 getter，完整标量规则行与 GameInfo 附带的关联表缓存分开。所有视图并列读取区域与地块相邻值，两者可能受修正影响而不同。两个已知条件形状仅比较人口／地块门槛，不实现通用 Modifier 求值器。

已装备政策时，继续读 GameCore 的本方修正实例、主体／追踪对象计数和 RequirementSet 状态，再以 InGame 世界／回合复核。只有原生集合完整、城市对象的精确诊断格式、ID／所有者／原始名称与当前自有城市全部吻合，且当前规则链与原生状态一致时，才解释对应分支的生效状态。未绑定、冲突或不支持条件保持 unknown。该格式依赖集中在 Lua，格式变化不能回退为按名称匹配。完整展开保留原生记录；只读查询不计算净科技增量，不授予动作资格，不修改或确认 pending。

城市购买候选和实际提交前检查共用 `lua/purchase_facts.py` 的原生事实查询：先按 ProductionPanel 的 `PurchaseYield`／本城信仰购买能力检查币种，再读资格、失败原因、精确价格与余额。`CanStartCommand` 本身不足以证明币种已启用；有价格也不等于可购买。查询不持有购买意图，执行前重新读取；既有购买回执和 ActionLifecycle 仍负责单次提交、产物与精确扣款确认。原生未解释的拒绝可附当前缺失前置的观察，不能据此自行授予资格。

生产候选沿用 ProductionPanel／CitySupport 的按类型、Index 查询，分别读取当前生产成本、已投入生产力和原生预计回合；静态 GameInfo 成本独立保存在 `base_cost`，不能在原生读取失败时回填当前值。零值与未知分别保留，生产资格和购买资格保持独立。`get_city_production` 默认简报和 `structured` 视图消费同一份候选，结构化展开保留完整字段，不新增缓存或提交路径。

`decision.py` 为按需读取的决策事实模块，由 GameState 的 `get_decision_context` 进入。它在同一个有界 InGame 请求中组合已有领域 getter，用独立 Lua 函数隔离局部变量、早返回和分项异常，保留各领域解析器。读取前后核对原生世界和回合见证，再检查实体、城市及胜利数据范围。该入口在任何游戏 I/O 前拒绝全部 pending，不调用普通实体查询的动作确认路径，不写观察缓存或维护另一份动作状态。默认简报复用领域文本，结构化视图供明确的数据核验；未请求领域和读取失败分别保留。它不提供候选排序、策略或连续执行。

96 个基础工具均有命名 CLI 入口，共 149 个命名子命令（含 3 个既有双人热座实验命令）；`call` 保留协议兼容调用，不成为第二套执行逻辑。普通会话不公开或执行 `run_lua`，包括其 `call` 和预演路径；显式 `debug --developer` 才开放 `developer lua`，仍受原 Runtime 未决门禁约束。

`debug --hotseat-seat/--hotseat-run` 启动既有双人实验控制器，使用其原生身份检查、文件锁和交接确认。CLI 额外只读观察共享 pending 文件，退出时同时核对内存和共享门禁，不删除或接管文件。检测到已有共享请求时拒绝新建该轮控制器。此适配不创建补丁、不扩展席位数量或替代原控制器规则。

前台领域子命令在 `devtools/commands.py` 将参数转换为公开 MCP 工具调用，不持有另一份游戏状态或确认逻辑。`verify state` 使用同一前台客户端执行有界只读检查，不自动重启、加载、推进或解决阻塞；一次性入口独立建会话，不能继承其他进程的 pending。

`get_game_snapshot` 在整体工具锁内委托 `snapshot.py` 采集公开领域数据，并检查读取前后世界身份、玩家回合和实体范围。普通 `get_units`／`get_cities` 可能顺带只读确认已有动作；该快照入口在任何游戏 I/O 前拒绝全部 pending，避免自动验收触发这条确认路径。快照不拥有、复制或退役请求；身份刷新仍可能记录已观察到的世界变化，不能据此清门禁。数据有 `ready`／`blocked`／`unknown` 状态，只有完整约定检查通过才允许 CLI 授予只读验收通过。

决策查询的原生候选与当前资格继续由领域模块解释。`lua/tile_facts.py` 只共享购地报价和执行预检的纯事实读取，不拥有请求、扣款或确认状态。区域／奇观落点只取原生 `PLOTS`；其他数值数组不表示合法候选。`city_yields.py` 保留区域、地块、建筑与全城收益的不同口径，用响应内别名压缩相等事实，不通过隐藏候选或缓存跨动作状态减少读取。

政策与总督的精简候选视图只省略原生明确拒绝的选项并报告覆盖数量；精确政策查询和总督完整展开可恢复原因与未取得的树。原生布尔接口没有给出详细拒绝原因时保留这一限制。全局选址、建造者和伟人地点报告不承担固定策略排序，也不把高亮、几何距离或有行动力解释为已经可以执行。

`city_growth.py` 按需提供原生增长解释，复用现有 JSON 传输格式，拒绝 pending 并验证完整世界身份和前后范围。分项修正保持原生单位，总体增长乘数与预计回合由引擎提供；UI 进度派生量不构成新的增长规则解释器。全局选址的范围在原生候选计算前过滤，页面在完整候选读取后切片并保留总量；每次查询重读当前状态，不冻结或跨动作缓存候选。

`city_workforce.py` 通过 `get_city_workforce` 读取单个自有城市的原生 `MANAGE` 数组，以原生键配对地块、市民数、容量和锁定数，并分别读取工作状态、购地归属、六种地块收益及产出偏好。几何半径、购地集合和人口数不能替代原生管理范围。`brief`、`structured` 和 `evidence` 共用查询，证据视图增加购地 ID 与数组键；地块收益不解释为边际城市净收益或专家收益。读取前拒绝 pending，核对城市归属及前后世界身份；分项失败保留未知，数组不配对或身份变化返回 unknown。不修改市民、焦点、界面或动作状态。

本地／全局选址共用当前可见性边界：迷雾中心不读取动态归属，未知归属保留为候选事实；周围当前收益与资源只读取可见地块。粮食、生产力和资源分别记录观测覆盖量，粮食与生产力另列已观测小计；只有对应已揭示范围全部取得观测才形成完整汇总。未观测动态字段保持 unknown，不用零值、空资源集或无主补齐，也不把观测小计当作建城后的可工作收益。

`lua/great_people.py` 先扫描完整原生时间线并绑定个人／类别身份，再以可选 `individual_id`、原生 `class_type` 的 AND 条件筛选，只有匹配者读取能力、点数、报价和资格。扫描总数、匹配数、展示数、完整性及原生耗尽类别分别保留；缺行、绑定冲突或解析不完整不能解释为空结果。展示层仅合并本次响应内完全相同且已知的余额，未筛选入口仍返回完整候选，不从静态定义合成当前伟人。

`lua/resource_facts.py` 共享资源工作单位分类及可见范围内的归属／设施读取，不持有库存或动作状态。设施未知和资源目击分别保留，未受损不代表资源已供应；帝国扫描携带完成和可见性标志，未知空集不表示资源不存在。古迹／沉船另列为考古资源，不能进入建造者改良任务。

地图资源搜索由 `lua/public_reports.py` 采集，`resource_search.py` 只格式化简报，将重复范围说明共享展示，并保留地点身份、动态字段的未知值、分页、状态和完整性。命名 CLI 默认 `brief`，内部 `get_public_report` 默认 `structured`，完整展开保留逐行原生字段。`observed_total` 是已观测匹配数；原生匹配扫描不完整时 `count_complete=false`，`total` 和 `truncated` 为 null，不能因一页为空就确认资源不存在。格式化不新增游戏查询，不缓存跨动作事实，也不改变结构化采集契约。
