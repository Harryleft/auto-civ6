# 当前架构

修改状态归属或排查实现机制时读取本页对应章节。操作顺序见[游戏操作](agent-playbook.md)与[保存恢复](agent-recovery.md)，验证门槛见[开发与验证](development.md)。

## 调用关系

```text
MCP 客户端
  │ stdio JSON-RPC
  ▼
server.py：参数、工具入口、结果文本
  ▼
game_state.py：领域 interface、查询、存档替换
  ├─ actions.py：动作提交与确认
  ├─ end_turn.py：推进请求与确认
  └─ diplomacy.py：外交回应与交易阶段
  ▼
lua/：按游戏领域构造与解析 Lua
  ▼
connection.py / tuner_client.py：FireTuner 通信
  │ TCP 127.0.0.1:4318
  ▼
Civilization VI
```

游戏规则由引擎执行。GameCore 提供状态读取，InGame 发出操作，FrontEnd 提供主菜单读档。领域查询和动作保持独立，工具返回必要事实和回读结果供模型决策。

## 动作确认

已纳管动作按「单次提交 → 有界只读确认」执行。`ActionLifecycle` 唯一持有未决动作，共用提交、回应解释、明确拒绝、未知保留和确认过程；GameState 负责领域准备与结果叙述。移动、攻击、建城、生产及城市射击保留各自证据，listener 仍核对来源并只清理自身。相关依赖操作、保存和推进先核对结果；读取旧状态或丢失回应不触发自动重发。兼容私有属性只代理同一份状态，不保留副本。

使者沿用同一所有者，`lua/envoys.py` 保存请求记录与原生双侧计数。同目标重入只确认原请求，只有可用使者减少一枚且指定城邦收到的使者增加才报告完成；世界变化、取消、丢回应与不完整证据保留未决。MCP 的其他变更先经过该全局消费门禁。运行模型为单一 MCP 控制游戏；本项目不处理人工并发操作，不提供跨服务重启的意图持久化。

该约束尚未覆盖所有工具：购买、部分治理／单位动作等仍直接提交，另有仅局部回读的路径。完整入口、状态归属和逐项迁移顺序见[变更操作审计](specs/2026-10-19-mutation-audit.md)。

## 回合推进

`TurnProgress` 唯一持有未决推进、原世界身份、起始回合和原始差分快照，通过明确的 `TurnContext` 协作获取事实与报告，不读写 GameState 的任意私有字段。原身份包含文明、种子和本地玩家；确认回合增长或终局前直接核对原生身份，不依赖普通查询先刷新缓存。身份未知时保留未决，缺少原绑定不能用当前世界追认；观察到不匹配后锁存来源失效，显式受保护的会话替换才可退役。

普通概览更新观察缓存不会替换原请求基线；陈旧或未来快照不得生成错误差分，报告读取失败也不重新发送已确认推进。`turn_pending` 提供只读门禁事实，普通身份刷新不释放它。

`end_turn` 只检查阻塞、发起推进并确认结果；需要生产、科研、外交、占城或议会决策时，由模型调用相应工具。无需反思 payload 或日记前置步骤。回合数字变化后还需确认本地玩家可操作；外交回应后继续确认原来的推进请求。

`get_turn_status` 与推进共用原生阶段解释，分别保留本地活动、完整性、UI 消息处理及 complete／可提交事实。首次提交时间、最近观测与阶段变化属于同一个 `TurnProgress`；查询可更新观察事实，但不退役请求。等待预算与真实读取失败分开，时长不承担死锁判定。

## 外交与交易

`diplomacy.py` 的 `DiplomacyProgress` 持有当前语句见证、单次回应及交易尝试；`lua/trade.py` 负责准确原生上下文中的准备、事件匹配和提交。观察器只记录本世界的公开外交事件，不替模型回应。原生选项由当前会话语句解析，缺少见证保持未知，不以文本不变判断 goodbye。

交易先空条款打开会话，确认原生界面就绪后再发送，并以 nonce、世界、参与方、session 和 action 匹配响应。既有主动提案的最终接受与反提案沿其明确提交流程确认；已知零发送失败只终结本次会话。来约评估复用同一观察器，以世界、原生会话、双向条款及资格阶段指纹绑定单次 `INSPECT`／`EQUALIZE`，不重开会话、不自动接受或关闭。丢回应或取消后只确认原尝试；绑定的原生 `ZERO` 回执及零提交终结均确认后，才返回未提交并退役。外交所有者独立锁存已观测的世界不匹配，不依赖是否存在推进请求；身份未知保留未决，返回原身份不能解除已锁存失效。原生 `AcceptDeal` 资格与双向条款相等共同约束最终接受，拒绝后的相等条款不能冒充已谈妥。结果、会话终结与视图清理分别确认，取消或丢回应不重发。未决事实保护推进、保存及普通换档；显式受保护替换沿既有恢复边界处理。

## 会话替换与检查点

GameState 拥有完整会话替换；`game_launcher.py` 负责原生进程操作，`game_lifecycle.py` 负责原生菜单、加载和文件事实。MCP 只调度和展示，不写入私有门禁、重置会话或清理索引。菜单路径与完整重启复用同一加载确认。入口、时限和完成条件见[保存与恢复](agent-recovery.md)。

`replacement_pending` 只表示替换未知，保存未知由 `save_pending` 提供。`reset_session` 在显式受保护替换中退役旧动作和推进，但保留替换门禁；普通身份刷新只清观察缓存，保留未决请求。旧保存列表索引随显式替换清理。

`NativeTransition` 提供原生转换状态，`ProcessResult` 提供进程事实，展示文案不承担完成判断。原生加载调用已进入后抛错只能得到 unknown；前置条件能够证明未调用时才允许 not_submitted。重连用于发现和回读，不重放已发出的块。

`checkpoints.py` 把原生保存完成证据、精确文件指纹、身份回合和本轮标识组合成检查点记录；只有完整加载确认后才释放替换门禁，加载原始基准时才建立新轮次。操作规则集中在[检查点与测试轮次](agent-recovery.md#检查点与测试轮次)。

## 通信与验证职责

日志仅用于本地问题追踪，不参与玩法决策或回合放行。服务不启动网页、云同步、后台镜头、弹窗轮询或终局监测任务。

离线测试只收集 `tests/`。`integration_turns.py` 通过 `mcp.client.stdio` 和 `ClientSession` 启动同一 MCP 服务，复用实际工具的执行、回读与生命周期入口，不另建底层控制路径。驱动的固定策略只处理常见阻塞，异常和结果未知时停止；总时间与每回合处理次数有上限。实机验收需要固定存档并检查动作、阻塞、回合推进和显式恢复。

## 世界议会

`open_world_congress` 独立于纯查询，在已确认的原生投票阶段、存在可投选择且本阶段未提交时，执行 Intro 的 DequeuePopup → ShowWorldCongress 开始路径。开始前记录文明、种子、回合及阶段；已请求或丢应答只核对可见状态，不重复事件。原普通推进未决时可以打开议会，其他未决动作、保存及加载门禁保持。无选择或未知提案不走开始路径，以免原生 UI 自动提交与显式票计划重复。

议会查询、显式打开和显式票单共用原生阶段与提案可投资格解释。`proposal_status` 的 `CHOICES` 表示存在可投提案，`EMPTY` 表示没有可投提案（可能仍有禁投行），`UNKNOWN` 表示资格未核实；resolutions 另行按当前阶段处理，Stage2 不重投旧决议。共享解释不合并三种操作，也不引入默认投票。
