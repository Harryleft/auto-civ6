# 游戏操作

启动、查询、动作、推进和世界议会操作时读取本指南。保存、换档和未知结果处理转到[保存与恢复](agent-recovery.md)；不需要开发任务的验证流程。

制定策略与开局理解文明／领袖时，先读[获胜决策](agent-strategy.md)；本指南负责查询、合法执行和回读。

## 开始运行

1. 已有游戏和 MCP 连接时，直接调用 `get_game_overview`，确认当前文明和回合；不为检查连接而重新加载存档。
2. 需要安装或配置时，按 [README 的安装与启动](../README.md#安装与启动)完成依赖、FireTuner 和客户端配置。FireTuner 使用本机 TCP 4318，保持单一活动客户端，避免多个客户端争用连接。
3. 游戏尚未运行时，按任务授权使用 `launch_game`。已有主菜单需要加载时，按[入口选择](agent-recovery.md#选择入口)调用生命周期工具；需要替换当前对局时先核对目标检查点。
4. 读取 `get_units`、`get_cities` 等本次动作需要的事实。能够确认当前对局、回合和实体后，才开始游戏动作。

新实机测试的开局依据见[受信测试基准](../fixtures/saves/README.md)，不从历史结果或旧示例地图建立新测试。

## 动作与回读

- 使用本回合查询返回的坐标和实体 ID；不推断迷雾中的对象。
- 动作完成需要对应证据：移动位置或原生片段、城市归属、生产队列或区域落点、攻击命令或实际伤害。收到提交回应不等于完成。
- 同一意图尚未确认时，只继续确认原请求。无可见目标、旧位置或旧队列不能单独证明动作失败。
- 返回 `OUTCOME_UNKNOWN` 或其他未知结果时，进入[未知结果处理](agent-recovery.md#结果未知)，停止依赖写入。
- 移动返回 `MOVE_DEFERRED` 表示原生路径的第一步要到未来回合才能走，本次没有提交，旧队列不变。继续处理其他合法动作或在下回合重评，不反复提交相同意图；已确认的部分位移与最终到达分开判断。
- 结束前提示当回合移动队列时，先判断是否仍值得移动；需要继续则显式移动，不再需要则用 `unit_action(action="cancel_move")` 取消已核实队列，再单独选择驻防、治疗或待命。取消确认保留位置，不自动执行下一意图；`NOT_READY` 保留原活动，不代表已完成新驻防。
- `skip` 只跳过本回合，`skip_remaining_units` 只处理当前就绪单位；驻防、治疗或警戒由模型显式选择。历史驻防回合数不表示单位当前仍在待命。
- 掠夺由模型根据目标价值、反击风险和撤退路线决定。单位已在敌方目标格时，用 `unit_action(unit_id=..., action="pillage")` 显式掠夺一次；原生规则核对战争与资格，不自动移动或连续掠夺。区域内建筑与区域本体分别受损，后续层需重新判断、明确调用。`PILLAGED` 只确认所列原生损坏，未测量收益；未知时确认原请求，不追加掠夺。

## 宗教防御

`get_religion_defense` 读取当前世界、回合、本地玩家及 InGame／GameCore 范围，列出自有城市的多数宗教、信徒、累计压力 `accumulated_pressure` 与流入压力 `incoming_pressure`，以及当前可见的外方宗教单位。隐藏单位和外方城市细节不在查询范围内；空列表不能证明地图上没有传教士。

先检查范围、`partial`／`unknown` 与冲突说明，再读取逐城事实。`owned_city_majorities` 来自本方城市逐项计数；`native_religion_city_stat` 保留引擎统计含义，不能当成本方城市数。审判已启动只表示购买前提之一，不表示城市压力已清除。多数宗教、信徒与累计压力分别保留原生读数，不从某一个指标推定下一回合安全。

| 目的 | 入口与确认边界 |
| --- | --- |
| 当前谴责资格 | 查询返回同格、唯一可见宗教目标与本方 actor 的 `native_can_condemn`；执行仍使用 `unit_action(action="condemn_heretic")` 并重新核对原生资格。战争、议会决议与其他限制不能相互代替。 |
| 清除异教 | 对当前符合原生资格的审判官调用 `unit_action(unit_id=unit_id, action="remove_heresy")`，不传城市坐标。工具绑定精确所在自有城中心，或原生返回的唯一自有城市目标；若原生坐标存在则须完整且一致，确认精确操作事件、一次 charge 消耗和异教累计压力实际下降后返回 `HERESY_REMOVED`。不推定本教压力增加或城市转化。 |
| 神学攻击 | 对本次查询可见的异教宗教单位调用 `unit_action(unit_id=unit_id, action="religious_attack", target_x=target_x, target_y=target_y)`。原生宗教预演、实际目标和本回合路径都须匹配；不自动宣战。`RELIGIOUS_COMBAT_CONFIRMED` 需要原始操作和精确战斗参与者事件，加实际伤害或原生移除证据。移动或排队本身不能确认战斗。 |

议会信息只读取当前 active resolutions，保留原始目标与选项。不能唯一对应当前宗教、效果或权限来源时，返回 `unknown`；历史会议回顾不能证明和平谴责权限仍生效。具体单位能否谴责，以本次原生资格为准。

清除异教返回 `NATIVE_TARGET_UNCONFIRMED`，表示既非可核实的精确自有城中心，也无法从当前原生目标结果确定实际作用城市，本次未提交。不要补猜最近城市或复制传教坐标重发。确认后的动作可用 `get_religion_defense` 刷新逐城压力和单位；查询不会消耗行动、关闭 UI 或释放未决门禁。

返回 `OUTCOME_UNKNOWN` 时，保留原 actor、目标坐标和意图；只用完全相同的动作确认原请求。只读查询即使看到压力下降或目标消失，也不退役原请求。保存、推进和其他动作继续受门禁保护。原请求已确认后，再次相同调用属于新动作，可能再次消耗 charge。恢复操作按[未知结果处理](agent-recovery.md#结果未知)执行。

本工具链的[离线验收](acceptance/2026-10-20-religion-defense.md)与[原局实机验收](../games/2026-10-19-gold/runs/2026-10-19-first/religion-native-validation-2026-10-20/acceptance.md)分别保留。模型按本局局面选择是否防御；Runtime 不设固定城市比例、强制回合检查或后台防御策略。

## 推进回合

1. 完成当前策略所需动作，读取必要的回读结果。
2. 调用 `end_turn`。该工具没有 reflection 参数，也不要求反思或日记。
3. 返回具体阻塞时，读取对应领域信息，再由模型明确选择科研、生产、政策、外交、交易、占城或议会操作。
4. 外交、交易、议会或信息弹窗暂停了已提交推进时，显式解决阻塞。外交返回 `SESSION_CONTINUES` 时先读取并处理剩余对话，直到会话结束，再调用 `end_turn` 确认原请求；确认回合后才保存。
5. 返回等待时，用只读 `get_turn_status` 查看原生阶段、交互待办和累计等待；按下表处理。一次观察预算耗尽或阶段不变都不证明死锁。
6. 回合增加且本地玩家已就绪后，才能开始下一回合。只读阶段查询不清未决门禁；即使已看到更高回合，仍用 `end_turn` 确认原请求。报告读取失败只限制变化说明，不构成重新推进的理由。

| 观测 | 判断与处理 |
| --- | --- |
| `WAITING_FOR_PLAYERS` | 本地回合未活动，继续确认原请求；该状态不证明某个 AI 的计算进度。 |
| `LOCAL_TURN_STARTING`／`UI_PROCESSING` | 本地回合或消息尚未就绪，等待原生完成。 |
| `LOCAL_ACTION_REQUIRED` | 有具体本地待办或可执行移动队列，明确作单位／城市决定；剩余行动能力不构成必须移动或攻击的理由。 |
| `LOCAL_COMPLETION_UNCONFIRMED` | 请求进入后仍在原回合、本地未送完成，不能称为其他玩家等待；保留原请求与门禁，按恢复指南处理。 |
| 外交、议会或信息弹窗待办 | 有具体交互阻塞，读取相应领域后显式处理。 |
| 未知字段／实际读取错误 | 保留未知和未决门禁；错误与观察预算到期分别报告。 |

## 交易与外交

`propose_trade` 的预览和发送都须等待本次会话的原生响应；返回未确认时只核对原尝试，不据旧工作交易缓存或瞬时空态重开会话。AI 提出不同条款时，先比较实际代价，再明确选择；不把预览当作成交。

来约先用 `get_pending_trades` 读取原生报价、当前编辑稿及 `fingerprint`。用 `negotiate_incoming_trade` 明确调整已有金币／每回合金币条款并 `inspect`；`equalize` 请求对方反提案，可能改动其他条款。两者均不成交、不另开会话，普通回合未决时可处理其已核实来约；未知时重复只确认原尝试。再次出价前刷新指纹，最终决定用 `respond_to_trade`；编辑未评估、被拒或未知条款不能接受。缺失、重复或锁定的金币项不自动新增／删除。

用 `get_pending_diplomacy` 核对当前原生选项；仅有退出选项时显式使用 `EXIT`。选项未知时继续读取，不按文本不变推断 goodbye，也不默认发送 POSITIVE／NEGATIVE。

交易结果、会话终结和视图清理分别确认。无会话、排队会话或待回应交易时，显式 `dismiss_popup` 可沿原生关闭路径清理残留视图；真实外交待办仍须明确回应。清理失败不重提交易。需要恢复时转到[保存与恢复](agent-recovery.md)。

## 世界议会

1. 使用 `get_world_congress` 读取原生阶段和本地请求状态；单凭「正在开会」不能判断本地玩家需要投票。查询保持纯读。
2. 原生阶段和选择已确认、需要开始投票界面时，调用 `open_world_congress`，再读取 `get_world_congress` 获取议题；打开工具不替模型投票。
3. 用 `queue_wc_votes` 提交明确票单。`votes` 是 JSON 数组字符串：决议使用 `hash`、`option`、`target`、`votes`；提案使用本次查询返回的完整 `proposal_key`、`option`、`votes`。提案的 `option=1` 赞成、`option=2` 反对，决议按当前 A／B 效果选择；目标和票数依据当前选择及共同预算，不提供默认票，不复用旧会议的标识。
4. 当前原生阶段已确认没有任何选择时，显式传入 `votes="[]"`；此时不走可能自动提交的 Intro 开始事件。Stage2 不重投 Stage1 的旧决议。
5. 已记录提交或继续请求后，只读核对状态；原普通推进尚未完成时，用 `end_turn` 确认，不重复开始、投票、提交或阶段继续。

| `proposal_status` | 含义与处理 |
| --- | --- |
| `CHOICES` | 存在可投提案。显式提供每项提案的票，并与本阶段决议合为同一计划；不以只有决议的票单隐式略过提案。 |
| `EMPTY` | 没有可投提案，可能仍有禁投行。仍需核对本阶段是否有决议，不能仅据此提交空计划。 |
| `UNKNOWN` | 资格未核实。继续查询或报告问题，不推断为无选择。 |
