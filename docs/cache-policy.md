# 状态分类、缓存与历史窗口

缓存按信息的有效条件复用。5／10／20 回合表示历史分析范围，不能用作敌军位置、可行动单位或可用预算的有效期。

## 分类与当前实现

| 信息 | 有效边界 | 实现与使用方式 |
|---|---|---|
| 科技、市政的名称、时代、提升说明、前置关系、解锁内容 | 同一规则环境、对局、语言与连接代次 | `ResearchCache` 按类型 ID 增量缓存已查询到的定义；Lua 后续返回对应动态字段，由 Python 恢复原有 DTO |
| 已完成科技／市政 | 当前对局分支内的累计状态 | 每次科研请求仍读取完成集合，不因退出历史窗口删除；读档重新建立分支 |
| 研究进度、实际成本、剩余回合、提升状态、合法候选及缺失前置 | 当前采集 | 实时读取；规则缓存不能替代合法性检查 |
| 城市、单位、外交、政策、资源、地图与蛮族 | 同一次请求中的采集范围 | `ReadCache` 在同一异步任务的一次 collection 内复用；下一个 MCP 请求重新读取 |
| 世界变化与受影响领域 | 相邻 typed snapshot，同一 epoch | 由 `GraphDelta` 派生有界摘要；首次采集或读档后只建立基线 |
| 近 5／10／20 回合趋势 | 当前 epoch 内真实观测的回合区间 | 从现有 Observation 派生 `history_summary`，不新增持久化账本、不补齐缺测、不代替当前事实 |

地块坐标、已探索范围、领土、改良设施和可见资源不能整体当成永久不变量。当前实现保守地实时读取地块状态；科技完成信息变化会触发“补查资源可见性”的提示，但不会声称资源已经发生变化。

## 规则复用

`GameState.get_tech_civics()` 的返回类型不变。`ResearchCache` 仅保存已经返回过的定义，不预读整个隐藏树，也不持久化跨进程数据库。规则身份包括实际 ruleset、随机种子、速度、本地玩家与语言样本，并叠加连接代次及本地读档代次。

只有 `GAMEMODE_TREE_RANDOMIZER` 明确为 false／0 时才允许复用。开关启用、开关未知、身份缺失或连接生命周期不明时走完整读取。缓存缺项或协议不匹配会清缓存并尝试完整读取；读取失败不会留下可复用的半成品。本改动不修复原先随机树查询本身的其他机制限制。

这层减少重复的描述／解锁信息生成和返回；动态候选与缺失前置仍在 Lua 中计算。不能将它描述成“以后查询科技不再访问游戏”。

## 动态采集与失效

`_logged` 为 `get_` 查询建立 collection；`get_governance_snapshot()` 也可以独立建立 collection。嵌套采集共享已经取得的 typed 数据，部门继续消费同一份图快照。子任务不会继承父任务的部分采集结果，缓存返回值也不会因调用者修改而污染。

- 同一采集中，重复读取总览、政策和蛮族等状态会复用。typed snapshot 的开始／结束回合检查始终访问游戏。
- `execute_mutation` 进入发送临界区前递增 `mutation_revision`，成功、失败、结果未知均作废先前缓存。重连／断连递增 `generation`。
- 采集中回合改变或检测到提交／重连，清空本次缓存并重新采集，最多重试一次；不能一致时显式报错。
- 每个独立 `get_game_overview` 请求都重新采集治理快照。异步动作可能在第一次回读之后才生效，账本中的动作时间早于快照并不能证明快照仍有效。
- 三个普通读档工具在尝试前清空缓存。成功提交、未知结果、提交后报错或取消均切换 epoch；无提交的明确拒绝不建立假成功。若只能确认发出了请求而无法确认是否加载，保守地作废旧分支。
- `off` 模式仍清除运行时缓存；原始日志与 belief mode 的既有边界不变。

这并不是游戏引擎的原子事务。外部操作和异步变化未必在连接计数器中可见，因此动态状态不跨独立请求保留，也不按“同一个回合”无限复用。关键动作仍需新的直接回读。

## 图变化进入决策上下文

`get_governance_brief.snapshot.world_changes` 包含本次采集的 `snapshot_id/turn/epoch`、变化总量、最多 8 条对象／关系变化、`affected_domains`、重评原因和待补查事项。总量与领域分析使用完整变化集合，不受展示条数限制。总览显示更短的中文说明。

只比较世界来源的内容变化，忽略治理写入和纯时间戳变化。`removed`、`no_longer_visible`、`not_observed` 和 `reobserved` 分开；不从“没看见”推断被消灭。采集批次的新鲜度不从内容去重后的节点 `last_observed_turn` 推断。

`affected_domains` 用于指导模型优先重评相关事项；当前部门协调器仍保留全部硬约束与预算检查，没有跳过未列出的部门。后续若要缓存部门决策，必须先明确其世界、治理、预算和时间依赖，不能只按部门名字或回合数复用。

## 5／10／20 回合历史

在 T29，三个窗口分别为 T25–29、T20–29、T10–29，包含当前回合。T0 也合法。每个指标在同回合多次观测时取最新有效值；未来观测和无效数值被排除。

默认最多 8 个指标：科研、文化、金币、每回合金币、城市数、人口、单位数和探索比例。每项保留实际采样回合数、覆盖率、首末观测、变化量和末次观测年龄。只有一个采样点时变化量为 null；缺测不能按零处理。已完成科技等累计事实不受窗口淘汰影响。

历史视图直接读取冻结的图属性，避免为生成几个指标而复制全部历史大对象；重复请求沿用现有 `(turn, limit, journal sequence)` 简报缓存。趋势外推的回看窗口也改为实际回合范围，不再按最后 N 条样本计算。

## 模型结果与验证

现有模型结果过滤仍只覆盖三个控制面工具，超过已有阈值才触发。治理摘要增加同一响应内部的重复指标引用、变更 ID 列表的计数及限量展示，保留门禁、预算、置信缺口、图变化和历史覆盖。引用不依赖模型记得上一条消息。遥测保留完整原文。

离线回归覆盖：collection 查询次数及同回合重新读取、异步变化后的第二次回读、未知动作、重连和读档、科研字段合并与随机树禁用、图基线／可见性、稀疏历史及 T0／读档、压缩后硬约束保留。真实 FireTuner 时延、游戏内规则开关返回和实际模型 token 成本需要在获授权的游戏运行中测量；离线通过不代表这些现场指标已验证。
