# 特殊操作指南

议会、国家间交易、外交对话、强制选择和信息弹窗可能进入独立交互状态或暂停回合推进。出现对应待办时读取本指南，按当前状态进入相应章节。常规动作见[游戏操作](agent-playbook.md)，选择的战略依据见[每局策略检查清单](agent-checklist.md)。

下文均为同一 [CLI 会话](cli.md)的命名命令。变更先 `--dry-run`，明确执行后沿原命令确认；MCP 仅在 CLI 内部运行。

## 公共流程

1. **识别状态。** 使用 `turn status`、`notifications show` 或对应领域查询，确认当前世界、回合、参与者、待办对象及已存在的请求。界面可见、提示文字或单次观察超时只提供线索。
2. **明确选择。** 读取本次原生合法选项、目标、费用及限制，比较战略影响，再明确本次意图；选择采用当前实体 ID 和候选标识。
3. **提交与确认。** 每个明确意图提交一次。已有未决请求时，沿原入口确认该请求；阶段观察和普通查询不释放门禁。查询仍无法确认时，保留原对象与请求，按[结果未知](agent-recovery.md#结果未知)处理。
4. **完成收尾。** 分别核对本次操作结果、会话或阶段完成，以及界面暂停是否解除。收到提交回应或弹窗消失，都不足以单独证明全部完成。
5. **恢复推进。** 如果特殊操作暂停了已提交的回合推进请求，用 `turn end` 确认原请求；下一本地可行动回合已确认后再进入常规决策。若返回 `REOPENED_LOCAL`，表示原回合重开、本次未推进，先处理报告的本地待办，再单独请求新推进。没有原推进请求时，回到常规流程决定是否结束回合。

完成依据只针对本次操作；出现新的待办时，按新状态继续分流。保存、加载、断线、挂起和显式恢复统一使用[保存与恢复](agent-recovery.md)，不另建恢复流程。

## 世界议会

**进入条件：**议会待办、会期或阶段变化，或 `turn end` 报告议会暂停。

1. 使用 `congress show` 读取原生阶段和本地请求状态；单凭「正在开会」不能判断本地玩家需要投票。查询保持纯读。
2. 原生阶段和选择已确认、需要开始投票界面时，调用 `congress open`，再读取 `congress show` 获取议题；打开工具不替模型投票。
3. 用 `congress votes` 传入明确的完整票单。会期前可登记等待执行的计划，会期内则可立即执行原生投票、提交和阶段继续；按返回状态分别核对。`votes` 是 JSON 数组字符串：决议使用 `hash`、`option`、`target`、`votes`；提案使用本次查询返回的完整 `proposal_key`、`option`、`votes`。提案的 `option=1` 赞成、`option=2` 反对，决议按当前 A／B 效果选择；目标和票数依据当前选择及共同预算，不提供默认票，不复用旧会议的标识。
4. 当前原生阶段已确认没有任何选择时，显式传入 `congress votes '[]'`；此时不走可能自动提交的 Intro 开始事件。Stage2 不重投 Stage1 的旧决议。
5. 已登记票单或已记录投票、提交、阶段继续请求后，只读核对状态；原回合推进请求尚未确认时，用 `turn end` 确认，不重复开始、投票、提交或阶段继续。

| `proposal_status` | 含义与处理 |
| --- | --- |
| `CHOICES` | 存在可投提案。显式提供每项提案的票，并与本阶段决议合为同一计划；不以只有决议的票单隐式略过提案。 |
| `EMPTY` | 没有可投提案，可能仍有禁投行。仍需核对本阶段是否有决议，不能仅据此提交空计划。 |
| `UNKNOWN` | 资格未核实。继续查询或报告问题，不推断为无选择。 |

`REGISTERED` 只表示投票计划已登记，允许显式调用 `turn end` 触发原生阶段事件，尚不表示已经投票。部分提交或结果未知时，沿原请求核对，不重新登记或补投。阶段查询只观察，不自动继续或退役原请求。

**完成依据：**本次投票请求的原生阶段已完成，才可读取新阶段并决定是否存在新的选择。阶段完成不证明所投方案获胜；投票结果需另查。如果原推进被暂停，再按[公共流程](#公共流程)确认推进结果。

## 国家间交易

**进入条件：**主动提出国家间交易、收到来约或反报价。商人建立贸易路线属于常规单位操作。

1. 主动交易前使用 `trade options PLAYER_ID` 核对双方可交易内容，比较物品、期限、持续收支和下一关键行动的资源需求。有限试价，明确本次预览或发送意图。
2. `trade propose PLAYER_ID` 的预览和发送都须等待本次会话的原生响应；返回未确认时只核对原尝试，不据旧工作交易缓存或瞬时空态重开会话。AI 提出不同条款时，先比较实际代价，再明确选择；不把预览当作成交。
3. 来约先用 `trade pending` 读取原生报价、当前编辑稿及 `fingerprint`。用 `trade negotiate PLAYER_ID --fingerprint VALUE` 明确调整已有金币／每回合金币条款并 `inspect`；`equalize` 请求对方反提案，可能改动其他条款。两者均不成交、不另开会话，回合推进请求未决时可处理其已核实来约；结果未知时重复只确认原尝试。再次出价前刷新指纹，最终决定用 `trade respond PLAYER_ID --accept` 或 `trade respond PLAYER_ID --reject`；编辑未评估、被拒或未知条款不能接受。缺失、重复或锁定的金币项不自动新增／删除。
4. 交易结果确认后，读取 `diplomacy pending`，处理当前后续选项直至会话结束；界面残留按[外交界面清理](#外交界面清理)处理。

来约中的协议名称使用当前原生条目名称或 SDK 对应的外交行动名称；无法解析时显示 `Unknown Agreement` 及原始 subtype／value，不能从通用 Agreement、期限或金币推定为讲和、通行权或结盟。期限与金额保留本案原生报价，静态规则的默认期限不能覆盖它。

**完成依据：**本次交易已确认成交、拒绝或未提交，且本次会话已结束。原生预览可接受仅表示当次评价；会话结束也不能单独证明成交。若仍未知，按[公共流程](#公共流程)保留并确认原请求；若原推进被暂停，继续确认原推进。

## 外交对话

**进入条件：**要求、谴责、承诺、问候或其他外交会话，包括推进时出现的外交暂停。

1. 用 `diplomacy pending` 核对当前原生选项；仅有退出选项时显式使用 `EXIT`。选项未知时继续读取，不按文本不变推断 goodbye，也不默认发送 POSITIVE／NEGATIVE。
2. 对当前参与者调用 `diplomacy respond PLAYER_ID RESPONSE`，使用本次原生选项作出明确回应；回应未知时，相同调用只确认原请求。
3. 返回 `SESSION_CONTINUES` 时重新读取当前选项，继续处理本次会话。对方回复「谢谢」仍可能有 `EXIT`，须完成退出。
4. 返回 `SESSION_CLOSED` 后用 `diplomacy pending` 核对本次会话已结束；其他新会话作为新待办处理。若回执同时含 `TRADE_CONFIRMATION_PENDING`，原交易尚待收尾；按所示玩家与 test／send 模式，以原 offer／request 重复原 `trade propose` 仅确认，不另开交易、不改参。该确认不重发提案；在原生清理确认前，游戏写入仍受门禁保护。

已核验参与者的会话仍开放、但没有当前语句或界面时，按[保存与恢复的入口选择](agent-recovery.md#选择入口)判断是否显式取消原会话。多个会话分别核对参与者；不能把空选项当作退出选项，也不能用关弹窗代替会话取消。

**完成依据：**所选回应已确认、本次会话已结束。若仍有外交视图，按[外交界面清理](#外交界面清理)处理；若原推进被暂停，再确认原推进结果。

### 外交界面清理

交易结果、会话结束和界面清理分别确认。确认不存在活动或排队外交会话、也没有待回应交易后，可显式调用 `popup dismiss` 沿原生关闭路径清理残留视图。真实外交待办先明确回应，清理失败不重提交易。需要恢复时转到[保存与恢复](agent-recovery.md)。

## 强制选择

**进入条件：**通知或推进报告要求时代着力点、间谍逃离、占城或忠诚翻转后的城市决定。常规科研、生产和单位待办仍按[游戏操作](agent-playbook.md#推进回合)处理。

1. 使用 `notifications show`、`turn status` 与对应领域查询，定位本次待办对象。
2. 按下表读取当前候选并明确选择。未取得合法候选或无法核对对象时保留未知；静态支持的动作名称不表示本次必然可执行。
3. 执行后回读对应状态和待办。结果未知时，用相同对象、相同意图确认原请求，不改选项试探。

| 待办 | 查询与提交 | 完成依据 |
| --- | --- | --- |
| 时代着力点 | `era dedications` 读取当前时代与可选项；`era choose INDEX` 使用本次索引选择，再回读 | 选择已确认，对应着力点待办解除 |
| 间谍逃离 | `spy list` 读取原间谍 ID 与列出的路线；`spy action UNIT_ID "escape:<列出的区域>" 0 0` 明确选择 | `ESCAPE_ROUTE_CONFIRMED` 确认原间谍的逃离选择门禁解除；不据此推定已返回或存活 |
| 占城或忠诚翻转决定 | `notifications show`、`city list` 定位原城市；`city decision CITY_ID ACTION` 重新核对原生待决身份与资格 | 原城市决定已确认，归属或移除效果及该待办状态符合结果；未知时保留原城市 |

城市决定支持 `keep`、`reject`、`raze`、`liberate_founder`、`liberate_previous`，适用情形由原生资格决定；保留、拒绝、夷平和解放均须模型明确选择。`popup dismiss` 不代替这些选择。

**完成依据：**指定对象的选择已生效，对应待办解除。若后续仍需旅行、建设或等待，分别按实际进度观察；原推进未确认时按[公共流程](#公共流程)继续确认。

## 信息弹窗

**进入条件：**推进或动作报告历史时刻、科技完成等信息界面暂停，且没有需要先回应的真实会话或强制选择。

1. 用 `turn status` 和必要的领域查询区分信息展示、外交、交易、议会和强制选择。属于其他章节的待办，先按对应流程处理。
2. 对已确认的信息界面显式调用 `popup dismiss`，核对工具返回及当前暂停状态。
3. 如果暂停了原动作或推进，沿其原入口确认；出现新的待办时重新分流。

**完成依据：**本次信息界面造成的暂停已解除，原请求的结果已确认，或已明确定位到下一待办。弹窗关闭后仍无法确认原请求时，保留未知并按[保存与恢复](agent-recovery.md#结果未知)处理。
