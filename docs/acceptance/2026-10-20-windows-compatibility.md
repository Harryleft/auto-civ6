## 代码改动

| 问题 | 处理 |
| --- | --- |
| 知识 CLI 继承 MCP 输入，在 Windows 下卡住 | 子进程 `stdin=DEVNULL`，真实 stdio 回归测试覆盖连续搜索和分层读取 |
| Windows 默认 GBK 与中文元数据、知识 JSON 冲突 | 元数据显式 UTF-8，知识子进程显式 `-X utf8`；通用 MCP 示例提供 `PYTHONUTF8=1` |
| 元数据包名查询不匹配 | 使用实际分发名称 `civ6-mcp`；保留源码版本回退 |
| Windows 检出知识文件变成 CRLF，破坏指纹 | 仓库 `.gitattributes` 固定知识目录为 LF，不更改知识规则和指纹清单 |
| Steam 安装在非默认盘符时发现失败 | 查询注册表中的 Steam 根目录，再解析外部库清单；没有清单时仍可发现根库中的游戏 |
| Steam URI 桌面关联存在额外依赖 | 已找到 Steam 程序时直接使用 `steam.exe -applaunch 289070`；保留 URI 和实际游戏 EXE 回退 |
| 文档目录重定向导致存档定位错误 | Windows 读取系统文档目录登记路径；提供跨平台的 `CIV6_SAVE_DIR` 显式覆盖 |
| 游戏辅助进程继承协议管道 | 启动与进程查询使用空标准输入；Windows 本机命令容忍本地化输出解码差异 |
| 导出脚本引用 Windows 不存在的 SIGPIPE | 按信号存在性设置；导出和日志拆分显式 UTF-8，CSV 避免额外空行 |
| 采集结果出现 Windows 反斜杠逻辑路径 | 知识采集的相对来源标识统一为 POSIX 格式，不改变实际文件路径 |

新增 `platform_paths.py` 集中处理路径。macOS 原有默认路径和 Steam URI 启动保持原语义，不引入平台模拟层或新的运行服务。

## 测试兼容

现有部分测试默认运行在 Unix：全局替换 `socket.socket` 会破坏 Windows 事件循环内部唤醒管道，`os.kill(pid, 0)` 的异常和进程启动器 PID 也与 Unix 不同。现在只隔离被测模块的游戏通信和启动器，保留事件循环所需的标准库类型；超时回收测试同时核对实际进程退出。

涉及多次延迟观察的几个夹具，在 Windows 下给予可容纳调度粒度的预算；显式截止时间测试继续检查有界完成，没有放宽运行层动作确认规则。SQLite 测试夹具显式关闭连接，避免 Windows 删除已打开文件失败；带引号的非法 Windows 存档名验证为提交前拒绝。

新增 Windows 路径、外部 Steam 库、元数据、知识 UTF-8、脚本启动和实际 stdio 测试。CI 配置增加 Windows、macOS 和 Linux 原生运行器；本次没有推送，因此新增 CI 矩阵尚未在 GitHub 上执行。
