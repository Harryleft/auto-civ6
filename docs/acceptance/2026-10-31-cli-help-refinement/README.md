# CLI 短帮助与按需文档：实施及五智能体复验

结果：读取量下降，原有条件可完整展开，同口径主评分没有下降。五个新智能体的标准化资料输出均值从 123,401.8 B 降为 81,435.6 B，减少 **34.01%**；仓库资料组减少 **38.82%**。总平均覆盖得分从 44.6／48 提高到 47.6／48。仍有两处书面完整性遗漏，不能表述为五份答案均逐项完整，也不以 n=5 宣称统计非劣或实战收益。

所有复验为离线操作。未查询、加载、推进或修改真实游戏；原始四叶草基准和既有 T100 核验存档指纹未变。

## 实施范围

受测源固定为 `b0d21a3ef9c3c79e43b0fe29a909bc449ed63fb3`。主要实现提交为 `eb714d8`，后续仅明确了索引中短帮助与详细条件的关系。相对修复前，生产源码只改 `src/civ_mcp/devtools/commands.py`、`src/civ_mcp/devtools/debug.py`；未修改 GameState、Lua、业务参数映射、规则包、单次提交、确认器或原门禁。

| 入口 | 就近提供的事实与边界 |
| --- | --- |
| `city list`、`empire cities` | 逐城多数宗教 ID／名称；-1、0、unknown 的区别；InGame 来源；玩家多数与全局统计不替代逐城值；压力另查 |
| `map area` | GameCore `Plot:GetYield`、小数与负数；InGame workforce 是不同语境；整数差异原因未知；F/P 零、块内省略 G/S/C/Fa 和无收益块的含义 |
| `government list/change` | 一般开关、当前窗口与逐目标拒因分开；保留当前的 ACK 与新政体选择分开；政策付费不创建政府窗口 |
| 单位／城市读取与移动 | 普通实体读取可能确认原动作；原请求仍 pending 才同参确认，已经确认后不能当作确认重发 |
| `unit combat-preview` | 原生动态估计、Runtime 提前拒绝不是引擎禁止、unknown 与神学／AIR 边界、预估不保证实战；公开前后状态与 pending 核对 |
| `save reload/load`、`game recover` | 对应入口、当前轮登记检查点、原成果保全、复验结果另存、恢复后实体与 pending／transport 核对，不为清理再推进 |

新增 `help GROUP COMMAND`，与原 `GROUP COMMAND --help` 生成同一份本地帮助。未知名称、业务参数和破损引号只返回错误；它不调用业务工具，也不确认／释放既有 pending。CLI 启动仍有 MCP 初始化、发现及内存状态读取，不能把「帮助零业务调用」说成进程零协议通信。

[CLI 索引](../../cli.md) 从原 65,292 B 缩至 **4,048 B（减少93.80%）**，原文迁移到 17 份领域说明。原 501 行在重定位链接、提升页首标题及增加导航后均按顺序保留，全部既有小节锚点仍在索引；详细条件和例外没有因缩短入口被删除。少量新增说明补齐查询确认与恢复后核对。迁移证明见 [doc-relocation.json](doc-relocation.json)。这表示入口变短，不是全体知识总量缩小。

## 五个新盲智能体的口径

与[首轮](../2026-10-31-agent-knowledge-use/README.md)使用相同的 12 题、提示词、2 对照／3 实验比例、20 次材料操作／2 个 CLI 会话／40 条会话命令预算、48 分主评分与宽松敏感性分析。五者均为新的 `fork_turns=none` 会话，继承同一宿主模型设置，没有收到旧答案或中途反馈。

对照使用更新后的离线 CLI；实验额外获得当前仓库知识。封存了上一轮和本轮的答案、评分、报告及其验收索引，防止从新增评估文档中读取答案；其余材料为固定源版本的未修改副本。分组、排除清单、字节公式和评分条件在启动前冻结，见 [preregistration.json](preregistration.json)。

盲法限制沿用首轮：文件是否存在可能暴露访问条件；宿主强制上下文和预训练知识不能移除；材料访问协议不是 OS 沙箱；评分者可从引用推测分组。因此不宣称严格双盲或完整宿主工具审计。

资料输出口径为材料 list／read／search 的成功输出字节，扣除共同题目与说明的直接读取，再加本地帮助、预演、错误和 pending 的规范化 JSON 负载，以及知识工具文本正文。去除事件时间、序号等包装，使用相同算法重算两轮原始记录，不能拿首轮仅材料字节与新轮合计比较。这不是 token、全部协议流量或证明模型看见每一字节的指标；工具截断和未记录的 stderr 不在该口径内。

统计有一项公开修正：冻结的分析器错误假设每次合法 CLI 启动都会产生 debug 证据；r11 曾调用顶层 `--help`，按设计不启动 MCP、不生成该目录。原分析器和失败记录保留，v2 对这一次在冻结源下确定性重放，并保守补计完整1,363 B，未将重放伪装为当时原始输出。规则、题目、评分和样本均未改变。修正说明见 [analysis-correction.json](analysis-correction.json)，两轮均以 v2 重算。

三名新实验者均直接读取领域页，没有首轮约28.7～29.6KB的重复区间输出；其中一名还读了4KB短索引，其余通过目录／检索直接定位小页。不能把这一结果归因于「所有人先按AGENTS路由」。

## 条件覆盖与剩余问题

| 检查项 | 新轮覆盖 |
| --- | --- |
| 逐城宗教窄查询及 ID／unknown 区别 | 5/5 |
| 地图精度、来源、零与 unknown 契约 | 5/5，按语义判分；r35用 `Plot:GetYield` 对比 InGame，没有重复 GameCore 字样 |
| 预估不等于引擎许可、神学边界及 pending | 5/5 |
| 实体读取已确认后不再重发原动作 | 5/5 |
| 恢复后实体、pending 和 transport 核对 | 5/5 |
| 明确保留当前政体的 ACK | 4/5；r24只说继续采用与换新政体分开，未明确 ACK |
| 明确复验结果另存后再恢复 | 4/5；r11的结果另存时点表述含混 |

上述两处遗漏按首轮同样标准各扣1分，没有因引用过文档而补分。原答案、逐项条件与缺项理由分别保存在 [answers/](answers/)、[case-scores.md](case-scores.md)、[scores.json](scores.json)。原三题宽松敏感性口径下，新轮两组均为48分，首轮对照44.5、实验48，方向没有倒转。

还有两项判分与效率边界：C01题未给城市ID，r46使用合法的无ID `city yields` 读取所有本方城市，覆盖条件但不是未来最小返回范围；C10接受原生 getter 与 InGame 的语义区分，不要求逐字复述来源标签。它们均在固定评分说明中披露，不作为实际执行证明。

r35曾请求不存在的 `help government set`，被本地拒绝并提示实际选项，最终答案改为 `government change`；没有目标 RPC，错误输出计入成本。八个离线 debug 会话全部关闭，transport 为 null、没有 context loss／pending 或游戏连接；另一次顶层帮助未启动 MCP。

材料操作和命令次数并未下降：实验组平均 CLI 命令3→10，对照37.5→40。这里确认的是资料输出量下降和本次主评分不降，不能宣称端到端更快、每份答案完整、整体模型非劣或胜率提高。新对照也能接近满分，说明将知识放到命令附近后，许多问题不再需要额外翻阅大量文档。
