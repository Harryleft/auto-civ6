# 取消失去路径的移动队列

状态：ready-for-agent。起点 `3a26445`；实机证据在 `~/.civ6-mcp/acceptance/20261018-turn121-scheduling/live/060–067`。

## Problem Statement

T104，弩手仍指向已被己方骑士占用的目标格。原生队列存在，路径的 plots／turns 为空，取消资格为 true，核心不忙。当前取消入口要求路径完整，返回 READINESS_UNKNOWN，无法由模型取消过时意图；推进门禁也保留未知，形成可避免的本地阻塞。

## Solution

显式取消只验证“这是当前本方单位的普通移动队列，且原生允许取消”，不把路径可行性当作取消条件。结束回合仍保守处理未知路径，由模型决定取消或改派。

## User Stories

1. 作为操作 Agent，我能取消目标被占用、路径为空的旧队列，重新选择驻防或目标。
2. 作为操作 Agent，我能区分存在队列与队列当回合可执行，未知路径不自动推进。
3. 作为用户，我的商路、间谍及忽略移动规则的活动不被普通取消误伤。
4. 作为用户，取消只提交一次，确认丢失时保留原请求，不移动单位或隐式待命。
5. 作为用户，对局、回合、单位或位置变化时，不把旧取消确认为成功。

## Implementation Decisions

- 最小调整既有本地准备事实：分离队列目标及归属的已知性与路径时序已知性，复用现有扫描；不新增控制实现。
- 目标和单位坐标须有效、目标不同于当前位置、商路归属明确为 false，单位 Spy／IgnoreMoves 均明确为 false，核心明确空闲。
- 有效目标但路径空、不可用或异常不阻止显式取消；目标／归属／核心状态未知仍零提交拒绝。
- 保留原生 strict CanStartCommand、单次 RequestCommand 和现有作用域及回读确认。
- 未知路径对 end_turn 仍是未知；不能自动取消、跳过、清除门禁或重启。

## Testing Decisions

沿用已授权 GameState／FakeConn 及 Lua 5.1 执行边界。先复现空 plots／turns 队列，再最小修复；补充路径缺失／抛错及目标、商路、核心未知的行为验证。复用丢回复、作用域变化及无隐式动作回归。仅测试取消、单位就绪及直接相关调度模块。

## Out of Scope

不改变移动策略、不让 end_turn 猜测路径、不自动取消、不修改资源、外交、存档及既有验收。
