# 终局续测：世界议会提案的显式投票

标签 ready-for-agent；本地 Markdown tracker；基点 `e0b4889`，沿用 `codex/architecture-deepening`。

## Problem Statement

第 167 回合议会同时包含三项决议和“世界博览会”竞赛。查询只展示决议及提案 CHOICES 标记，投票入口在任何发送前拒绝全部计划。模型既读不到完整议程，也不能为竞赛作出选择，原推进请求因此停在 STAGE1。

## Solution

同一查询完整展示当前可投提案、方向限制与费用；同一投票入口接收模型对决议和提案的完整显式计划，统一验证和预算后单次提交当前阶段，再确认原推进请求。保留空阶段、未知结果和无重放保护。

## User Stories

1. 作为玩家，我希望读到竞赛名称、目标和规则，以便决定赞成或反对。
2. 作为玩家，我希望紧急事件同样可见，以便判断是否参与。
3. 作为玩家，我希望看见禁投方向与禁投原因，以便提交合法计划。
4. 作为玩家，我希望每个可投议题都由模型选择，以便不产生隐藏默认票。
5. 作为玩家，我希望决议与提案共同消耗本方支持度，以便不超预算。
6. 作为玩家，我希望类别专属票费被保留，以便正确估算花费。
7. 作为玩家，我希望提案标识包含原生类型、目标与可空发起方，以便竞赛不被误认成另一议题。
8. 作为玩家，我希望缺项、重复、过期及非法方向在任何发送前拒绝，以便能安全修改计划。
9. 作为玩家，我希望 STAGE2 不重复 STAGE1 决议，以便不重复投票。
10. 作为玩家，我希望所有提案禁投时仍允许明确空计划，以便不引入新阻塞。
11. 作为维护者，我希望查询、打开与投票共用资格解释，以便三个入口不会分歧。
12. 作为维护者，我希望异常和丢响应保留已提交状态，以便不会重复讨论票或阶段继续。
13. 作为测试者，我希望离线真实 Lua 覆盖请求参数和计数，以便证明原生交互而非复制算法。
14. 作为玩家，我希望修复后继续原地图至引擎胜负终点，并保留原始及本次检查点。

## Implementation Decisions

- 扩展现有议会领域与公开投票参数，不新增独立后台服务、自动投票器或第二套议会状态机。
- 查询由本机原生提案分类及条目产生，保留名称、类型、目标、可空发起方、稳定原生组合标识、可投方向、禁投状态和类别费用。原生类型、限制或费用不明则明确 UNKNOWN，不生成默认或伪造议题。
- 保持既有决议票对象兼容；提案票以查询提供的唯一组合标识区分，并显式提供方向与票数。两种对象不得混用标识；重复、未知或不属于当前阶段的标识均拒绝。
- 组合标识依照本机官方 TypeName、Target、Sender 或 NONE 规则。提交参数严格遵循本机 WORLD_CONGRESS_DISCUSSION_VOTE；无法唯一映射到原生请求的情况拒绝，不猜测发起方或目标。
- STAGE1 处理当前决议及提案，STAGE2 仅处理当前提案。完整预验证后才发送任何请求：覆盖全部可投条目，遵守 Disabled 与 NoUpvote／NoDownvote；所有禁投条目不需要默认票，仍验证未知数据。
- 决议与提案共享支持度预算，使用原生通用或类别专属累计费用与上限，沿用显式最大票数语义。预算不足时按已说明的最大票数分配规则处理；缺失、非数、非法费用在发送前拒绝，不将未知费用视为免费。
- 沿用现有身份、回合、阶段和请求锁存；每个阶段最多一次投票计划、一次 SUBMIT_TURN 和一次继续。已发送或未知结果只允许查询确认，不重放。已知预验证失败允许修正计划。
- 当前现场不通过隐藏 UI 默认投票或删除缓存跳过；必要恢复优先菜单，无法安全换档才使用明确故障恢复。诊断重放单独计数。

## Testing Decisions

沿用用户已确认的 GameState／FakeConn、现有 Lua 5.1、内存 FireTuner 流及临时目录边界，不连接游戏；无需重复确认。

- 真实生成 Lua 从公开 GameState 查询到叙述，包含正常竞赛、紧急事件、可空发起方、禁止单方向、全部禁投和未知条目。
- 执行完整混合计划，验证每条讨论票的原生参数、正负票数、费用及顺序，以及一次提交和继续；覆盖仅提案 STAGE2。
- 缺项、重复、未知组合标识、非法方向、过期阶段、费用缺失／异常、预算边界均在零原生提交前验证。
- 丢响应、原生异常、重复调用与事件重入保持无重放；已有空阶段和禁投回归继续通过。
- 全量离线、编译、diff 与独立 Standards／Spec 审查后，原地图第 167 回合竞赛现场实测完整查询与显式投票，并继续终局续测。

## Out of Scope

自动选择投票、议会 UI 通用自动化、改写游戏规则、强制胜负、改造生命周期或所有动作、网络资料抓取、push。
