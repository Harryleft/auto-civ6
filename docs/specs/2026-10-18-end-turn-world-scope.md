# 结束回合的世界身份绑定

## Problem Statement

已有推进请求仅保存起始回合，确认时依赖另一次普通身份查询使来源失效。用户在 MCP 外换世界后直接调用阶段查询或结束回合，新世界更大的回合数可能被当作旧推进成功，错误清除未决门禁。离线已复现：旧世界 seed=1、起始 T50，换到 seed=2、T51，未调用身份刷新便返回 T50→51 并解除门禁。

## Solution

由推进请求自身持有提交时的世界身份，每次确认直接读取并核对当前原生身份。回合增长或终局只有与原请求身份一致才可确认；身份不匹配或未知均保留未决，不依赖用户先调用其他查询。只离线验证，完成后合入 main，不 push。

## User Stories

1. 作为游戏 Agent，我希望每次新推进绑定文明、地图种子和本地玩家，以免不同世界或玩家的状态被混用。
2. 作为游戏 Agent，我希望确认旧请求时直接核对原生身份，以免遗漏普通身份刷新造成错误成功。
3. 作为用户，我希望换世界后即使回合更大且玩家已就绪，旧请求仍保持未知和未决门禁。
4. 作为用户，我希望新世界已终局时也不能将其胜负用于终结旧推进。
5. 作为游戏 Agent，我希望文明、种子或本地玩家任一改变都能使旧请求来源失效。
6. 作为用户，我希望曾观察到身份不匹配后，即使读数又回到旧值也不能自动解除来源失效。
7. 作为游戏 Agent，我希望身份缺失、格式错误或读取失败时保留未知，而不是补绑到当前世界。
8. 作为游戏 Agent，我希望暂时读不到身份后，同一世界证据恢复时仍能继续确认原请求，且不重发。
9. 作为用户，我希望原生身份和回合事实来自一致的观测；跨上下文或提交前换世界不能生成混合成功证据。
10. 作为游戏 Agent，我希望请求提交前的最终原生检查也核对世界身份，身份改变时零提交。
11. 作为用户，我希望只读阶段查询说明原请求身份是否匹配，但不确认、退役或重发请求。
12. 作为用户，我希望已有未决但缺少原身份时保持未知，不能使用新世界首个读数追认原请求。
13. 作为游戏 Agent，我希望同世界的慢 AI、外交暂停和丢回应仍只确认原提交，并保留累计等待和原始快照。
14. 作为用户，我希望保存和依赖动作在旧推进未决时继续被阻止，普通身份刷新不能替代受保护恢复。
15. 作为用户，我希望明确且完整确认的会话替换仍可退役旧请求，新会话能建立自己的身份绑定。
16. 作为用户，我希望所有现有存档和 T101 验收结果保持原样，修复以相关离线回归验证，不启动游戏或全量测试。

## Implementation Decisions

- 推进所有权继续集中在 TurnProgress，绑定请求的原生文明、种子和本地玩家；不把回合号、缓存身份或展示文本当作世界身份。
- 新请求在确认身份可用后才建立绑定；既有未决缺少绑定时不追认。已有原生提交的观测与普通新提交使用同样的身份约束。
- 确认循环及成功退役前核对身份；终局证据也须属于原请求世界。观测到不匹配锁存来源失效；未知读取保留未知，不能确认也不能清门，但与已证实换世界分别处理。
- 原生身份与相关回合／终局事实须形成一致见证，必要时在同一 Lua 执行块加范围保护。结束动作最终复核身份与起始回合，确认未进入原生操作时才允许零提交退回。
- 阶段查询复用相同解释，保留原始请求、差分基线与等待计时；普通查询仅更新观测和来源失效事实，不替换原身份或自动恢复。
- 沿用原有 GameState、MCP、受保护会话替换及单次提交接口；不建立新的全局世界服务、持久化层或游戏控制实现。

## Testing Decisions

- 沿用已获确认的公开 GameState／MCP、FakeConn、Lua 5.1 原生边界和临时文件；不增加新的测试 seam，不连接游戏。
- 先通过公开结束回合发出旧世界请求，模拟未确认，再改变原生身份；不调用普通身份刷新。断言返回未知、门禁保持、请求数不增，不能只断言提示文本。
- 逐项红绿覆盖更大／相同回合、已终局的新世界、文明／种子／玩家变化、身份暂缺及恢复、身份恢复旧值后的锁存、提交与观察竞态、无原绑定的未决请求。
- 覆盖同世界正常增长、慢 AI、丢回应、外交／信息暂停、只读查询、保存／依赖门禁及受保护替换后的新请求。复用已有领域与生命周期回归，不复制另一套状态机。
- 只跑本次直接相关的推进、状态、原生结束检查和受影响的加载／MCP 门禁测试，记录精确版本、红绿结果及源指纹；独立合入后复用验证，不重复全量。

## Out of Scope

实机测试、推进 T101 后续回合、修改或覆盖旧存档／验收、push、自动重发或恢复、按等待时长清门、外交和移动策略调整、全面世界身份系统重构。
