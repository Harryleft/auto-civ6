# 单位 CLI 操作补齐

命名领域子命令从 76 增至 101，单位命令从 14 增至 39。新增 20 个已有动作的命名别名，以及编队查询、护卫编队连接／解除、军团／集团军合并 5 个入口。保留通用 `unit action`，已有操作继续沿用原 Runtime；不新增后台控制器或直接修改游戏规则。

## 能力对照

| 操作 | 原状态 | 本次结果 |
| --- | --- | --- |
| 移动、攻击、驻扎、治疗、兵种升级、晋升、跳过 | 已有命名 CLI 与确认逻辑 | 保留并定向回归 |
| 删除、警戒、休眠、取消移动、掠夺、建城 | 已有底层动作，需通用 action | 独立命名 CLI，均支持 `--dry-run` |
| 修复、移除改良／地貌、修路、自动探索 | 已有底层动作 | 独立命名 CLI |
| 伟人激活、皇家学会贡献、宗教／商人动作 | 已有底层动作 | 独立命名 CLI；带目标的动作显式传坐标 |
| 护卫编队 | 缺完整查询及操作链路 | `unit formations ID`、`unit link ID TARGET_ID`、`unit unlink ID` |
| 军团／舰队、集团军／无敌舰队合并 | 缺完整查询及操作链路 | `unit corps ID TARGET_ID`、`unit army ID TARGET_ID` |

`heal` 表示驻扎直至恢复；`alert` 表示敌人进入视野时自动唤醒；`delete` 永久解散单位。护卫编队保留参与单位并联动移动；军事合并会消耗一个单位。兵种升级与军事编制合并分别调用 UPGRADE 和 FORM_CORPS／FORM_ARMY，不能用经验等级相同代替原生资格检查。

## 原生依据和边界

依据本机游戏 Lua 源码，不操作原生 UI：

- `Base/Assets/UI/Panels/UnitPanel.lua`：ENTER_FORMATION 通过 CanStartCommand 的 UNITS 结果枚举对象，参数使用 PARAM_UNIT_PLAYER／PARAM_UNIT_ID。
- `Base/Assets/UI/WorldInput.lua`：FORM_CORPS／FORM_ARMY 使用 GetCommandTargets 枚举对象，通过带目标参数的 CanStartCommand 后 RequestCommand。
- `Base/Assets/UI/UnitFlagManager.lua`：UnitEnterFormation／UnitExitFormation 的双方玩家与完整单位 ID；UnitFormCorps／UnitFormArmy 的存活单位；GetMilitaryFormation 对应 CORPS_FORMATION／ARMY_FORMATION。

`lua/unit_formations.py` 只发原生命令，不调用 setter、不自行移除单位、不代替引擎检查科技／市政。查询限定本方单位，返回完整 ID、坐标、单位类型索引、军事编制、护卫编队单位数、四项动作资格及候选。底层资格或候选接口缺失时返回 partial／null，不能解释为没有可用目标。查询不确认或退役已有请求。

`GameState.change_unit_formation` 复用 ActionLifecycle：完整意图绑定发起单位、动作、目标、世界、玩家和回合。任何未决编队请求阻止对双方及其他实体的新变更。请求只提交一次；相同参数重入只确认原请求；丢回应、取消、原生调用异常或明确返回 false 均保留未决状态。前置拒绝须能证明零提交。

成功确认要求原命令开始见证及实际结果同时成立：护卫连接核对精确双方事件、编队数量及同地块；解除核对本单位退出事件及编队数不再大于 1；军事合并核对精确参与者的移除事件、原生编制事件、一个单位消失且另一个达到目标编制。两方完整 ID 任意一方可能存活，回执报告实际存活 ID。全新第三个替代 ID、缺失事件或不完整结果保持 unknown，不凭单位数减少推测合并成功。监听器只在显式提交路径安装，不形成后台轮询服务。
