# 终局续测：移动目标资格预检查

标签 ready-for-agent；本地 Markdown tracker；基点 `f5ca707`，沿用 `codex/architecture-deepening`。

## Problem Statement

第 207 回合侦察兵从 (23,22) 移往加拿大城市 (23,20)，没有移动，也没有原生完成事件。工具只检查泛化移动资格便提交请求，随后持续未知并阻止后续动作。当前外交回读已是研究同盟，诊断却仅因目标属于外国就声称缺少开放边界，不能解释真实拒绝原因。

## Solution

按本机官方界面的目标资格检查，在提交前使用最终目标和操作参数验证 MOVE_TO。原生拒绝时明确零提交，不留下未决请求；不能核实时保守拒绝。只有已确认处于战争关系的目标单位才触发攻击修饰。提交后的未知仍须保留，不能用没移动或后来无路径猜测失败。

## User Stories

1. 作为玩家，我希望不可进入的目标在提交前被拒绝，以便不锁住整局操作。
2. 作为玩家，我希望目标资格采用最终坐标，以便泛化移动能力不被当作目标可达。
3. 作为玩家，我希望同盟和中立单位不被当作敌军，以便不意外添加攻击意图。
4. 作为玩家，我希望敌方平民捕获保留攻击修饰，以便合法捕获继续可用。
5. 作为玩家，我希望友军堆叠和无移动力仍明确拒绝，以便保留已有约束。
6. 作为玩家，我希望合法的邻格与远距离移动继续工作，以便不缩减正常玩法。
7. 作为玩家，我希望资格读取异常明确零提交，以便不会留下可避免的未知请求。
8. 作为玩家，我希望外交诊断只报告已核实事实，以便不会把外国领土直接等同于缺少开放边界。
9. 作为维护者，我希望每次合法调用最多提交一次，以便确认过程不重放移动。
10. 作为维护者，我希望旧未知请求保持门禁，以便修复不能伪造过去的失败结果。
11. 作为测试者，我希望真实 Lua 与公开 GameState 检验请求计数和回执，以便不复制实现逻辑。
12. 作为玩家，我希望保留当前现场与全部存档，并从本轮检查点恢复到原生终局，以便修复不丢失已有成果。

## Implementation Decisions

- 复用移动 Lua 构造与 ActionLifecycle；不增加后台服务、目标规则副本或通用路径状态机。
- 保留现有无移动力、泛化能力与己方堆叠检查；最终 XY 与攻击修饰准备完成后，再依据本机官方调用方式检查目标级 CanStartOperation。资格 false、缺失或异常均在见证注册和 RequestOperation 之前返回明确未提交。
- 对非己方目标单位先核实本方与其所有者的原生战争关系；非战争目标不加 ATTACK。关系读取失败不猜测敌军、不提交可能带攻击意图的移动。
- 诊断不再把 foreign && !war 直接解释为缺少开放边界；没有权威通行资格时只报告外国领土及可能的路径约束。
- 不依据旧请求的当前位置、空路径、当前目标资格或新代码推断旧请求已失败；现有完成见证、对局身份及未决门禁保持不变。
- 本次已未知请求保留证据。菜单恢复被门禁拒绝后，使用已确认的第 204 回合检查点显式故障恢复，重放 3 次增长单独计入诊断，不计净推进。

## Testing Decisions

沿用已确认的公开 GameState／FakeConn、真实 Lua 5.1、内存见证及临时目录；离线不连接游戏。

- 泛化允许而目标拒绝：零 RequestOperation、零事件注册，随后其他合法动作不受未决锁阻挡。
- 合法目标使用同一最终参数验证和提交；邻格、长距离及现有分段完成行为保持兼容，一次调用最多一次提交。
- 己方、盟友、中立与实际战争目标的修饰分支；读取异常零提交，敌方平民捕获保留。
- 目标检查异常／缺失和已有无移动力、堆叠拒绝；诊断不把同盟领土声称为缺少开放边界。
- 已提交但无完成见证仍为未知，不能因没移动或无路径解除门禁。
- 全量离线、编译、diff 和独立双轴审查后，实机验证目标拒绝不锁存、合法移动以及原对局继续推进。

## Out of Scope

自动规划路线、绕过外交边界、自动宣战、通用移动完成协议重构、追认旧请求失败、删除存档、push。
