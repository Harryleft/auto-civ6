# 世界知识只读 MCP 查询

标签 ready-for-agent；本地 Markdown tracker；基点 `5a1037b`，集成分支沿用 `codex/architecture-deepening`。

## Problem Statement

规则资料已独立整理为九主题，但只能由具备文件／终端权限的 Agent 按路径运行脚本查询。仅持有 Civ6 MCP 工具的模型无法调用，AGENTS 的链接又容易被误解为自动加载。默认摘要主要是 ID 与名称，用户不清楚何时展开规则或证据，也不清楚静态规则与本局资格的区别。

## Solution

向现有 MCP 服务提供两个只读工具：搜索规则，以及按摘要、规则、证据逐层读取。复用当前本机知识和查询解释，工具说明与 Agent 流程明确触发条件。客户端无需文件权限；无游戏连接和未决操作时仍可查静态规则。文档集中保留一份调用说明，实机与 push 均不执行。

## User Stories

1. 作为 Agent，我希望只凭 MCP 就能搜索本地世界知识，以便不依赖终端权限。
2. 作为 Agent，我希望按中文、英文名称或内部 ID 搜索，以便定位实体与机制。
3. 作为 Agent，我希望按九主题筛选并限制结果数，以便只展开相关资料。
4. 作为 Agent，我希望结果包含 ID、名称、主题及截断标记，以便继续定点读取。
5. 作为 Agent，我希望先读摘要，再按需读规则和来源，以便控制上下文。
6. 作为 Agent，我希望规则层提供前置、解锁、条件和关联，以便做扩张与胜利路线判断。
7. 作为 Agent，我希望证据层保留真实来源定位，以便核对冲突与不确定规则。
8. 作为 Agent，我希望缺失记录与来源损坏明确报错，以便不把未命中当成不存在。
9. 作为玩家，我希望每次回复说明版本快照与适用边界，以便静态资料不被当成本局已验证资格。
10. 作为玩家，我希望游戏没启动时也可查询，以便规则查阅无需加载存档。
11. 作为玩家，我希望未决动作、保存或换档期间查知识不改变门禁，以便不会误清未知结果。
12. 作为维护者，我希望 CLI 与 MCP 共用知识解释，以便维护一套规则。
13. 作为维护者，我希望目录只由服务器配置决定，以便客户端不能任意读取文件或执行命令。
14. 作为维护者，我希望知识源丢失、错误配置、超时或非 JSON 返回能明确失败，以便不自动捕获游戏资料或重建库。
15. 作为 Agent，我希望在扩张、解锁、区域、议会或胜利机制不清楚时明确调用，以便规则真正进入决策流程。
16. 作为 Agent，我希望当前费用、候选、进度和地块仍由游戏工具核对，以便不混淆资料与状态。
17. 作为玩家，我希望现有存档和验收全部保留，以便本次接入不影响前次对局。
18. 作为玩家，我希望离线完成注册、调用、失败边界与门禁验证，以便不启动实机也能审阅成果。

## Implementation Decisions

- 新增 `search_knowledge(query, topic=None, limit=5)` 与 `get_knowledge(entry_id, level="summary")`，均声明只读、幂等。搜索主题采用现有九主题 ID；limit 范围 1～20；空查询及明显无效参数拒绝。
- 搜索复用当前名称／内部 ID 的大小写不敏感包含匹配；不宣称自然语言语义或全文检索。返回 total、limit、truncated、结果摘要；零命中明确 not_found。读取支持 summary、rule、evidence；未知 ID 明确报错。summary 为身份与概览，实际规则判断显式请求 rule，冲突或来源问题才展开 evidence。
- 返回 UTF-8 JSON 文本，附版本 profile／快照标识与静态适用边界；不声称当前会话、活动模组或操作资格已验证。复用原始来源引用与关联，不新增模型推理、规则求值或自动规划。
- 保持独立知识目录与标准库 CLI 可直接使用。MCP 为薄适配，调用既有查询入口，不复制构建或规则解释。若以子进程复用，使用固定 Python／脚本路径与参数数组、无 shell、禁写字节码和有限超时；错误不得转成成功摘要。
- 默认从源码仓库定位知识目录；允许服务器环境变量 `CIV6_KNOWLEDGE_DIR` 指定独立资料目录。工具参数不接受任意 root、文件或脚本路径。非源码安装没有资料时明确提示配置目录，不暗中按当前工作目录选库、下载或重建。
- 查询不实例化额外游戏控制、不调用 GameState／FireTuner、不读写检查点、存档或未决状态。沿用现有整体串行和工具日志；只对两个明确离线工具放行未决查询，不扩大其他动作权限，不确认或清除旧动作。
- MCP 服务总说明、工具自身说明与 AGENTS 路由共同明确：规则／前置／解锁／机制不清楚时 search 定位、get(rule) 判断，来源冲突才 get(evidence)，随后用对应游戏查询核对本局资格。已明确且足够的规则不要求每回合重查，不新增反思或硬门禁。
- 简化 Agent 决策、知识入口及必要安装说明；调用契约集中一处，其他文档仅给触发条件和链接。CLI 是备用／维护入口，构建更新与普通查询分开。
- 文档变化按既有构建流程同步支持文件指纹；保留全部规则和 sources 原始字节。不运行采集、不修改本机规则数据、不引入新依赖。

## Testing Decisions

沿用此前确认的 MCP 公共工具／内存协议、GameState／FakeConn 与临时知识目录／CLI 边界；不连接游戏，不为文案复述编写测试。

- MCP 注册及输入 schema：两个只读工具可发现，参数、主题、级别、结果数量约束明确；实际内存 ClientSession 搜索再按结果 ID 逐层读取。
- 公开入口验证中英名称、ID、筛选、数量／截断、零命中、未知 ID、无效参数、来源引用与版本边界；与现有 CLI 同源语义一致。
- 未启动或不可访问的游戏，未决 action/save/load/end_turn：工具照常查询，零 FireTuner／GameState 调用，未决不变，原动作仍受既有门禁。
- 固定目录、显式环境配置、错误目录、不同 cwd、损坏 JSON／指纹／来源缺失、超时与坏返回；不执行 shell、不任意读路径、不自动采集、重建或重试。
- 临时目录验证知识文件／来源与存档未写入；正常本地工具日志仍沿用现有机制。知识正式目录 validate、文档链接／工具名与单一调用说明核对。
- 全量离线、编译、diff 与独立 Standards／Spec 双轴审查；修复发现后关闭本地工作项。实机对局与真实 FireTuner 均不属于本次验证。

## Out of Scope

语义向量检索、联网抓取、自动同步、规则引擎、全库上下文注入、自动替模型决策、运行时强制查知识门禁、活动模组推断、实机对局、删除旧成果、合并 main、push。
