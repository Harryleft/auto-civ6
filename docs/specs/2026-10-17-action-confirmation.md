# Civ6 动作确认与恢复时序修复规格

日期：2026-10-17。依据：原始基准 20 个净回合验收，以及 `96e23af` → `6743bd1` 的代码审查和相关既有调用链复查。

状态：已实施并通过离线检查与独立审查，实机验收中。当前代码验收起点为 `a673f62`，571 项测试通过；完整状态见 [第二轮验收记录](../acceptance/2026-10-17-confirmation.md)。未发布到 issue tracker。

## Problem Statement（问题）

用户希望模型通过本机 MCP 连续推进 Civilization VI，在正常阻塞时继续决策，在通信异常时准确判断结果，并在必要时恢复同一对局。当前工具的串行执行只能保证请求顺序，不能保证游戏引擎已经完成异步动作。

本次实机从 `benchmark_turn_1` 第 1 回合推进至第 21 回合，共 20 个净回合。计数期间没有游戏重启或读档回退，但经过两处接口兼容修复和 MCP 服务重启。最终检查点通过一次显式重启恢复，文明、种子、回合、城市和单位回读一致。这证明本次对局可以完成，不证明所有异步路径都能稳定自动处理。

已经修复、需要保留回归验证的事项：没有胜利方时 `Game.GetWinningTeam()` 返回 nil；macOS GameCore 未实现生产耗时 API；主菜单尚未出现就尝试加载；手工构造的读档描述符缺少原生条目元数据。

同格冲突、需要选择市政、外交应答属于正常游戏约束。用户买不到的内容导致旧地图无法加载属于基准和授权问题，均不得误标为通信时序故障。

## Solution（方案）

统一采用「提交一次 → 有界只读确认 → 已确认／明确拒绝／结果未知」的动作契约。只有可验证的状态变化才能支持成功结论；一次旧状态、丢失回应或固定等待结束都不构成动作失败或完成的证明。

结果未知时，工具保留事实和可继续查询的依据，停止依赖该结果的后续写操作，并指向现有查询或显式恢复入口。重新连接用于读取状态，不透明重放动作。模型继续负责游戏策略，Runtime 负责如实提交、确认和报告。

完成标准是：下述离线故障场景通过，并从唯一原始基准重新完成 20 个净回合及最终检查点恢复。旧验收成绩不能代替修复后的新验收。

## Implementation Decisions（实施决策）

### 1. 保持现有职责边界

- 保留 MCP → GameState → Lua → FireTuner → Civ6 调用链。修改集中在已有动作验证、Lua 构造、回合推进和生命周期模块。
- MCP 入口继续整体串行执行。串行锁不作为游戏完成信号，连接锁也不替代动作结果确认。
- 优先在 GameState 内复用小范围的有界确认逻辑，各动作定义自己的完成条件。不建设通用任务平台、持久化操作账本或新的后台服务。
- 保留现有 MCP 工具名称与参数。已确认时可保留原有成功前缀；未知情况使用现有 OUTCOME_UNKNOWN 语义，并给出核对对象、已观察状态和下一步。

### 2. 统一结果与等待规则

| 结果 | 所需证据 | 后续行为 |
| --- | --- | --- |
| 已确认 | 目标状态真实出现，且属于当前对局、目标实体和动作 | 允许依赖此结果的后续动作 |
| 明确拒绝 | 引擎明确拒绝，或可靠前置条件证明未提交 | 返回原因，由模型重新决策 |
| 结果未知 | 请求可能已执行，但回读丢失、状态尚未变化、证据不足或确认超时 | 只读核对；不自动重发，不冒充成功或失败 |

- 使用单调时钟和总截止时间；查询耗时也计入预算。查询之间允许短暂退让，禁止忙等、无限重连和无限延长预算。
- 不把固定 sleep、两次往返或连续相同的旧状态单独当作完成证据。轮询必须检查与动作相关的事实。
- 保留未确认动作的必要依据。至少能识别对局、目标实体、动作和提交前状态；精确字段按现有类型选择，不建立额外的全局协议。
- 未知状态不能因一次重连而自动清除。涉及同一实体的依赖动作，以及保存检查点和推进回合，应先确认结果；只读核对及为解决阻塞所必需的操作仍可进行。
- MCP 服务重新启动会丢失内存状态；重新连接后的状态读取不能被宣称为恢复了旧请求的提交记录。无法从游戏事实确认时，继续报告未知并使用显式恢复。

### 3. 动作完成条件

| 动作 | 完成证据与处理要求 |
| --- | --- |
| 转产 | 目标城市的当前生产项目匹配请求；读到旧队列时继续有界确认。回读断线或超时返回未知，不建议盲目重试或通过购买掩盖未确认结果。保持 macOS 已验证可用的队列 API。 |
| 建城 | 请求位置出现归属正确的城市；必要时核对开拓者状态。删除「一次查不到城市便重发」路径。提交后的 NO_CITY_HERE 只能证明本次观察尚未看到城市。 |
| 移动 | 核对实际位置、剩余行动力，以及平台能可靠读取的执行状态。到达目标可确认；中途位置需有停步依据才说明原因。原地旧位置不能直接判受阻，未核对行动力不能写「耗尽」。 |
| 攻击 | 预估与提交使用一致的攻击方式判断，不能将相邻远程单位默认视为近战。结合目标身份、攻击者行动状态与真实生命值确认结果；未确认时只报告已提交、观察值及估算。 |
| 击杀判断 | 需要目标消灭或相应战斗结果的可靠证据。空回应、不可见、目标格暂时没有单位，都不能单独证明击杀。 |

不要求每个动作必须改变所有观察字段。相同队列、零伤害、部分移动等情况应按引擎事实解释，不能为了满足确认逻辑伪造变化。

### 4. 回合推进与外交

- 保留 end_turn 单次提交和 pending 确认机制。处理外交后再次调用只确认已有推进，不再发送 ACTION_ENDTURN。
- 依赖动作结果未知时，不提交新的回合推进。返回具体待核对对象，避免只有「连接失败」而无处理方向。
- 将「回合数字变化」与「本地玩家已可继续操作」分别验证；这是本次强化验收要求，不是已经复现的缺陷。不得在引擎仍处理时宣告可安全提交下一批动作。
- 外交属于正常阻塞，不记作技术恢复。先核实 AI 处理阶段可安全查询的信号，再改善当前约 45 秒才探测的延迟；不得靠高频切换 InGame UI 干扰引擎。
- 外交探测应可在有界窗口内继续进行，避免首次探测无会话便永久忽略后来出现的会话。探测不代替模型应答，也不增加自动结束回合的路径。
- 暂不设新的秒级性能承诺；实施时记录信号可用时间、探测耗时和阻塞返回耗时，依据实机证据选择间隔。

### 5. 保存完成与恢复资格

- 保存请求仍只发送一次，使用独立名称，不覆盖原始基准。保存前确认没有未决的依赖动作或回合推进，保存后核对文明、种子和回合。
- 新鲜、非空、短暂稳定的文件只能证明观察到了文件，不能单独升级为可恢复检查点。
- 实施时优先核实原生保存完成信号或可靠完整性验证。现有逆向格式研究只作线索，不能未经验证就当作所有存档的完整性标准。
- 若无法取得足够完成证据，工具必须保留「文件已出现，完成未确认」的未知结果，不允许仅增加静止时长后承诺可恢复。
- 显式恢复不选择仍在写入或完成未知的检查点。没有符合回退范围的已确认检查点时停止，并报告原因。
- 文件完成性、身份匹配和成功加载是不同证据。最终验收仍须实际加载命名检查点，不能以文件检查替代恢复验证。

### 6. 启动与加载确认

- 显式恢复统一检查重新启动条件，覆盖主动关闭、游戏刚崩溃和游戏已长期退出。不能只在主动杀进程分支等待 Steam 释放。
- 检查必须有总截止时间。无法可靠取得 Steam 就绪信号时，不将固定等待视为保证；记录适用的保守退让和失败结果，不反复提交启动来探测是否就绪。
- 保留主菜单就绪发现和精确原生存档条目加载。未发现 MainMenu、同名歧义或条目缺失时不发送读档。
- 每次恢复固定目标检查点及其预期文明、种子、回合。沿用已有名称接口时，预期值可取自与该名称及文件指纹绑定的已确认记录或可靠原生元数据；仅有名称、无法确认预期值时，不返回「已验证恢复」。
- 加载后必须比较预期与实际值，并确认可操作状态。回合必须有效；错误文明、错误种子、错误回合或旧会话不得返回 Loaded 成功结论。
- 未知加载结果只通过读取确认，不重发加载。确认目标前不放行依赖新会话的玩法操作。

### 7. 实施顺序

1. 先修 F1～F4 的动作结果判定，补齐单次提交和延迟回读回归测试。
2. 修 F5～F7 的检查点完成与恢复验证，覆盖主动关闭和崩溃边界。
3. 在安全查询信号明确后处理 F8 的外交提示延迟，保留现有推进单次提交行为。
4. 执行全套离线检查，再从唯一原始基准完成新的实机验收；分别记录各阶段结果。

## Testing Decisions（测试决策）

主要测试边界沿用 GameState 与可脚本化 FakeConn：调用公开动作方法，控制游戏观察序列，检查返回语义和实际提交次数。MCP 入口只补必要契约检查；保存使用隔离临时目录和可控制写入，启动使用进程／Steam 状态替身。沿用现有测试边界，不增加第二套游戏控制实现。

好测试验证对外行为与安全约束，不固定内部 helper 名称、循环次数或真实机器耗时。所有离线测试不得连接游戏、修改真实存档或读取生产数据；时间推进应可控。

### 离线验收矩阵

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| A01 | 转产连续读到旧队列，随后目标队列出现 | 最终确认目标项目；转产只提交一次，无中途伪失败 |
| A02 | 转产已提交，确认读取断线或直到截止仍未确认 | 返回未知；不返回正常生产成功，不建议重发或花钱购买 |
| A03 | 建城第一次观察无城市，稍后出现己方城市 | 返回已确认，建城提交恰好一次 |
| A04 | 建城直到截止仍无城市，或城市归属不符 | 不重发、不宣告完成；返回未知并提示核对 |
| A05 | 移动依次读到起点、中途、目标 | 不提前判受阻或耗尽，最终确认目标；提交一次 |
| A06 | 移动确实停在途中，或确实无法通行 | 仅在有相应证据时返回停步及原因；未核对行动力不报告耗尽 |
| A07 | 移动提交后回读失败或超时 | 返回未知，依赖该位置的后续写动作不被提交 |
| A08 | 邻接投石兵、远距离远程单位和近战单位攻击 | 预估分类与实际提交方式一致；无需真实伤害精确等于估算 |
| A09 | 战后先返回旧生命值，随后返回新生命值 | 最终报告真实观察；中间估算不标为实际伤害 |
| A10 | 战后空回应、目标不可见或离开原格 | 不虚报击杀；保留未确认边界 |
| A11 | 动作未决时请求 end_turn 或保存 | 不越过未决结果；仍允许核对及必要阻塞处理 |
| A12 | end_turn 遇到外交，处理后继续确认 | ACTION_ENDTURN 总计一次；外交回应由调用者决定 |
| A13 | 外交首次探测后才出现，或回合计数先于可操作状态变化 | 有界发现阻塞；不重复推进，不过早放行新动作 |
