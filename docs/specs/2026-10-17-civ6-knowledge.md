# 本机版本 Civ6 世界知识规格

标签：ready-for-agent。Tracker：本地 Markdown。固定基点：4c16f8f。集成分支沿用当前 codex/architecture-deepening；不切换 main、不 push。用户指定独立目录 `civ6_knowledge`。

## Problem Statement

现有手册以人类顺序阅读为主，AI 难以快速定位条件、例外与相互依赖；模型知识可能混用原版、扩展与补丁。当前工具能查询真实状态，但不应承担整套静态世界知识。需要与本机版本绑定、独立存在、可追溯且按需读取的资料。

## Solution

建立本机版本的离线文件知识库，首批覆盖市政、科技解锁、区域建设和世界议会。入口提供主题路由；主题提供机制概览、查询触发和缺口；规则卡提供实体条件、关联与例外；证据层保存从本机规则与文本数据库提取的原始记录及必要原生脚本片段。提供仅访问该目录的构建、检索和完整性验证命令。复制整个目录即可查阅，不依赖游戏进程或 MCP。

## User Stories

1. 作为模型，我希望先看到短目录，以便按当前任务选择主题。
2. 作为模型，我希望读取主题概览，以便识别跨领域影响。
3. 作为模型，我希望按中文、英文或游戏内部 ID 查找，以便匹配查询输出。
4. 作为模型，我希望查看一个市政的前置与解锁，以便规划文化路线。
5. 作为模型，我希望查看科技的前置、尤里卡与解锁，以便比较研究路线。
6. 作为模型，我希望区分直接解锁与条件性内容，以便不把科技完成当作全部合法条件。
7. 作为模型，我希望查看区域的地形限制、人口条件和相邻加成定义，以便读取必要的本局事实。
8. 作为模型，我希望理解议会阶段、决议、提案和禁投资格，以便显式选择并核对工具结果。
9. 作为模型，我希望未知资格保留未知，以便不把缺少资料当作没有选择。
10. 作为模型，我希望按摘要、完整卡、原始证据逐级展开，以便控制上下文。
11. 作为模型，我希望沿前置和解锁关系定位其他条目，以便保持跨主题规划能力。
12. 作为使用者，我希望看到覆盖数、未覆盖机制和外部关联，以便判断答案边界。
13. 作为使用者，我希望看到包版本、Steam Build、内部版本及来源指纹，以便发现不兼容资料。
14. 作为使用者，我希望缓存来源与本局启用内容未验证时有明确标识，以便避免冒充当前游戏事实。
15. 作为开发者，我希望从受控本机输入重建资料，以便更新时可复现。
16. 作为开发者，我希望全部离线验证，以便不启动游戏、不覆盖存档。
17. 作为使用者，我希望目录可独立复制，以便脱离当前项目查阅。
18. 作为使用者，我希望后续知识有明确优先级，以便按决策收益扩展。

## Implementation Decisions

- 知识与游戏控制运行时独立；本期不添加 MCP 工具、数据库服务、向量检索或依赖包。命令使用 Python 标准库。
- 简单目录划分：主题说明、规则卡、来源证据；根入口与版本清单负责路由。结构化事实由来源快照生成，主题指南只解释机制与使用边界，不复制数值清单。
- 本机内部版本为 1.0.12.54 (951533)，macOS 包 1.4.6／376653.178，Steam Build 15296837；目标规则集为项目唯一基准记录的 RULESET_EXPANSION_2。再次采集时以实际输入为准。
- 采集只读访问本机数据库和文件，并绑定 SHA-256。游戏生成的数据库视为最后生成的规则快照；本期不声称已经识别当前加载存档、活动模组或模式。配置日志中的 enabled 列表不等同于本局活动内容。
- 来源快照公开契约为 schema_version、profile、tables、localization、code_evidence。tables 保存按表名组织的原始行；localization 将 LOC 标识映射到本机简体中文和英语；脚本证据记录相对路径、行范围、全文指纹及片段。资料中不带个人账号信息。
- profile 记录来源版本、目标规则集、来源文件指纹、采集范围、当前对局匹配未验证、模组与模式匹配未验证；知识匹配不等于动作合法性。
- 首批实体卡覆盖快照中全部市政、科技、区域、决议、提案类型和禁投定义。解锁含快照中直接科技／市政前置的单位、建筑、区域、改良、项目、政策、政体、资源及路线；保留文明专属等原始限制，明确这不是完整引擎合法性判定。
- 前置、解锁与相邻加成关联采用明确类型和稳定 ID。未作为独立规则卡覆盖的关联保留原始来源并标注外部覆盖，不伪造完整条目。
- 基础成本与本局实际成本分开，尤里卡原始值不直接换算成最终比例；人口、落位、目标资格、有效费用、随机树等依赖当前游戏查询。
- 分层命令默认仅返回摘要；显式请求完整卡或证据时才返回该项内容。搜索限量、稳定排序并返回总匹配数；未命中明确报告，禁止截断为貌似完整答案。版本比较不匹配时明确拒绝兼容结论。
- 本地完整性验证覆盖规则数量、来源引用、关联、指纹和版本。构建相同输入结果确定，不依赖本机路径或生成时间；知识目录复制后仍可检索验证。
- 原有协作入口仅增加一个明确的规则查询指针；主题指出该读哪些现有工具，避免知识库取代真实状态读取。

## Testing Decisions

用户已确认：通过知识目录公开文件／命令入口测试，使用临时 SQLite 和临时目录验证采集、构建、分层查询、版本不匹配、来源与关联完整性，不连接游戏。

- 测试外部行为；使用独立可计算的最小规则样本，先失败再实现，不匹配源码字符串。
- 覆盖输入不全／不可读、语言回退、前置与跨主题解锁、区域相邻定义、全部禁投与单向禁投原始事实、缺失引用、未知条目和显式覆盖缺口。
- 验证摘要不携带原始大段证据、规则保留条件和限制、证据能定位原始行、搜索确定且有分页／截断说明。
- 使用本机只读输入生成正式资料；离线抽查写作→学院、法典→政策、工业区相邻和议会禁投。
- 完成锁定依赖同步、全量 pytest、compileall、Markdown 本地链接与锚点检查、资料完整性验证及 diff 检查；旧代码／存档／历史验收哈希保持。
- 资料质量与检索行为为本轮验收；不声明策略收益、游戏合法性或新的实机回合验收。

## Out of Scope

游戏控制代码修改、自动决策或默认投票、游戏启动与读档、任何存档写入、联网下载全量手册、提取游戏隐藏状态、完整规则引擎、全量 Modifier 解释器、规则树随机化重建、胜率或性能收益承诺、远程发布。
