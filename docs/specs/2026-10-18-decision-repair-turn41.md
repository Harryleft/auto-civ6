# 决策查询与调度修复：第 21～41 回合

标签 ready-for-agent；本地 Markdown tracker；基点 `8c93525`；集成分支 `codex/decision-repair-turn41`。工作项见[依赖图](2026-10-18-decision-repair-turn41-tickets.md)。

## Problem Statement

原始基准净推进 20 回合发现四个问题：近战候选过度声称本回合可执行，攻击提交后没有确认见证、锁住推进；使团将会话提交报告为接受；本方专属改良被候选过滤；市政候选进度和剩余时间不准确。这些事实会误导模型对成本、资格和外交关系的判断。原始失败与恢复记录保留在本机 `20261018-decision-flow-net20` 验收目录。

## Solution

按攻击、外交确认、专属改良、市政进度的优先级修正现有工具。模型继续围绕稳定规则、动态事实和可修正判断决策；不引入固定文明攻略或自动胜利规划。离线完成后从同一轮第 21 回合检查点续至第 41 回合，真实验证修复、保存新结果并保留旧成果。

## User Stories

1. 作为 Agent，我希望近战候选区分当前可执行与未知，以免提交需要下一回合才执行的攻击。
2. 作为 Agent，我希望候选和提交复用同一资格解释，以免两入口矛盾。
3. 作为玩家，我希望不足移动力、原生路径延后、控制区或不能验证的路径在提交前被明确拒绝，以免锁住对局。
4. 作为玩家，我希望合法相邻攻击仍可执行，以免保守检查封死正常战斗。
5. 作为维护者，我希望远程、空军、城市攻击与可见性边界保持正确。
6. 作为玩家，我希望已提交但结果未知的攻击保留原门禁，不重发、不透明释放或自动重启。
7. 作为 Agent，我希望使团和使馆的提交与接受分开，以免错误相信关系已经改善。
8. 作为 Agent，我希望只接受本方向对手派出使团／使馆的原生见证，以免把对手来访或金币变化当作成功。
9. 作为玩家，我希望确认读取短暂失败时保留未确认，不重发外交请求。
10. 作为维护者，我希望友谊与同盟已有确认、外交对话及推进门禁不回退。
11. 作为苏美尔 Agent，我希望看到原生允许建设的金字形神塔，以便把知识查询转化为实际选择。
12. 作为玩家，我希望别家专属改良、未解锁改良及不能建设的地块继续被排除，以免静态知识越过本局资格。
13. 作为 Agent，我希望当前市政顶部与候选列表的累计进度、剩余回合一致，以便比较机会成本。
14. 作为 Agent，我希望鼓舞、溢出及已部分研究的非当前市政按实际进度读取，不用完整成本冒充剩余成本。
15. 作为 Agent，我希望缺失或失败的原生读取明确未知，不显示伪造的零进度或确定回合。
16. 作为玩家，我希望修复先经过离线行为回归与审查，再操作真实存档。
17. 作为玩家，我希望从本轮已确认第 21 回合续测，净推进 20 回合到第 41 回合，并另存检查点和结果。
18. 作为玩家，我希望继续按公开身份理解对手、根据产能与军事风险修正路线，不用回档挑选更好战略结果。

## Implementation Decisions

- 保持既有 MCP 工具名称、职责和整体串行调度；不增加游戏控制入口、缓存、后台服务或固定策略。
- 近战资格在现有 Lua 构造层共享解释，考虑原生移动路径、节点／到达回合及攻击操作条件；以本机已有路径查询先例为依据，不把静态地形成本或单纯相邻、正移动力、CanStartOperation 当作本回合执行证明。路径不可证明时拒绝当前提交并说明原因；未知不伪装为合法候选。原始 1 点移动跨河雨林场景需有对应回归，具体触发机制继续基于证据校准。
- 已提交后的原生攻击见证、未决归属、原请求确认与无重放保持；不能通过无变化、超时或普通读取直接判定失败并解除门禁。
- 使团和使馆先报告已提议，再在后续只读帧查询本地玩家指向对手的原生派出状态。接受要求对应见证；未观察到或读取失败保持 PROPOSED_UNCONFIRMED，不自动重发。金币减少或对方来访不能单独确认。已有同类状态可无提交报告已存在，不伪造本次新动作。
- 可建改良对所有 Buildable 候选调用原生资格判断，不在查询前排除带 Trait 的本方内容。原生拒绝及不可读取不被当成允许，保持只读；构建任务建议与单位候选的范围各自明确，不为补一项改良引入策略排序系统。
- 市政进度通过本机受支持的原生接口读取；统一顶部与候选事实，剩余时间扣除累计进度，并在可用时优先当前原生剩余回合。缺失 API、进度、产出或无效数值明确未知，兼容旧响应；不能将 pcall 失败静默转成 0%。
- 实机只读探测进一步确认：市政进度与当前／候选剩余 API 属于 InGame；GameCore 不提供这些接口。研究查询通过现有 InGame 纯读通道取得该组事实，不能只照搬 UI API 名称却在另一上下文执行。公开 GameState 回归须覆盖上下文能力差异，既有未知门禁和无写入保证不变。
- 策略指南只补充与本次故障直接有关的通用执行约束：处理完多轮会话后确认原推进；区分落位与建成、提议与接受；在扩张时比较护卫和援军到达时间。不给具体文明或对手写固定响应配方。
- 新服务必须加载测试过的源码；本机 MCP 只保持一个活动 FireTuner 客户端。续测优先菜单快速换档，完整重启仅限无法确认的故障恢复，使用本轮已确认检查点并记录回退量。

## Testing Decisions

沿用此前用户已确认的 GameState／FakeConn、Lua 5.1 原生 API 桩、内存 MCP 公开边界；不新增测试边界，不重复请求既有授权。按 TDD 纵向切片，先证明失败再实施；不以源码字符串断言代替核心行为。

- 攻击：查询与执行同一场景，覆盖正移动但原生路径下一回合到达、不可用／坏路径、控制区、合法当前到达、零次提交、恰好一次合法提交，以及提交未知后门禁不释放；保留已覆盖攻击类别。
- 外交：延迟派出见证后接受、只收到对方使团、无见证、读取失败、不同对象、已有状态、单次提交和友谊／同盟回归。
- 改良：本方专属与通用原生允许均出现，别家专属原生拒绝不出现；查询不产生改良请求。
- 市政：当前与非当前累计进度、鼓舞、部分成本、零文化、缺失 API、非法值及旧响应兼容；顶部与候选的数字或未知相符。
- 全量离线、compileall、diff 与独立 Standards／Spec 审查通过，保留源码树指纹。只在这些检查后进入实机。
- 实机从 `benchmark_decision_flow_20261018_net20_t21`（SHA-256 `e3f0bf11c20bfe2ac27f0bd66ac1ca7c0fd5e60375bc2311d9560c77ab912a86`）续至第 41 回合；记录能力查询、路线改变、具体修复验证、未遇到场景、阻塞／恢复与保存。不得为复现故障发出会锁住游戏的已知非法操作。
