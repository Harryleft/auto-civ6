# 间谍撤离完整身份

## Problem Statement

本轮 T148 出现原生选择撤离路线门禁。只读核对返回待撤离间谍完整 ID 2949124，而 MCP 将其截为索引 4 后比较，拒绝合法撤离。get_spies 仍将此间谍展示为任务中，未暴露可操作的撤离状态。

## Solution

保持公开 spy_action 参数，以完整原生身份核对待撤离间谍，明确选择合法路线，确认门禁解除后继续原对局。查询仅在有效撤离门禁存在时探查该原生接口，避免已知原生崩溃风险。

## User Stories

1. 玩家能从查询识别真正待撤离间谍和可选路线。
2. 玩家使用完整 ID 选择撤离，不因截断误判。
3. 不同代但相同低位索引的单位不能替代原间谍。
4. 无撤离门禁时查询不调用危险的原生待撤离接口。
5. 未知、丢回应和迟到时不透明重发撤离；实际解除门禁后才报告确认。
6. 世界变化、无归因证据的间谍缺失或路线不可用时保留拒绝或未知，不替玩家选择路线。
7. 撤离选择导致间谍立即阵亡或进入原生旅行时，玩家能区分路线选择已处理与成功逃生；旧单位不再存在不应单独造成永久门禁。

## Implementation Decisions

- 先核对本机官方 EspionageEscape 源码的 ID 与路线语义；修复公开入口至原生比较之间的完整身份传递，不改变普通任务／旅行语义。
- 复用现有查询模型展示 escaping 及合法路线；只在原生有效通知门禁内读取待撤离 ID，不进行推测式危险调用。查询保持只读。
- 复用动作确认能力，在结果未知时保留单次意图；不按旧任务字段宣称撤离完成，不盲目重发。动作核对原世界及完整实体身份。
- 不增加自动撤离策略或全局框架；具体选择由模型依据当前选项做出。
- T148 首次复验发现：选择后原单位立即消失，出现本次间谍阵亡通知，原撤离门禁解除。确认须支持有本次 token、原世界／完整原实体与新鲜精确原生终结证据的选择处理；不能仅按缺失确认，也不能继续强制旧单位仍存在。成功逃生不由选择完成推断。

## Testing Decisions

沿用已确认的 GameState／FakeConn、Lua 5.1 与公开 MCP 边界。回归涵盖真实完整 ID 2949124／低位索引 4、同索引异代身份、无门禁零危险调用、合法／非法路线、真实确认、迟到／丢回应／取消／换世界，以及选择后立即阵亡／旅行、旧通知／他人事件不能归因、无证据缺失保持未知。仅运行受影响模块；原生实机在当前 T148 续测，不做战略回档。确认修复若需恢复，只使用本轮已确认 T148 检查点复现原路线选择，保留首次阵亡证据，不为改变结果改选路线。
