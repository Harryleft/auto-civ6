# 五主题世界知识扩展规格

标签：ready-for-agent。本地 Markdown tracker；基点 `71c4f64`，沿用 `codex/architecture-deepening`。独立目录仍为 `civ6_knowledge`，不 push、不操作游戏。

## Problem Statement

现有四主题缺少城市经营、资源气候、军事、外交及胜利宗教知识。需要按已有优先级补齐，同时保持简短入口、按实体查询、条件与例外同处，以及本机版本可追溯。

## Solution

按优先级扩展经济与成长、资源电力气候、战斗移动、外交贸易、胜利与宗教五个主题。五项内容独立工作，并发槽位释放后接续其余项；共享采集、构建与查询统一集成。所有知识保存在现有三层目录，默认摘要，规则与证据显式展开。

## User Stories

1. 作为模型，我希望查人口、住房、宜居度与生产条件，以便理解城市瓶颈。
2. 作为模型，我希望查看建筑、政策和产出定义，以便比较经营选项。
3. 作为模型，我希望区分资源揭示、改良、库存与消耗，以便判断解锁后的供应约束。
4. 作为模型，我希望查电力、排放、灾害和海平面条件，以便理解长期成本。
5. 作为模型，我希望查单位、晋升、地形和地貌，以便解释移动与作战约束。
6. 作为模型，我希望查升级、编队与攻城条件，以便避免只比较基础战力。
7. 作为模型，我希望查外交行动与联盟定义，以便核对关系、研究和对象条件。
8. 作为模型，我希望理解商路与交易限制，以便区分商路产出和双边交易。
9. 作为模型，我希望查胜利定义及项目，以便理解长期目标。
10. 作为模型，我希望查宗教、信条和传播条件，以便解释宗教行动。
11. 作为模型，我希望中文、英文与内部 ID 都能找到条目，以便匹配工具输出。
12. 作为模型，我希望沿关联查已有主题，以便补全前置而不通读资料。
13. 作为模型，我希望重要条件和例外与规则一起出现，以便完整判断。
14. 作为模型，我希望缺失来源明确报出，以便不把未知当作不存在。
15. 作为使用者，我希望来源绑定本机版本及指纹，以便发现不匹配。
16. 作为使用者，我希望目录可独立复制和重建，以便脱离游戏查阅。
17. 作为开发者，我希望只读采集和离线验证，以便不影响存档与验收成果。
18. 作为使用者，我希望五个主题并行推进且避免共享文件冲突，以便缩短交付时间。

## Implementation Decisions

- 保留主题、规则、来源三层。主题页约 20～40 行，只写主题特有机制、例外及动态查询入口；公共版本边界和命令只在总入口说明，不链接大型 JSON 供默认通读。
- 复核本机内部版本、包版本与 Steam Build；当前可见内部版本仍为 1.0.12.54 (951533)。目标规则集为 RULESET_EXPANSION_2。缓存、当前存档、活动模组／模式仍分开，离线采集不声称当前会话已匹配。
- 复用临时 SQLite 副本含 WAL、来源变化检查、真实启动时间解析及指纹；保留旧输出的失败语义。
- 扩展本机静态规则表与关联文本，采集必要的效果、参数和需求定义作为原始证据，不求值完整 Modifier 或执行原生脚本。
- 实体卡采用原始稳定 ID：经营覆盖产出／建筑／政策，资源覆盖资源／灾害，军事覆盖单位／晋升／地形／地貌，外交覆盖行动／联盟，胜利宗教覆盖胜利／宗教／信条。项目仍作为关联证据，不复制到多个主题。
- 各主题另有少量人工机制定义，与指南同处；记录稳定机制 ID、双语名称、简短解释、条件、动态事实需求和明确来源选择器。选择器只支持表名、字段和值的精确匹配，不新增查询语言或插件框架。
- 机制定义中的解释与导航标为人工整理；事实证据仍来自快照。每条选择器须命中；缺失时拒绝生成，不能静默删除条件。无关的合法空表与缺表明确区分。
- 新实体的相关记录只表明数据库关联，不自动推断效果适用于当前玩家。保留原始字段、文明／领袖条件、前置及需求集合；间接效果与本局有效数值仍需游戏查询。
- 保持已有公开命令与卡片层级；主题列表、过滤、复制文件和完整性验证覆盖全部九主题。人工定义也纳入指纹与独立重建。
- 五主题分别独立 worktree 和提交；父任务拥有共享采集／构建／查询、入口、快照与生成资料。题目之间通过稳定 ID 和来源契约协作，不互改文件。
- 既有四主题及其规则查询保持可用；允许新增实体使原外部关联变为内部关联，须验证这种预期变化。

## Testing Decisions

沿用用户已确认的公开文件／CLI、临时 SQLite 和临时目录 seam，不新增游戏控制或需要联网的测试边界。

- 各主题使用公开查询验证可观察事实、条件和来源；代码扩展按红→绿逐项实施，不断言源码形状。
- 经营抽查人口／住房／宜居度及建筑产出；资源抽查煤电资源消耗与洪水；军事抽查单位与地形移动字段；外交抽查行动前置与联盟；胜利宗教抽查胜利需求、信条关联与传播机制。
- 验证来源选择器无命中／错字段、缺实体表、重复 ID、悬空内部关联、版本不匹配、摘要不泄露大段证据、主题过滤、独立重建及确定性。
- 正式资料必须所有人工机制来源命中；实际数量以本机采集与最终清单为准，不预设卡片数量。
- 锁定依赖同步、全量 pytest、compileall、文档链接／锚点、卡片／定义指纹、主题工具名与 source_refs 检查通过后交付。
- 原始基准、既有存档、历史规格与验收成果逐文件核对哈希。不进行实机回合或恢复验收，不宣称策略收益。

## Out of Scope

运行时与 MCP 改造、自动策略或默认投票、游戏启动／读档／存档写入、完整规则引擎、向量服务、网络下载全部手册、完整 Modifier 求值、活动模组识别、胜率／耗时改善承诺、远程发布。
