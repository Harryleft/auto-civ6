# 模块接口收敛

本轮在 `f8da6302` 上实施全项目设计评估的五项建议。保留命名 CLI、原生证据和未决请求的既有归属；不增加策略选择或连续对局脚本。

| 工作项 | 交付与验收 |
| --- | --- |
| 结果接口 | 原所有者给出状态、错误码和事实；MCP 保留原文本并附结构化结果。CLI、验收与统计共用一个旧格式 Adapter。展示文案变化不改变已迁移结果判断。 |
| 动作接口 | 固定意图匹配、门禁、范围绑定、单次提交和确认顺序由 ActionLifecycle 管理；领域提供原生计划，普通确认不得推进多阶段动作。 |
| 查询接口 | JSON 编码与世界见证共享；领域 Observation 解释完整性，组合器只组合与核对跨领域范围。坏行、未知与空结果分别保留。 |
| 命令契约 | 静态能力与参数组合共用一个登记；动态状态仍由原所有者决定。预演不访问游戏，不判断本局资格。 |
| 知识读取 | 独立知识包统一验证快照、规则及 manifest；Runtime 保留子进程、协议与前后核验。独立目录与 wheel 安装均可使用。 |

## 实施取舍

- 结果使用兼容字符串的载体逐入口迁移，保留直接 Python 调用及 MCP 文本。机器状态放在 `structuredContent.outcome`；未知不等同未提交，等待不等同错误。
- 查询 Observation 是单次观测，不能作为动作回执或退役 pending 的授权。旧解析器的兼容返回与严格观测接口分别维护，严格组合拒绝不完整领域。
- 命令能力描述不保存状态、不执行确认；允许调度仍不表示原生操作可提交。
- 知识 reader 的源码只有一份；wheel 作为受信包资源携带它，独立知识目录构建时复制同一文件。配置的数据目录不成为 Runtime 导入代码的位置。
- 回归以正式接口、真实 Lua 执行、隔离 stdio 和脚本化传输为主。内部 seam 可保留有针对性的测试，不新增生产 setter 供测试使用。
