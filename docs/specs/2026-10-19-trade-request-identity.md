# 交易确认请求身份

状态：complete。分支codex/native-pillage，[工作项](2026-10-19-trade-request-identity-tickets.md)。

## Problem Statement

T207 已成交瑞典交易关闭对话后，Runtime还保留该尝试的清理阶段。随后向巴西提交不同条款的test请求，只清理旧尝试，却返回瑞典ACCEPTED文案，容易误认巴西报价已成交。金币与资源未变，未收到化妆品；不将旧结果算作新提交。

## Solution

仍保留交易尝试时，只有同一目标、预览模式和条款的原请求可继续确认。不同请求明确拒绝，标明原尝试身份与未提交新请求；不清理或转送为新交易，不返回旧成交冒充新结果。原请求完成清理后可显式另开新请求。

## User Stories

1. 作为Agent，我要让不同文明的报价不能领取旧交易回执，以免误判成交。
2. 作为Agent，我要让同一文明但不同模式或条款也不能暗中确认旧请求，以免混淆试价和成交授权。
3. 作为Agent，我要继续使用原请求完成未决确认与清理，以免交易门禁永久卡住。
4. 作为维护者，我要保留已有单次提交和世界门禁，以免身份检查引入重复发送或隐式恢复。

## Implementation Decisions

在已有run_trade尝试恢复之前对照target、preview、offer、request与准备时副本。使用现有结构化输入；不借此迁移完整交易领域、重写条款序列化。不同请求零原生调用、尝试与门禁保留，明确PENDING_TRADE_MISMATCH／未提交新请求并给出原目标及模式，不能返回旧ACCEPTED结果。原样输入仍只确认原尝试；旧尝试正常退役后，新请求走正常准备。

## Testing Decisions

沿用已确认GameState／FakeConn、内存MCP及现有交易进度测试边界，不连接游戏。覆盖目标、模式、报价、索取各项不一致与DIALOGUE／CLEANUP等阶段：零调用、旧尝试不变、不返回成功，原请求可继续、清理后新请求可进入正常路径。仅运行交易直接相关模块、编译与差分检查。

## Out of Scope

自动新开交易、重试、猜测报价、吞掉原请求、全量测试、合main、push。

## Further Notes

证据1792瑞典成交、1796对话关闭、1798巴西test返回旧ACCEPTED与cleanup，1799–1802无会话且金币／资源无新增。旧尝试在该调用中已清理，后续明确请求可正常提交；不得再将1798视为巴西成交证据。
