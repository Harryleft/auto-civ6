# 文明特性知识与自主决策

标签 ready-for-agent；本地 Markdown tracker；基点 `2b19881`；集成分支 `codex/civilization-knowledge`。

## Problem Statement

Agent 能查询通用规则，却缺少完整的文明、领袖能力及专属内容关联。概览与外交只提供本地化名称，难以准确对应同名或变体领袖。策略指南混有按特定场景固定行动的建议，容易把能力优势直接等同于胜利路线，把敌人能力等同于当前意图，或每回合重复加载稳定规则。

## Solution

用现有只读知识工具按文明、领袖和能力查询，提供名称、来源、继承关系、独有内容和效果条件；本方与已相遇对手复用同一套资料。现有状态工具补充稳定内部 ID。指南按稳定规则、动态事实和可修正判断组织，让模型结合当前证据选择目标与行动，不内置文明攻略或胜利路线评分。

## User Stories

1. 作为 Agent，我希望从当前概览取得准确文明和领袖 ID，以便查询对应资料。
2. 作为 Agent，我希望从外交取得已相遇对手的同类身份，以便理解其能力。
3. 作为玩家，我希望未相遇对手继续未知，以便知识接入不绕过信息可见性。
4. 作为 Agent，我希望身份无法读取时明确未知，以便不从显示名猜测内部 ID。
5. 作为 Agent，我希望按中英文名称和 ID 搜索文明、领袖与能力，以便沿用既有工具。
6. 作为 Agent，我希望通过一个文明主题筛选这些条目，以便控制搜索范围。
7. 作为 Agent，我希望先读摘要确认身份，再展开规则和来源，以便渐进式阅读。
8. 作为 Agent，我希望了解文明能力与领袖能力的归属，以便区分其叠加来源。
9. 作为 Agent，我希望保留领袖继承能力及来源，以便基础领袖和变体能力不被混淆。
10. 作为 Agent，我希望知道对应的特色单位、建筑、区域和改良设施，以便查明发展机会。
11. 作为 Agent，我希望效果、限制、负面能力和触发条件有原始来源，以便判断实际收益。
12. 作为 Agent，我希望专属内容保留解锁、替代与所属关系，以便避免误用其他文明内容。
13. 作为维护者，我希望关联不会混入无关文明或领袖，以便资料可信。
14. 作为 Agent，我希望缺失定义、继承或效果证据明确暴露，以便不把缺失当作无能力。
15. 作为玩家，我希望本机版本来源可核对，以便安装资料不被误当成拥有 DLC 或本局启用证明。
16. 作为 Agent，我希望敌人的能力知识与当前关系、军力、意图分开，以便保留判断的不确定性。
17. 作为 Agent，我希望开局先理解本方能力，再结合地图、启用胜利与竞争决定路线，以便自主取舍。
18. 作为 Agent，我希望稳定规则按需复核、动态事实在决策前更新，以便减少重复读取。
19. 作为 Agent，我希望主路线、对手意图与预期收益作为可修正判断，以便行动回读能改变计划。
20. 作为玩家，我希望没有固定文明胜利配方或额外决策门禁，以便发挥模型的能动性。
21. 作为维护者，我希望新主题不破坏九个现有主题、CLI 和 MCP 查询，以便兼容已有使用方式。
22. 作为玩家，我希望通过离线测试完成验收并保留旧资料、存档和验收，以便不影响现有对局。

## Implementation Decisions

- 新增知识主题 `civilizations`，容纳文明、领袖及能力条目；沿用 search_knowledge 与 get_knowledge 的名称／ID 搜索、限量、三层读取和静态适用边界，不新增游戏控制工具。查询工具总数保持不变。
- 从本机只读来源补充文明、领袖、文明与领袖对应、能力定义与归属、领袖继承、能力效果和专属内容关联所需记录；复用现有来源采集、版本绑定、本地化、关联追踪和校验机制。清单与支持文件指纹随构建同步。
- 本机缓存未涵盖部分已安装文明，缺失者可作为独立的未应用安装定义目录收录。保留所属包、原始 XML 动作与条件来源，不执行 SQL、模组加载或条件求值，不覆盖缓存规则；每层回复标明来源范围及拥有／启用未知。只收录文明特性所需记录，包内关系避免串入无关定义；SQL 或不支持动作造成的缺口显式记录，不声称已经得到该文明的完整有效规则。
- 文明、领袖、能力和专属内容之间使用有来源的关联；领袖直接与继承能力分清归属。继承循环、缺失目标、同名或多个领袖不能静默猜测、截断或混并。效果条件沿用原始 Modifier／需求记录，不求值，不自动转化为最优路线。
- summary 负责身份和概览；rule 提供能力归属、条件、限制、继承和专属内容；evidence 保留可复核来源。没有数据库表达的脚本或本局覆盖保持未知／限制，不从描述补造数值。
- 已安装或缓存的资料是知识覆盖，不证明购买、启用或当前对局适用。静态目录可包含其他文明；不能据此宣称其参加当前游戏，亦不推断对手的隐藏议程和战争计划。
- 现有概览与外交的类型对象和叙述兼容追加可选 `civilization_type`、`leader_type`。只从原生身份 API 读取；未相遇对手不读取／不返回这些 ID，旧记录和 API 缺失保留未知。保持现有名字、动作和可见度行为。
- 策略指南以三类信息为主轴：本局条件下相对稳定的规则与身份、需要及时更新的状态事实、可被证据修正的目标与判断。能力是否在当前生效属于动态核对，不把“定义稳定”理解为收益不变。
- 开局核对本方文明与领袖并查询相关能力，遇到对手再按公开身份查询。只刷新会影响当前决定的必要事实；加载／配置改变或证据冲突时重新核对稳定信息的适用性。不新增缓存、状态存储、后台服务、强制反思或每回合日记。
- 指南保留统一判断问题：目标与瓶颈、相关机制、待核对事实、候选行动的收益／成本／时间／风险、动作回读与调整。将文明攻略、固定胜利分配、特定单位／项目触发的硬编码策略收敛为判断依据；游戏合法性、可见性、未知结果和原生终局边界保持。
- AGENTS 保持简洁入口，查询契约仍集中知识 README；主题指南解释如何读取，策略指南解释如何判断。保留旧知识完整副本和全部现有验收，不覆盖或删除存档。

## Testing Decisions

沿用用户此前已确认的临时 SQLite／知识目录公开 capture、build、query CLI，内存 MCP ClientSession，以及 GameState／FakeConn 和 Lua 5.1 公开查询边界；不新增游戏控制测试入口，无需重复确认这些既有边界。

- 从独立样本断言公开输出：中英及 ID 搜索、文明主题、三层读取、版本与来源、能力归属、直接／继承能力、特色内容与替代关系；无关文明不能混入。
- 来源缺表／缺目标、同名变体、多领袖、继承循环及缺失本地化：明确错误或可观察未知，不能产生伪造规则；维护现有主题兼容与校验。
- 内存 MCP 验证新增主题 schema、公开搜索与分层、无游戏与未决期间读取；工具只读、旧门禁和工具数量保持。
- 概览与外交通过现有公开 GameState／MCP 入口和 Lua 5.1 假原生 API 验证 ID、旧格式、缺失 API、已相遇与未相遇；不测试私有方法或源码字符串。
- 按 TDD 纵向切片实施代码；文档核对原始来源、链接、工具名和三类信息边界，不为文案复述写测试。
- 全量离线、编译、diff、正式知识 validate 与独立 Standards／Spec 双轴审查；保留测试树指纹和存档保护结果。实机、真实 FireTuner、当前客户端游戏调用均不属于本轮验收。

## Out of Scope

文明固定攻略、自动选择胜利路线、策略评分引擎、完整 Modifier 或脚本执行、推测隐藏对手、改写游戏状态、新缓存／后台观测／强制反思系统、联网规则抓取、实机测试、删除旧成果、合并 main、push。
