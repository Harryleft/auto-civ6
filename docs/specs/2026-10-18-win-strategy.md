# 获胜导向的 Agent 决策与胜利预警

标签 ready-for-agent；本地 Markdown tracker；基点 `ed23713`，集成分支沿用 `codex/architecture-deepening`。

## Problem Statement

上一局第 100 回合仅一城，第 127 回合才建立第二城，终局仍两城；对手已有 12～14 城。本方未形成可赶在对手之前完成的胜利路线，第 244 回合输给瑞典科技胜利。胜利专项读取曾间隔 22 回合；现有轻量预警构造器没有调用者，太空项目查询还混用旧规则的项目和前置、用胜利积分猜测项目完成，损害战略输入。

## Solution

以扩张、可完成的主胜利路线、对手胜利时限为决策主线。Agent 在开局、关键变化和路线失效时比较机会成本，按实时合法候选选择动作；确认推进后持续提供轻量只读预警，出现风险再展开完整胜利事实。离线通过后，从唯一原始基准重新开局，以获胜为目标完成原生终局验证，保留旧数据与新结果。

## User Stories

1. 作为玩家，我希望开局先评估扩张空间，以便人口、区域和生产形成规模。
2. 作为玩家，我希望比较开拓者、护卫、基础设施及安全成本，以便扩张不是机械追城数。
3. 作为玩家，我希望有限的安全地块优先被占据，以便不在单城停留到中期。
4. 作为玩家，我希望主动探索与护送开拓者，以便不把跳过单位当成策略。
5. 作为玩家，我希望早期选择一条主胜利路线和可行备选，以便科研、市政与生产共同服务于终点。
6. 作为玩家，我希望把未解锁、已解锁、可生产、正在生产、已完成和未知分开，以便不按错误项目链决策。
7. 作为玩家，我希望所需科技来自本机活动规则，以便不混用原版与风云变幻。
8. 作为玩家，我希望新宇航中心、实际太空进度和接近胜利的对手及时被发现，以便还有干预窗口。
9. 作为玩家，我希望预警保留 33.5 之类真实需求，以便不截断阈值。
10. 作为玩家，我希望未知、禁用胜利及未相遇对手不被误报为安全或泄露情报，以便依据已知事实判断。
11. 作为玩家，我希望风险提示不替我投票、宣战或改变生产，以便由模型明确权衡并执行。
12. 作为玩家，我希望战争兼顾保城、消耗与扩张收益，以便避免长期防守挤占全部发展。
13. 作为玩家，我希望议会投入围绕胜利点与竞争情况安排，以便提交成功不被当成战略成功。
14. 作为维护者，我希望策略与 Runtime 职责分离，以便不引入第二套游戏控制、后台规划或强制反思协议。
15. 作为测试者，我希望真实 Lua 与公开 GameState 检验查询及报告行为，以便提示不会重放推进或产生写操作。
16. 作为玩家，我希望从 benchmark_turn_1 原件开始新轮次，以便能比较早期扩张与胜利路线。
17. 作为玩家，我希望保留所有旧存档和验收，并独立保存新检查点及原生结果，以便完整复查。
18. 作为玩家，我希望以原生胜利为成功标准，以便不得用分数、工具提示或人为修改世界状态冒充胜利。

## Implementation Decisions

- 当前 Agent 是外部模型。新增简短获胜策略指南，以 AGENTS 和操作指南的条件路由接入；知识规则仍由独立规则目录提供，策略文档只保留取舍与行动顺序。固定阻塞验收驱动不改为获胜 Agent。
- 开局读取速度、难度、文明、地图与已探索土地，选择主路线及备选。扩张评估包含淡水、有效产出、忠诚、通路、护卫、财政和边界风险；文明能力与本机规则核对。阶段城数仅作为本局可调整目标，不作为引擎规则或动作门禁。
- 维持一份紧凑当前计划：主路线、下一瓶颈、扩张动作、主要对手及风险、下一行动。计划留在任务上下文或本轮验收摘要，不要求每回合日记，不增加 end_turn payload、强制状态机或服务器策略缓存。
- 研究、生产、政策、交易、战争和议会选择按主路线、收益生效时间、对手剩余窗口及生存约束排序；主路线不可赶及时明确换路或干预。保城紧急行动优先，战后恢复扩张与发展，避免长期以防御替代发展。
- 接入既有轻量胜利风险查询至每次已确认推进后的报告；不在尚未确认的推进上发新动作或重放。预警为纯读附加信息，读取失败只限制报告，不改变已确认回合或释放未决。终局由权威终局事实判断，风险不判胜负。
- 科技预警在已完成宇航中心或正太空进度时就出现；接近需求时提升紧迫性。比例阈值属于可说明的策略启发式，必须保留原始进度／需求，不能作为已胜利、精确剩余回合或资格判定。其他已启用胜利沿用可核实的原生外交／宗教等风险，缺失资料明确未知，不默认为安全。
- 仅展示当前工具能合法读到的本方、已相遇对手及允许的汇总；禁用胜利不生成对应风险。普通完整查询和回合预警共用事实解释，避免两套矛盾阈值。
- 修正太空项目事实：项目存在性与 PrereqTech 读取本机 GameInfo；实际建设队列优先，原生项目完成状态核实后才能标完成，真实 CanProduce 资格核实后才能标可建。积分、固定序号或正生产成本不能推断项目完成／可建；缺失 API 或读取异常保留未知。
- 科技胜利需求使用有限非负数，分数保留；不截断 33.5，不填未经核实的默认需求。工具说明改为风险驱动的读取频率，出现宇航中心／进度后每回合核对必要事实，不再统一建议 20～30 回合读取。
- 新实机仅原始基准，保持原生难度／速度／规则。游戏动作通过现有 MCP 单次提交和完成见证；不以直接修改产出、资源、科技、胜利状态或重掷地图制造结果。既有非标准晋升兼容路径不用于本轮获胜证明。
- 普通恢复优先菜单，完整重启仅显式故障恢复；恢复仅使用本轮确认检查点，不因战略失误回档挑结果。原始基准和现有成果只保留，新结果独立命名。

## Testing Decisions

沿用用户已确认的公开 GameState／FakeConn、真实 Lua 5.1、内存 FireTuner 与临时目录；离线不连接游戏。不为文档措辞编写复述实现的测试。

- 经公开胜利查询与真实 Lua 验证本机项目名／前置、原版与扩展存在性、原生完成、真实生产资格、缺失 API 和异常；积分不能伪造完成、正成本不能伪造 ready。
- 覆盖 fractional science 33.5、未知需求、零进度但已有宇航中心、接近阈值、已禁用胜利、未相遇对手及未知字段；保留事实并区分启发式风险与权威终局。
- GameState.end_turn 确认后报告含风险，预警异常仍保留已确认增长；未决推进、暂停、终局与传输未知不引入额外推进、写入或自动恢复。合法普通动作契约保持。
- 指南检查链接、知识入口、工具存在性及与实现一致；不新增纯字符串措辞测试。全量离线、编译、diff 与独立双轴审查通过后开始新局。
- 实机记录原始指纹与新轮次，观察扩张里程碑、路线选择和风险响应，保存 20 回合及关键事件检查点。以原生胜利为成功；若失败则保留原生失败与原因，不能声称获胜验证通过。继续处理实际阻塞和本次实现造成的问题。

## Out of Scope

云端或网页 Agent、第二套控制实现、自动后台规划／投票／宣战、通用规则引擎、批量对局评测、强制反思／日记、修改原始存档、降低难度、作弊完成胜利、删除旧成果、push 或合并 main。
