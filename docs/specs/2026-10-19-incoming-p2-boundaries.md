# 来约零提交确认与世界失效锁存

Status: completed

## Problem Statement

终局后离线审查发现两项 P2：来约编辑被原生校验拒绝、草稿成功恢复后，如果零提交回应丢失或调用取消，后续确认忽略 ZERO 回执，未决门禁无法解除；来约的世界检查依赖未决推进，没有 end_turn 时观察到换世界不会锁存失效，返回原身份后旧事件可能错误确认。

## Solution

同一来约重试只确认原尝试。明确的原生零提交证据允许安全退役该尝试；世界不匹配必须由外交所有者自行锁存，不能因没有推进请求或随后身份恢复而释放。完成相关模块离线验证后提交 main，不连接游戏、不 push，保留现有存档和 T233 科技胜利验收。

## User Stories

1. 作为调用方，我希望丢失零提交回应后，重试能够明确返回未提交，避免永久阻塞。
2. 作为调用方，我希望取消后仍只确认原尝试，不重复编辑或发送评估。
3. 作为调用方，我希望原生零提交、发送成功和证据未知分别处理，不把未知当作未提交。
4. 作为调用方，我希望缺失、过期或不匹配的回执不能解除门禁。
5. 作为调用方，我希望没有未决推进时，来约也不能跨世界确认。
6. 作为调用方，我希望先观察到其他世界再返回原身份时，旧来约仍保持未决。
7. 作为调用方，我希望缺失或无法读取身份时保留未决，恢复原身份读取后仍可安全确认。
8. 作为调用方，我希望正常推进未决的来约处理继续有效，其他写操作仍受门禁保护。
9. 作为维护者，我希望显式受保护会话替换仍是退役失效请求的入口，不增加隐式重启或清理。

## Implementation Decisions

- DiplomacyProgress 持有来约尝试及其世界绑定，独立于 TurnProgress 判断观测身份；继续把每个世界观测交给推进所有者，保留既有推进保护。
- 完整且明确的不匹配身份锁存外交来源失效；缺失、未知或格式不完整的身份只保持未知，不能被当作成功或明确换世界。
- 确认读取必须绑定原世界、会话、参与方和 token。ZERO 回执通过现有零提交 finish 入口退役，finish 未确认时继续保留；不读取成交事件代替零提交证据，不重发评估。
- 已观察到换世界的尝试不能因旧身份、旧事件或普通身份查询再次出现而恢复；SENT／ZERO 两种确认均受此限制。
- 保持现有公开接口，不增加后台任务、自动恢复或新游戏控制路径。

## Testing Decisions

沿用用户此前确认的 GameState／FakeConn、内存 Lua 5.1 与 MCP 公开边界，不新增测试缝。红绿测试覆盖：原生编辑后校验失败并恢复草稿，丢回应／取消后 ZERO 确认且零发送；回执缺失、错 token／会话、世界未知和 finish 失败继续保护；没有 pending end_turn 的世界切换锁存、返回原身份仍未知、正常同世界延迟确认和已有推进世界保护。换世界覆盖发送、回执、响应、最终报价及零提交／正常 finish 的原生调用边界。测试观察公开结果、未决事实、草稿与原生发送记录。只运行来约、主动交易、外交清理、推进世界绑定和相关 MCP 门禁模块；不运行全量或实机脚本。
