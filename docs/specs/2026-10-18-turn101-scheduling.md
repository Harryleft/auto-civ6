# T81→101 调度与等待识别

## Problem Statement

上一轮三项查询修复已验收，但 T66 将本回合不能开始的移动提交为未来队列，随后因无位移不能确认；T78 则在已确认移动和交易后长时间无法推进，恢复同一世界后约 5 秒通过。现工具把等待预算耗尽称为 HANG、误报读取失败，且缺少可独立读取的原生阶段。用户难以区分正常 AI 等待、人工交互与运行故障。

本机原生外交界面通过 ReferenceCurrentEvent 锁引擎，在正常关闭的 UninitializeView 中释放。项目直接 SetHide 会跳过释放，并使后续 TurnEnd 的条件关闭失效；隔离执行原生函数已复现事件锁残留。这是已证实的清理缺陷，尚须实机隔离它与 T78 的因果关系。城市资源提示另有坐标拆分及中心地块误报。

## Solution

按优先级修复外交原生关闭和等待观测、移动前置检查、资源提示。使用与原生 UI 一致的提交前提及单次请求确认；等待保持等待，已识别的待办明确展示，缺失事实保持未知，不用固定时长推断死锁。

离线通过后可用同轮 T78 前后检查点开展必要的受控诊断，再从 T81 verified 续推到 T101；诊断与重做进度不计入这 20 个净回合。保留现有成果，另存结果并验证菜单恢复，不 push。

## User Stories

1. 作为游戏 Agent，我希望当前不能开始的移动零提交，以免产生永远等不到位移的未决动作。
2. 作为游戏 Agent，我希望第一步可走、终点在未来回合的路线仍可执行，以保留合法分段移动。
3. 作为游戏 Agent，我希望剩余移动力与原生路径共同解释当前可行性，而不把正移动力当作下一格可达证明。
4. 作为游戏 Agent，我希望拒绝新移动时保留原队列、见证及既有门禁。
5. 作为游戏 Agent，我希望丢失回应或提交后无可靠证据时保持未知，不靠时间释放门禁。
6. 作为用户，我希望正常 AI 等待超出一次工具预算时仍被准确命名，而不被判为死锁。
7. 作为游戏 Agent，我希望独立查询本地回合活动、完整性与消息处理状态，以判断下一步是等待还是处理交互。
8. 作为游戏 Agent，我希望看到原生已发回合完成、能否结束及接口模式，避免重复或过早提交。
9. 作为用户，我希望看到首次提交以来的总等待时间及最近阶段变化，不在每次确认时重新计时。
10. 作为用户，我希望实际读取错误与观察预算耗尽分开呈现。
11. 作为游戏 Agent，我希望外交、议会与信息弹窗有明确状态，正常等待不替模型投票或回应。
12. 作为用户，我希望只读阶段查询既不写游戏，也不确认或清除未决请求。
13. 作为游戏 Agent，我希望外交成交后沿原生关闭路径释放事件锁，不仅隐藏画面。
14. 作为用户，我希望清理 UI 前核对无会话、排队会话和待回应交易，不强制关闭真实待办。
15. 作为用户，我希望已成交交易与 UI 清理状态分开报告，清理失败不吞异常或重新成交。
16. 作为用户，我希望资源、修复提示保持完整坐标，不出现孤立数字，旧协议仍能读取。
17. 作为游戏 Agent，我希望中心及区域地块不被误报为待改良资源，隐藏资源及未知仍遵守现有边界。
18. 作为用户，我希望 T78 的历史诊断区分已证实机制、实机对照和剩余假设。
19. 作为用户，我希望从指定 T81 档净推进 20 回合，按实际战争、经济与对手进度修正决策。
20. 作为用户，我希望原始基准、旧档、旧验收、同轮身份和新结果均可核验，恢复优先走菜单，完整重启只作显式故障恢复。
21. 作为游戏 Agent，我希望交易准备完成后才发条款，避免迟到的原生 OnShow 自动 INSPECT 与本次请求交叉。
22. 作为用户，我希望预览和发送只消费本次会话的实际响应，不把工作交易缓存当作新回复。
23. 作为游戏 Agent，我希望预览未终结或已有真实外交待办时不另开交易会话；再次调用只核对原尝试。
24. 作为用户，我希望交易在取消或丢回应后保留世界、对象、会话及阶段，不重复 RequestSession、EQUALIZE 或 PROPOSED。
25. 作为游戏 Agent，我希望查询展示当前原生选择，成交致谢只有退出选项时明确使用 EXIT，不先发不存在的 POSITIVE。
26. 作为用户，我希望文本暂时不变不能触发强制闭会，真正的退出由当前会话与原生选项证明。
27. 作为用户，我希望已提交接受后的真实终结语句能被确认，不因原生最终回应使用不同字段而永久等待；旧语句、其他会话和未提交接受仍不能证明成交。
28. 作为游戏 Agent，我希望原生单位／城市软待办在结束前被明确报告，不能仅凭通知首阻塞为空和 CanEndTurn=true 就认定会完整结束回合。
29. 作为用户，我希望自动移动后仍停在本地且未送 complete 的情况与等待其他玩家分开显示；旧未决请求不能靠时间或 LOCAL_READY 自动释放。
30. 作为游戏 Agent，我希望根据全局目标判断移动是否必要，既可继续原移动，也可明确取消移动并留在原地；剩余移动力和结束回合检查不能迫使我移动、自动跳过或改变站位。

## Implementation Decisions

- 沿用现有集成分支；本地 Markdown tracker 使用 ready-for-agent。三个独立工作项使用各自工作树，由独立 merger 按优先级合入。
- 推进所有权仍在 TurnProgress。新增公开只读 get_turn_status，与推进共用原生阶段解释，分别保留 active、complete、processing、has_sent_turn_complete、can_end_turn、interface_mode 和未知原因；有待办则报告对应交互。查询不退役请求、不自动回应或恢复。
- 原请求记录首次提交时间、最后成功观测和阶段变化；重复确认累计时长，仍只有一次提交。观察预算继续有界；阶段长时间不变仅表示未确认，不自动成为死锁。真正读取错误单独记录，丢失回应和世界范围失效继续保留门禁。
- 结束回合按本机原生前提作同块最终复核：消息处理中、已发 complete、原生不允许或事实未知时不新增请求；必要的 SELECTION 恢复沿原生结束回合路径。已提交和确定未提交必须分别解释，取消或丢回应不能假定零提交。
- 外交视图由准确发现的原生上下文执行 Close，禁止猜上下文索引或直接释放任意事件 ID。只在当前所有会话、排队及待回应交易已确认为空时清理；清理不新增外交回应，不重提已成交交易。显式弹窗处理入口可修复无待办的残留视图，再确认原推进；纯查询不得清理。清理进入后丢回应保留不确定性，不透明重放，不以固定延迟或 SetHide 证明关闭。
- 移动继续使用完整原生路径：路径回合以本机 UI 的 1 为当前回合；首个离开原点的步属于未来时，明确 MOVE_DEFERRED、零提交且保留旧队列。首步当前而终点未来仍允许分段执行。结构不完整或语义未知时保守拒绝本次；提交后的确认证据不放宽。
- 城市提示用无歧义条目分隔并兼容旧 NAME@x,y，展示保留坐标；排除中心和区域地块。保留可见性三态、安全部分结果及纯查询属性，不扩大为资源调度或城市归属重构。
- 实机 C 组新增交易准备时序：先确认所有 open／queued／pending 为空，清空本次工作交易并确认空，再单次 RequestSession。等待准确的 DealView 上下文、参与方、发起方及会话匹配后才填条款，避免 OnShow 对已有条款自动 INSPECT。预览发送 EQUALIZE；对 AI 发送沿本机界面先单次 INSPECT，用本次 nonce、世界及 session／action 匹配的原生事件读取评估，再对与原授权条款完全一致的反案单次 ACCEPTED；不同反案须明确决定。INSPECT 的 AI_ACCEPT 仅表示评估，不能解释为成交，最终接受另行确认。不将无响应的 PROPOSED 当同步 AI 协商；多人交易不在本次扩展范围。旧缓存、瞬时空态、固定延迟均不能证明完成。重复调用只确认未决尝试，不重发或开启第二会话，不引入通用交易框架或自动接受新条件。
- 当前外交选择按原生会话及 statement 解析并展示；EXIT 与 POSITIVE／NEGATIVE 分别核对当前选项，不以相同文本和 0.3 秒等待推断 goodbye，不自动为用户挑选回应。退出与原生视图清理仍分别确认。
- 实机最终接受回应另行核对本机原生契约：同一已提交接受、nonce／世界／参与方／会话和提交后新语句均匹配时，处理 HUMAN_ACCEPT_DEAL 的原生终结形式。不能把任意零 action、经济变化或显示文本作为完成见证；继续分别确认显式退出和视图清理。
- T91 增量：结束前核对本机 ActionPanel 的单位可行动、城市可攻击软条件，保留用户选项、战术命令许可和具体原生单位／通知事实。只读阶段展示本地尚未送 complete 的待办，不称为电脑玩家等待。跨回合移动队列可在结束动作期间执行并留下剩余移动，前置与回读须按实际原生证据处理；单靠活动类型、固定延迟或当前就绪不能退役旧请求。已有未决本轮通过显式受保护恢复到 T91 已确认检查点重验，不新增强制跳过、Shift+Enter 或透明重发。
- T91 受控读取确认：auto_end=false，弩手有非商路原生排队目标、剩余2移动且首步为本回合；显式完成原目标后队列消失。结束前对这类当前可执行队列零提交，报告具体单位及目标，由模型明确完成移动／处置后再推进。首步未来的合法队列不拦，活动类型本身不作依据；排除已确认商路，目标或路径结构未知保留未知。预检与最终提交使用同一解释并再次核对，不新增通用规划缓存。
- 移动队列检查只暴露待决意图，不规定策略。是否继续移动、取消原意图后驻防／治疗／待命由模型结合目标、地形、威胁和机会成本选择；禁止为了耗尽移动力或解除门禁制造无必要位移。留在原地的处置必须走已核实的原生控制并确认队列结果，不能直接篡改活动／队列、误停商路或以未知结果推定取消成功。
- 指南简洁说明“等引擎／处理交互／未知”的入口；文明能力属稳定规则，战争、收支、路径及对手胜利进度属动态事实，主路线可修正，不加入固定场景策略。

## Testing Decisions

- 沿用用户已确认的公开 GameState／MCP、FakeConn、Lua 5.1、内存 FireTuner 和临时目录边界；没有新增游戏控制实现。不再重复询问已同意的测试边界。
- 逐项 red→green，测试外部可观察行为与原生边界：纯未来路径零提交且旧队列不变；合法部分移动、正剩余移动力片段、错身份／丢回应／未知忙态仍按原确认规则处理。
- 使用独立时钟和原生阶段序列验证慢 AI 超预算、跨调用累计、实际失败、就绪但旧请求未确认、已有 native complete、原子检查竞态及世界切换。请求至多提交一次，不仅匹配文案或源码字符串。
- 外交测试覆盖原生事件锁残留复现、正常 Close 的配对释放、隐藏但初始化的视图、活动及排队待办拒绝清理、未知上下文、丢回应及成交结果保留；查询必须零游戏／UI 写入。
- T91 回归覆盖通知 NONE 但原生软待办存在时零结束提交、纯读具体待办、缺失选项或原生字段保持未知、队列执行后本地未送 complete 的报告；不能将慢 AI、队列或城市攻击一概自动 skip。沿用既有公开 GameState／MCP、FakeConn 与 Lua 边界，只跑受影响模块。
- 验证明确选择留在原地时不产生位移，原生队列取消与后续驻防／治疗分别确认；读取或结束预检不自动取消，不影响已确认商路和其他操作。丢回应及错误身份仍保留未决状态。
- 沿用 GameState／内存 FireTuner／Lua 5.1 边界，加入迟到 OnShow 自动 INSPECT、会话延迟出现、旧 incoming 缓存、错 session／action／world 响应、各阶段取消与重复调用零重发、原生 EXIT-only 及文本不变仍需等待的回归。实机补充仅 preview／仅 send 对照；等待结果保留原请求，不据超时宣布死锁。
- 城市提示覆盖新旧协议、多条同类资源、负坐标、掠夺条目、中心与区域排除、隐藏／未知和普通资源；通过真实查询与叙述边界验证。
- 按用户最新要求，后续集成只运行当前改动相关模块测试：交易、外交选项、取消与重试、受影响的回合／保存恢复／MCP 门禁及叙述契约；保留锁定依赖、compileall、diff 与受测指纹检查。按本次起点审查 Standards／Spec，发现修复后只重跑相关门槛，不再重跑全量。此前 1,877 项全量结果保留为该旧版本的历史证据。
- 实机先记录阶段与有证据的最小 T78 对照；后从 benchmark_queries_20261018_t81_verified（同轮 f6f887b18a7b4c3b8af3571c70d9a509、种子719665280、SHA256 9398c15ebf5a8fbc897839e2380739401c5e28b9eb0577857184e6db206225bc）续推至101。每次未知只确认原请求；必要显式恢复保留证据，不按战略损益回档。
- T101 另存，优先菜单恢复并比较身份、回合、概览、单位、城市、政策、商路、着力点、外交、总督及必要原生状态。分数差异原样记录，不能掩盖。完成后核对全部旧文件及新档指纹，清理实施工作树。

## Out of Scope

固定超时判死锁、后台监控服务、自动外交回应或投票、静默重启、盲重发、放宽未决门禁、隐藏 AI 规划、重建路径算法、通用交易系统重写、固定文明胜利模板、修改游戏资源／科技／胜利、非标准晋升兼容路径、合并 main 或 push。
