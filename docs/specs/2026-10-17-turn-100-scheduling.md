# 第50至100回合调度修复规格

2026-10-17。起点 `d0a3b82`，集成分支 `codex/turn-100-scheduling`。本地 tracker，标签 `ready-for-agent`，沿用此前约定的测试边界和工作项流程；不建立远端 issue／PR，不push。

## Problem Statement

用户要求从最新第50回合检查点继续至100，每20回合检查调度并保留结果。第54回合建造者单次移动从(19,17)到(18,18)，实际停在(19,18)，普通与有效移动力均为1，ZOC为false、核心空闲、原生路径下一步为turn2。运行时缺少这一正常单回合移动段结束的证据，持续保持动作未知，拒绝推进。原命令不能重发，等待和重复读取也无法解除。

现有规则刻意不凭路径预览的turn2放行，仍然正确。需要补充原生当前移动段完成的见证，而非将路径预计时间解释为实际完成。

## Solution

在单次移动提交之前登记本次请求的原生移动段完成见证。结合新鲜身份、单位、位置、核心空闲、排队目标及原生完整路径，确认本回合段已停止，并如实报告剩余移动力和未到达目标。保留其他未知门禁。离线通过后显式从原第50回合检查点菜单恢复，重放第54回合触发点，再继续70、90、100回合验收和独立保存。

## User Stories

2. 作为玩家，我希望确认来自真实原生事件，以免把路径预览当作完成。
3. 作为玩家，我希望单次移动只提交一次，以免未知时重复操作。
4. 作为玩家，我希望移动到中间位置时如实显示，以免误以为已到目标。
5. 作为玩家，我希望保留实际剩余移动力，以免伪称移动力耗尽。
6. 作为玩家，我希望尚可继续移动的中间步骤保持未决，以免过早推进。
7. 作为玩家，我希望其他单位、玩家或旧请求的事件被忽略，以免错误放行。
8. 作为玩家，我希望换回合、换世界和单位重建时旧见证失效，以免错认结果。
9. 作为玩家，我希望事件不可用或响应不完整时继续报告未知，以免掩盖状态缺失。
10. 作为玩家，我希望晚到完成可以只读确认，以免重放原动作。
11. 作为玩家，我希望排队目标与本次请求一致，以免认错移动命令。
12. 作为玩家，我希望新见证只移除自己的监听，以免影响游戏原生行为。
13. 作为玩家，我希望旧未决动作不补造历史见证，以免伪造完成。
14. 作为玩家，我希望优先通过菜单恢复已确认检查点，以便避免完整重启等待。
15. 作为玩家，我希望诊断阶段的失败及回退得到记录，以便区分净推进和重放。
16. 作为玩家，我希望在70、90、100回合取得状态与检查点，以便审查阶段结果。
17. 作为玩家，我希望正常生产、科研和外交阻塞得到明确处理，以便与程序阻塞区分。
18. 作为玩家，我希望继续出现的程序阻塞按同一规格／实施流程修复，以便完成100回合目标。
19. 作为玩家，我希望已有存档和验收证据保持原字节，以便后续复核。
20. 作为维护者，我希望沿用现有MCP、GameState和FireTuner边界，以免新增游戏控制实现。

## Implementation Decisions

- 只补充移动提交与确认的证据，不移除既有路径预览单独不能确认、同身份同回合、busy和未知门禁。
- 本机原生ActionPanel登记UnitOperationSegmentComplete以刷新结束回合状态；该事件与每格UnitMoveComplete、全部队列清空的UnitOperationsCleared不同。原生回调提供player、unitID和两个未类型化附加参数；不能在未实测前假定附加参数等于MOVE_TO哈希。
- 在唯一RequestOperation之前建立请求作用域见证，绑定唯一token、本地owner、完整runtime单位ID、文明／种子／回合、原点和目标。token是本地记录隔离，不是原生回显ID；仍依赖串行门禁、目标归属和新鲜状态核验。
- 部分段新确认需要所有条件：本次作用域匹配的原生段完成；同身份／回合／完整单位；位置离开原点、核心明确空闲；原生排队目标匹配请求目标；结构完整的原生路径从当前位置到请求目标，紧接一步turn大于1。路径、队列、事件任意一项单独不足以确认。已到目标、原生零移动力和ZOC现有确认行为兼容。
- 若排队目标或事件在本机语义与假设不符，先记录实际事实再修正规格，不用缺省值或计时放宽门禁。对已完成的旧请求不得事后安装监听来制造历史完成。
- 监听保留函数引用，仅移除本工具自己的监听；完成或明确未提交失败清理，未知期间保留对应单一记录。上下文替换后旧记录不能绑定到新会话；不增加通用观察服务、后台轮询、重试动作或全局事件清空。
- 使用已有动作确认总预算和单次提交机制，返回明确部分停止原因、当前位置及真实剩余移动力。
- 第54回合旧未知保留在诊断日志。修复后重新建立MCP并显式菜单恢复最新第50回合已确认检查点，重放触发场景；不将客户端重建解释为旧动作完成。必要的完整重启仍需显式记录原因。
- 此后的新程序阻塞追加同一规格与依赖工作项，先诊断再修复；正常游戏规则拒绝、参数误用和战略损失单独记录。

## Testing Decisions

沿用已确认的MCP／真实GameState／FakeConn、内存FireTuner流、快照差分和临时存档目录，不新增测试边界。测试外部结果和请求次数，不以私有字段断言替代用户行为。

以第54回合实际读数形成先红后绿切片：原生见证与全部新鲜事实齐备时确认部分停止；只有turn2、旧或外来事件、未匹配排队目标、路径截断、busy、原点未变化、身份／回合／完整ID变化、断流和取消均不能误报成功。晚到见证只读确认且移动提交次数始终为1。使用现有保存完成见证、移动确认与连接测试作先例。

集成后执行locked依赖检查、全量离线测试、compileall和diff check；从固定起点进行Standards／Spec两轴独立审查。实机记录原生事件字段与恢复后同一触发动作的响应，然后只在真实回合增加且本地可操作时计数。70、90、100各检查概览、单位、城市、通知及未决门禁并原生保存；最终菜单恢复新100回合结果核对身份、回合、单位／城市和分类分。保留全部失败尝试、回退和新旧文件指纹。
