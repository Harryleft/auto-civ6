# 来约还价与底线试探

## Problem Statement

T135→136 的瑞典来约包含双向和解、巨作、3 金币及每回合 2 金币。用户要求先试探条件，再决定成交。现有交易试价会新开会话且拒绝战争目标；来约入口只有接受／拒绝，结束回合未决时不能修改报价。界面坐标操作持续返回 `noWindowsAvailable`，不能以重启客户端丢弃原推进请求来绕过限制。

## Solution

增加针对当前已核实来约的显式还价入口。模型指定本轮调整的金币条件，保留和解、巨作、资源及期限等其他条款；先读取原生评估或反提案，再决定下一次报价或是否接受。Runtime 不自动寻找最高价、不自动成交、不重开会话。

## User Stories

1. 作为玩家，我希望在对方来约中修改金币条款，保留其他条件供公平比较。
2. 作为玩家，我希望先读取完整报价及稳定指纹，再用该指纹约束修改，防止操作已变化的提案。
3. 作为玩家，我希望试价返回原生接受意愿、拒绝或反提案，并明确这是否已成交。
4. 作为玩家，我希望来约还价不自动接受原报价或新报价；最终接受仍须模型显式调用。
5. 作为玩家，我希望和平来约保留双向和解和原期限，不用普通贸易入口代替和谈。
6. 作为玩家，我希望每次只提交一次调整，丢回应、取消或超时后重复调用只确认原尝试。
7. 作为玩家，我希望正常结束回合未决期间能处理其来约，而保存、加载及其他动作门禁保持。
8. 作为玩家，我希望世界、会话、参与方、可见界面或报价不匹配时零提交，未知事实不能猜测。
9. 作为玩家，我希望报价被拒后仍可在当前原生会话中再次明确报价，或显式退出。
10. 作为玩家，我希望根据交易价值和继续行动成本自主判断，不由代码固定让步顺序或价格。

## Implementation Decisions

- 扩展现有外交领域，使用一个针对当前来约的公开还价入口及现有待处理交易查询、最终回应入口；不新建游戏客户端。
- 公开查询提供当前报价指纹和可核实条款。还价要求匹配世界、会话、双方、可见原生交易及原报价指纹；参数仅调整明确给出的本方／对方一次性金币和每回合金币，未指定项及非金币项保持不变。
- 依据本机官方交易界面的复制、金额编辑、原生评估／调整流程实施。只使用经确认不会最终成交的原生动作；若无法保证这一语义，零提交并报告限制，不以发送可成交提案冒充试价。
- 复用 DiplomacyProgress 的单次提交、事件关联和未决所有权；确认绑定原生 action、参与方、session 及前后条款，不能只凭界面文字或响应到达判定接受。
- 明确区分可接受意愿、反提案、拒绝、成交及结果未知。模型显式最终接受前不调用 ACCEPTED。若原生会话不支持无成交评估，公开接口应明确拒绝该操作。
- 仅允许此已绑定来约处理穿过普通推进未决门禁；其他未决动作、保存、替换及跨世界情况保持保护。不退役原 TurnProgress，不通过重启安装工具逃避门禁。
- 操作及策略指南简要说明先估值、有限试价、比较可接受区间再决定；不要求每笔交易机械穷举最高价格。

## Testing Decisions

沿用已获确认的 GameState／FakeConn、Lua 5.1 与 MCP 公开边界，离线不连接游戏。逐条 TDD 验证原条款保留、明确调整、指纹变化零提交、战争和平来约、正常推进未决许可、其他门禁、原生拒绝与反提案、丢回应／取消后只确认、跨世界和最终接受语义；只运行相关模块。实机不重载当前未决局面；安装新版只在当前请求已核实结束后进行。若需用户当前界面协助，保留真实操作及限制记录。

## Out of Scope
