# 原生掠夺动作

## Problem Statement

T127 瑞典突袭，本轮在 T131 需要通过掠夺削弱其科研、收入与文化。现有单位 MCP 支持移动、攻击和维修，却没有掠夺入口；无法用普通工具执行该合法策略。T131 已另存检查点，不回放战争或战略损失。

## Solution

在现有 `unit_action` 增加显式 `pillage`，仅作用于指定本方单位当前地块。原生规则决定资格及收益，动作生命周期负责单次提交和真实确认；模型决定是否值得进入该地块、掠夺哪一层以及何时撤退。

## User Stories

1. 作为玩家，我希望明确指定单位在当前格掠夺，不自动移动或选择目标。
2. 作为玩家，我希望学院、商业设施、剧院、资源改良等由本机实际规则判定，不维护固定目标白名单。
3. 作为玩家，我希望友方、中立、不合法目标及行动力不足时零提交拒绝。
4. 作为玩家，我希望一次只掠夺一次，区域内多层建筑不被工具自动全部破坏。
5. 作为玩家，我希望依据地块／建筑／区域的原生状态变化确认完成，而非仅凭提交、移动力或金币变化。
6. 作为玩家，我希望丢回应、超时及取消后保留未知，查询或重复同意图只确认原尝试，保存与推进受门禁保护。
7. 作为玩家，我希望回读绑定原世界、回合、完整单位身份、位置及原目标；换世界或目标未知不能追认成功。
8. 作为玩家，我希望收益只报告可核实的事实，不把估计、被动收入或缺失字段叙述成实际掠夺收益。

## Implementation Decisions

- 扩展现有单位动作接口，目标为当前格，无坐标参数依赖，不新增专用控制客户端或通用行动框架。
- 使用本机安装 Lua 中的原生掠夺操作及严格资格检查；优先读取官方脚本确定操作／见证，无法确认时拒绝或未知，不猜测常量和效果。
- 复用 ActionLifecycle 的未决所有权、单次提交及只读确认。提交前与原子提交块都复核身份、位置、目标、资格及空闲事实，明确零提交与可能已提交不同。
- 改良、建筑及区域的状态见证须能观察同一次原生损坏；多层区域按同一当前目标指纹比较。确认不能仅依据 ready、行动力消耗或收益字段变化。
- 失败或未知不自动选择其他目标、不自动移动、驻防、结束回合或恢复。其他单位动作不得穿过未决门禁。
- 操作指南简要说明调用条件和一次一层语义；不加入固定战争策略。

## Testing Decisions

沿用用户已确认的 GameState／FakeConn、Lua 5.1 原生流及 MCP 公开入口，不新增测试边界、不连接游戏。按 TDD 逐条验证合法单次提交、严格拒绝、区域多层见证、丢回应后不重发、原世界／单位／位置变化、取消和保存／推进门禁；仅运行直接相关模块。实机在同轮当前检查点之后，先核实敌方地块与撤退路线再执行合法掠夺；不为制造场景回档或修改规则、资源。

## Out of Scope

自动选择掠夺目标、自动连掠区域、自动战争、全量测试、晋升兼容路径、修改资源制造胜利、战略回档及 push。
