# Civ6 第 30～50 回合调度修复规格

日期：2026-10-17。来源：第 21～30 回合实机记录 B1～B5。状态：T1～T6 完成，629 项离线测试通过，双轴审查无实质问题；T7 实机验收中。代码基点 `bd11efb`，集成分支 `codex/turn-50-scheduling`。

## Problem Statement

模型通过本机 MCP 推进同一对局时，仍可能因响应串位、错误完成提示、落位拒绝无法分类及移动停步证据不足而卡住。上轮第 21～30 回合出现三次技术性未知结果，均依赖同回合检查点恢复；城市查询还存在自动修改生产队列的副作用，战斗估算会把有条件的晋升加成直接相加。

用户要求按已建议顺序修复这些问题，完成离线测试，再从已保存的第 30 回合继续到第 50 回合，保留新结果且不 push。此次延续的唯一存档来源仍是用户原始 `benchmark_turn_1` 对局；第 30 回合只是这轮已验证身份的继续点，不替代原始基准。

## Solution

保持现有 MCP → GameState → Lua → FireTuner 调用链。先保证每条请求只接收自己的完整响应，再让查询无副作用、完成事件以真实产物为依据，随后补足区域拒绝与移动停步证据，最后让战斗估算尊重加成条件。

继续保留单次提交、有界只读确认和未知结果门禁。可靠证据不足时明确未知，不自动重发、清空 pending、增加固定等待后冒充成功。通过现有工具解决正常游戏决策，只有明确的技术故障才显式恢复。

## User Stories

1. 作为模型客户端，我希望请求与响应准确对应，以便不把上一条请求的结果当作当前事实。
2. 作为模型客户端，我希望旧式 Lua 结束标记不会污染下一次调用，以便按已有工具说明调用时不会破坏连接。
3. 作为维护者，我希望只有一层负责请求完成边界，以便修改包装器时不再制造双重结束。
4. 作为玩家，我希望丢失或异常回应明确返回未知，以免未确认动作被重发。
5. 作为模型客户端，我希望空查询和错位响应能够区分，以免把通信异常判断为无城市、无单位或战败。
6. 作为维护者，我希望传输断线、超时、取消和 Lua 错误均保留既有单次提交约束，以免回归为隐式重放。
7. 作为玩家，我希望查询城市不会删除生产项目，以便读取状态不改变对局。
8. 作为模型客户端，我希望零 hash 或异常队列被如实报告，以便决定是否需要显式处理。
9. 作为玩家，我希望学院只有实际完成才被宣布完工，以免按不存在的产物继续决策。
10. 作为模型客户端，我希望转产、中断、队列失效和完成有不同描述，以便选择正确操作。
11. 作为玩家，我希望新建单位和建筑的完成消息有真实产物依据，以免仅因队列变化便误报。
12. 作为模型客户端，我希望区域顾问只把原生可用目标列为可执行候选，以免位置建议与提交条件冲突。
13. 作为模型客户端，我希望区域提交保留坐标和拒绝原因，以便知道问题来自地貌、科技、占用还是证据不足。
14. 作为玩家，我希望明确未提交的无效落位被直接拒绝，以免普通规则约束要求整局重启。
15. 作为模型客户端，我希望可能已提交的落位仍有只读确认，以免原生状态短暂未变便被判定为失败。
16. 作为玩家，我希望同城依赖操作不会越过未确认生产，以免转产或购买掩盖原动作结果。
17. 作为模型客户端，我希望移动返回真实位置、行动力和执行状态，以便识别回合内停步。
18. 作为玩家，我希望剩余行动力不足支付下一步、受阻或命令已停止时有可靠原因，以免长期挂在未知。
19. 作为模型客户端，我希望路径中的回合标签不能单独替代实际操作证据，以免再次误判停步。
20. 作为玩家，我希望移动结果仍未知时不自动重发或强制结束回合，以免错误传播。
21. 作为模型客户端，我希望能通过现有只读工具重新确认未知结果，以免连接正常被误认为动作已完成。
22. 作为玩家，我希望远程防御晋升不被算进近战进攻，以免伤害估算误导战术。
23. 作为模型客户端，我希望无法可靠评估的加成明确列为未知，以免估算数字假装覆盖全部规则。
24. 作为玩家，我希望估算与真实伤害继续分开，以免将击杀预测当作击杀事实。
25. 作为维护者，我希望既有离线边界能够重现这些故障，以便不靠反复操作真实游戏开发。
26. 作为玩家，我希望只加载已确认的第 30 回合命名检查点，以免混入旧地图或其他轮次。
27. 作为玩家，我希望最终第 50 回合对应 20 个净推进，以免将恢复重玩的回合重复计数。
28. 作为维护者，我希望逐回合记录墙钟、动作、阻塞及恢复，以便区分引擎耗时与诊断耗时。
29. 作为玩家，我希望正常战争、外交、市政、生产及总督选择由模型处理，以便 Runtime 不替我选择玩法。
30. 作为玩家，我希望原始基准、此前结果和第 30 回合存档不被覆盖，以便之后复验。
31. 作为玩家，我希望保留独立命名的第 50 回合结果，并实际验证最终保存恢复，以便成果可继续使用。
32. 作为维护者，我希望提交与审查集中在一个集成分支且不推送，以便本地结果可审阅。

## Implementation Decisions

### 保持职责和实施顺序

- 沿用领域工具名称与参数、单客户端 FireTuner、MCP 串行调用及现有未决状态；不增加后台任务平台或第二条游戏控制链路。
- 按顺序实施：响应归属 → 查询副作用及完成判定 → 区域落位 → 移动停步 → 晋升条件估算 → 全量验证与双轴审查 → 实机验证。
- 每项在基于最新集成分支的独立 worktree 实施并按 TDD 逐个行为推进，由 merger 合并。共享模块的修改顺序串行，独立原生接口调查可以并行。

### 请求响应边界

- 完成边界由连接执行层统一负责，并绑定当前请求，不能仅用所有请求共享的裸结束文本判断归属。
- 兼容现有构造器和原始 Lua 中的旧结束打印；旧标记作为普通遗留输出处理或在统一边界内忽略，不能提早结束当前请求，也不能遗留污染下一请求。
- 原始 Lua 工具说明与实际包装行为一致。调用方只提供代码，不再被要求自行负责传输完成标记；保留尾部 return 的合法性。
- 不通过 sleep 或无界 drain 猜测回应完整。总截止时间覆盖确认开销。异常、取消及边界不完整废弃不可信连接，不自动重放可能已执行的命令。
- 握手、发现 Lua 上下文、MainMenu 读档与普通 GameCore／InGame 操作仍保持各自上下文约束。

### 查询与完成事件

- 城市查询、回合快照和列表读取不能修改生产队列或发起玩法操作。移除读取时自动删除零 hash 项的路径；异常只记录事实。
- 队列变化不等于完工。区划、建筑和单位分别使用可靠的实际产物证据；缺失证据时只报告队列变化、中断或未确认。
- 完成证据属于同一对局、同一城市和目标项目。旧建筑、已存在区划、其他城市同类型单位或身份不符不得生成新的完成消息。
- 新增完成观察如需扩展既有快照类型，只添加对应事实字段，不建独立状态库或事件平台。保存和 end_turn 不因此增加隐式生产修复。

### 区域落位

- 核实原生目标返回的字段语义，区分可用位置、其他结果和失败原因，不能合并所有表字段当作候选坐标。
- 按目标城市、区划及精确坐标检查提交条件，并保留能够确定的地貌、科技、归属、已存在区划等拒绝原因。不得未经原生依据认定上轮雨林失败就是缺少某项科技。
- 对可靠的未提交拒绝直接返回原因并结束该意图；不能先发明知无效的请求再进入永远无法确认的 pending。
- 可能已提交或读回丢失仍只读核对。目标项目和位置匹配后才确认，其他位置同类型区划不能误证成功；不得自动重发。

### 移动停步

- 以捕获的第 22 回合观察序列为回归输入：已移动、剩余 1 点、引擎空闲、下一路径标签仍为当回合；保留它与真实原因尚未确定的区别。
- 优先核实引擎原生操作／活动状态和实际下一步可执行性，再选择最小有效停步依据。不能把引擎空闲、重复旧位置或路径标签本身升级成完成保证。
- 到达、中途停步、明确未提交拒绝与未知保持不同语义；只报告真实位置和行动力，不冒称耗尽或到达目标。
- 同一移动意图只提交一次；查询、确认及依赖门禁继续沿用既有机制。若平台不能提供某项信号，保留未知并明确限制，不用私有状态清零绕过。

### 战斗估算

- 晋升加成必须按攻击方／防御方、近战／远程、目标与规则条件处理。不能把全部 Modifier Amount 无条件累加。
- 优先使用已核实、平台可用的原生战斗评估；若无法可靠计算某些条件，明确省略该数值并列为未知，不制造覆盖全部规则的总和。
- 保留攻击方式一致性、战后真实观察和未知击杀边界；不要求估算等于随机真实伤害。

### 第 30～50 回合验证

- 唯一继续点是 `benchmark_turn_30_20261017`，700199 字节，SHA-256 `9b184d5967551215106c4b5ab3e9c3d25bf6309983ae95602c3cd07439a1343b`。加载前核对文件指纹和原有轮次记录，加载后核对苏美尔、种子 `719665280`、第 30 回合、城市与单位关键状态。
- 这是用户明确授权的同一原始对局延续，不创建新基准，不旋转成别的地图，不加载旧自动存档或其他轮次兜底。
- 全套离线检查及独立 Standards／Spec 审查通过后，才执行真实 stdio MCP，逐回合查询与决策，第 30 → 第 50 回合计为 20 个净推进。
- 计数前验证修复后的原始 Lua 紧邻查询无串位；自然对局可遇到的移动、转产、区域、攻击及正常决策要记录实际覆盖。不能用固定跳过脚本代替模型决策，不能人为制造损坏或改变地图规则。
- 每个将推进的回合保留独立命名、已确认的同轮检查点。技术故障每次最多一次完整恢复、最多回退 1 回合；未保存动作可能被撤销，重玩不重复计数。不为战损、战争或劣势读档。
- 计数期间不修改代码或重启 MCP 掩盖问题。如果需要修源码，停止该次验收，修正并完成离线检查后重新从受保护的第 30 回合开始完整计数，保留失败尝试。
- 最终第 50 回合使用独立名称保存，确认原生保存完成、文件和身份回合，再显式重启恢复该最终检查点，比较城市、单位等关键状态，回退为 0。
- 保留原始基准、两份第 21 回合结果及第 30 回合继续点；新结果和过程文件分别保留／归档。未达到第 50 回合或仍有未解决未知时，明确报告未通过对应门槛。若自然战败则报告终局事实，不能通过修改游戏或为战局回档凑回合。

## Testing Decisions

复用此前已确认的 GameState／FakeConn、内存 FireTuner 字节流、现有快照差分、MCP 入口及隔离临时存档目录。用户已再次明确确认沿用这些边界；没有新增游戏控制实现。优先通过公开接口验证结果、动作次数和后续可操作性，避免仅检查生成文本包含某个函数名。Lua 原生字段真实性结合本机随附源码调查与修复后的实机观察核实。

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| S01 | 原始 Lua 包含旧结束打印，随后调用查询 | 当前结果完整，下一条只得到自己的响应，无遗留空回应 |
| S02 | 异步旧结束、其他请求的结束或额外输出 | 不提早完成当前请求，不把错位当作正常空查询 |
| S03 | 尾部 return、无输出、Lua 错误、超时、取消 | 按契约完成或失败；异常流废弃，命令只发一次 |
| S04 | MainMenu／GameCore／InGame 上下文和重新连接 | 上下文正确，边界修复不破坏显式加载及既有连接测试 |
| S05 | 城市生产零 hash、异常队列或普通读取 | 查询不发生产修改；如实报告异常，不删除条目 |
| S06 | 队列清空、换项、取消、读取缺失或身份不符 | 不生成无证据的完成消息 |
| S07 | 区划实际完成、建筑出现、城市真实产出单位 | 仅对匹配的新产物报告完成；旧产物或其他城市不误证 |
| S08 | 原生目标列表含多种表字段、有效及无效位置 | 只返回明确可用候选；完整保留可靠拒绝事实 |
| S09 | 区域目标不能开始且请求尚未提交 | 明确拒绝，提交次数为 0，下一合法操作不被假 pending 挡住 |
| S10 | 区域提交后延迟、掉线、错误位置或同类型旧区划 | 不重发；匹配位置证据确认，证据不足保留未知和依赖门禁 |
| S11 | 移动旧位置→中途→到达，以及原生忙碌 | 不提早确认，不误报耗尽，提交一次 |
| S12 | 剩余行动力、当回合路径标签与可靠原生停步证据 | 只有可靠操作／可执行性证据才确认真实停步；证据缺失继续未知 |
| S13 | 移动读取缺失、身份变化、活动状态不明 | 未知不因重连被抹除，end_turn／保存／依赖操作不能越过 |
| S14 | 远程防御晋升、近战进攻、受伤目标及未知条件 | 不误加无效数值；无法判定条件明确未知，实际伤害独立回读 |
| S15 | 上轮保存、原始基准保护、轮次、end_turn／外交契约 | 保留全部既有回归行为；不重启、重放或代选玩法 |
| S16 | 真实第 30 → 第 50 回合及最终保存恢复 | 20 个净推进和最终匹配均有实机证据；未知、拒绝、正常阻塞和恢复分别统计 |

逐项采用一个失败行为 → 最小修复 → 对应通过的 TDD 循环。全量验证沿用锁定依赖安装、仅 tests 的离线 pytest、编译及差异检查。离线脚本不得连接真实游戏或修改真实存档；既有 575 项不是本轮完成凭据，应报告新的实际成绩。

## Out of Scope

- 不 push、不创建远端 issue／PR，不发布文档。项目尚未配置 issue tracker；采用本地 `ready-for-agent` 规格与依赖工作项，后续可运行 `/setup-matt-pocock-skills` 配置。
- 不增加云同步、网页、后台监控、自动评测平台、通用任务账本、策略代理或新的游戏控制通道。
- 不自动购买、不替模型选择外交／总督／市政／生产，不为演示篡改胜负、回合数或地图规则。
- 不将未知一律改判成功或拒绝，不通过盲目重试、额外固定 sleep、透明重启或丢弃 pending 伪造连续推进。
- 不承诺所有平台兼容、伤害精确预测、必胜或固定每回合耗时。自然对局没触发的故障只报告离线覆盖。
- 不复用其他地图／历史轮次的恢复存档，不覆盖本轮第 30 回合或既有基准与结果。
