# 保存与恢复

保存、加载、断线、挂起或结果未知时读取本指南。新测试核对[唯一测试基准](../fixtures/saves/README.md)及其 JSON 清单；日常动作流程见[游戏操作](agent-playbook.md)。

## 选择入口

先核对当前任务的授权、是否有未决操作，以及目标检查点的来源。菜单换档与完整重启都会丢失保存后的操作。

| 当前情形 | 入口及完成依据 |
| --- | --- |
| 正常保存当前对局 | `save_game(save_name)`；原生完成事件、新鲜非空文件、保存前后身份与回合均通过确认。 |
| 游戏响应正常，需要换档 | `reload_game_save(save_name)`；返回主菜单、保持进程，再完整验证目标。未决动作、保存、加载或推进须先确认。 |
| 已在主菜单，需要加载 | `load_game_save(save_name)` 或 `load_save_from_menu(save_name)`；已有列表索引可用 `load_save(save_index)`，复用同一确认流程。 |
| 游戏进程挂起、失联或菜单路径无法确认，需要完整恢复 | 在当前任务明确授权范围内调用 `restart_and_load(save_name)`；目标必须是已确认检查点，完整重启是显式入口。 |

旧菜单加载入口不自动退出正在进行的对局。菜单路径失败不自动升级为完整重启；不以 OCR 或鼠标操作绕过原生 FrontEnd 读档。

## 检查点与测试轮次

- 每次验证加载 `benchmark_turn_1` 原件会建立新测试轮次；MCP 重启和本轮检查点恢复保留轮次标识。
- 检查点绑定文件指纹、文明、种子、回合和本轮标识。恢复前必须能核实这些记录，不能按修改时间猜测「最新自动存档」。
- `save_game` 可覆盖同名普通存档，过程和结果必须取独立名称。原始基准与已保留成果不作为覆盖目标。
- 保存未知时，先核对文件和游戏事实，不重发写入。未决动作或推进不能被保存操作越过。
- 从第 1 回合净推进 20 回合的结果为游戏第 21 回合，第 50／100 回合结果也属于验收成果，不是新基准；[对应记录](README.md#规格与验收)只在核对该次结果时读取。
- 用户要求继续已有验收时，只使用该次同一对局、同一轮次的已确认检查点。旧轮次文件保留供查阅，不作为当前恢复来源。

## 结果未知

1. 保留工具返回的原请求、对象和已观察事实；停止依赖其结果的写入。
2. 读取对应事实：单位／城市状态、议会状态、当前对局身份、回合和目标文件。一次重连、固定等待或读取到旧状态都不能释放门禁。
3. 原动作或推进仍能确认时，只确认已有请求。普通身份查询发现不同对局时，只清观察缓存；旧推进保持未知，新对局较高回合或终局不能确认它。
4. 仍无法确认时，报告当前阻碍和可用检查点，按当前授权选择显式恢复。加载、退出或保存未知时不重复提交；需要完整重启的授权已包含在任务中时，无需重复确认。
5. 恢复工具报告完整验证通过后，重新调用 `get_game_overview`，再读取单位和城市，确认后续动作的依据。

## 加载完成条件

- 菜单返回上限为 30 秒，计入加载总预算 180 秒；退出和加载各最多提交一次。
- 主菜单依据原生 `UI.IsInFrontEnd`，仅发现 MainMenu／GameCore 索引不算完成。
- 加载须核对目标文件、文明、种子、回合、本地玩家就绪和本次完整新快照；最终回读仍须一致。
- 清理旧缓存和普通身份查询期间，未确认替换的门禁持续保留。原生加载调用进入后抛错只能视为未知，不能推断未提交。
- 超时、取消或读取瞬断不会透明重放退出／加载。先保留状态并核对事实，再选择显式恢复。

排查状态归属、原生见证或结果类型时，再读[当前架构](architecture.md)的对应章节。
