# 对局复盘与因果归因

赛后先定位胜利链条上领先或落后的形成阶段，再解释决策。复用已有验收快照和原生动作记录；不增加 Runtime 自动策略、后台采集或每回合强制表单。操作中的策略判断见[获胜决策](agent-strategy.md)。

## 分析顺序

| 步骤 | 要回答的问题 | 保留的结果 |
| --- | --- | --- |
| 1. 固定口径 | 是哪一局、什么配置、哪个受测版本？比较的回合和指标是否一致？ | 轮次、种子、版本、难度、速度、规则／模式；恢复和重复调用单独标记 |
| 2. 定义终点 | 原生胜利条件是什么？对手最可能先完成哪条路线？ | 本方终局事实、对手进度、当时可判断的竞争窗口 |
| 3. 对齐里程碑 | 双方差距最先在哪个阶段形成，之后扩大还是缩小？ | 解锁、具备执行条件、实际开始、完成的回合；首次观测与发生回合分开 |
| 4. 定位瓶颈 | 当时卡在解锁、建设准备、分配、施工、资源还是交互？ | 最多三个按解释力排序的假设，列支持证据和缺失证据 |
| 5. 检验归因 | 去掉某次操作，是否会推迟终点？有没有同样能解释结果的其他原因？ | 直接效果、条件化估计、待验证推断分别记录 |
| 6. 提炼经验 | 什么条件下应重新考虑此类行动，什么观察会推翻结论？ | 条件—机制—候选行动—预期信号—失效条件—证据链接 |

原生科技数量、总产能、城市／区域／伟人数量是解释变量，不直接代替胜利进度。文化胜利看旅游积累和动态游客门槛，外交胜利看点数及下一得分机会；研究文化和外交支持都不能直接替代这些目标。

## 用关键路径解释时间

科技胜利的链条是关键科技与城市准备 → 卫星 → 登月 → 火星 → 系外发射 → 飞行到达；加速项目改变飞行速度。各阶段可能在不同城市准备，不能把所有建设和研究时长简单相加。

对每个项目分别核对：

```text
最早可开工 = max(所需科技就绪、前序项目完成、城市／区域就绪、其他必要资源就绪)
实际完工 = 最早可开工 + 调度等待 + 实际施工时间
飞行到达 = 累计原生每回合有效速度达到本局门槛
```

施工包含普通产能、政策／总督修正、伟人、劳动力贡献等一次性推进，以及战争、损坏或供电造成的变化。未被原生确认的动作不计为已完成投入；实际费用与项目成本采用该局回读。

只有提前某项任务会提前后续终点，它才是当时的关键瓶颈。更早造好一个仍在等待科技的项目，不一定提前胜利；保留伟人等待更昂贵的项目，也不自动视为闲置损失。

### 分开四种原因

| 层次 | 内容 | 分析约束 |
| --- | --- | --- |
| 外部条件 | 地图、难度、文明能力、随机树、伟人顺序、灾害和竞赛机会 | 记录实际生效条件；收益来自机会还是主动利用机会分别解释 |
| 决策 | 路线、关键科技选择、城市分工、伟人保留、资源和外交安排 | 依据决策当时已知信息，不能用赛后信息替当时决策打分 |
| 执行 | 开始时点、真实投入、队列等待、资源不足和状态回读 | 区分想做、具备资格、已提交、已完成；能力数量不代表实际投入 |
| 工具与观测 | 错误候选、结果未知、重复确认、弹窗和恢复 | 墙钟等待与净游戏回合分开；没有推进回合的程序停顿不能直接折算为战略落后 |

胜利不能反向证明所有决策正确。错误决策也可能被其他优势补偿；不利随机事件也不证明策略错误。对手未公开的排产、解锁或损坏原因保持未知。

## 证据与反事实

| 等级 | 可以陈述什么 | 证据示例 |
| --- | --- | --- |
| A：直接观测 | 动作、前后状态和原生结果绑定，可以确认直接效果 | 萨根激活后，当前系外项目完成；明确劳动力消耗及项目推进 |
| B：机制支持的推断 | 规则和时序支持解释，但仍存在未控制因素 | 项目集中投入有助于较早发射；不能据此分配整场胜利的贡献百分比 |
| C：待验证假设 | 缺少能区分候选原因的记录 | 对手究竟晚解锁、晚排产，还是施工／资源受限 |

优先检验最能解释关键时点差距、已有直接证据且容易被推翻的假设，不填写虚构的概率或贡献百分比。

- 原生「预计 17 回合」是当时估时。实际当回合赶工完成证明了直接效果，不能直接解释为「净节省 17 回合」；没有该伟人时，政策、劳动力投入、城市选择和对手行为都可能改变。
- 固定状态外推要写清不变条件。T230 飞行 28／33.5、速度 1，若保持该速度且无其他变化，约 T236 到达；实机 T233 获胜。它只给出这一固定情景下约 3 回合的到达差，不能推出整场贡献或延后仍会获胜。
- 多项行动共享瓶颈或存在前后依赖，节省回合不能分别估算后直接相加。
- 一个种子的单局结果只能产生机制案例和待复验判断。后续需要时，在单独授权的新对局中验证；不为凑因果证据改写已完成主线或回档挑选战果。

## 记录模板

每局复盘放入[所属对局与轮次](../games/README.md)的 `reports/`，引用原始日志；稳定方法保留在本页。周期数据复用已有阶段检查，只在改变路线、关键解锁、伟人使用、关键项目完成、对手进度变化或重大干扰时补事件，不机械扩充逐回合记录。

```text
对局：轮次／种子／版本／难度／速度／规则与模式
结果：原生终局／回合／来源
核心问题：需要解释的具体时间差或进度变化

任务 | 主体 | 可执行回合 | 实际开始 | 完成／观测区间 | 投入与干扰 | 原生证据

关键决策：当时已知事实／候选／所选行动及理由／预期信号／实际结果
归因：首要假设／证据等级／竞争解释／缺失字段／可推翻信号
反事实：改变一项什么／固定什么／估计范围／未控制因素
经验：适用条件／机制／候选行动／预期结果／失效条件／来源
下一次验证：最小观察或比较；无新实机授权时仅列待办
```

知识分层沿用现有目录：`civ6_knowledge/` 保存版本绑定的规则；验收记录保存具体对局事实；只有被证据支持的条件化判断才进入策略指南。不能把一局的文明、回合数或伟人名字直接固化成 Runtime 行动。
