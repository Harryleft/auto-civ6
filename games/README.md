## 新资料放在哪里

每局使用稳定的目录名，如 `<开始日期>-<文明或对局标识>/`。同一地图从原始存档重新开始时，使用独立的 `runs/<日期>-<轮次标识>/`；文明和种子相同不等于同一测试轮次。索引至少写明基准来源、已知身份／种子、轮次、结果和证据位置，缺失字段保持未知。

```text
games/<对局>/
  README.md                 对局身份、轮次和结果索引
  runs/<轮次>/
    README.md               本轮范围、阶段入口和证据位置
    reports/                回合过程、实机验收和复盘
    changes/                本轮产生的修复规格、工作项及审查记录
    team-sharing/           基于本轮的分享稿、图表和交付核对材料（按需）
    evidence/               本地原始日志、截图、存档副本等，不默认提交 Git
```

没有重新开局的对局可以直接使用 `reports/`、`changes/` 和 `evidence/`。轻量报告与清单纳入 Git；大型存档、原始日志和截图默认保留本地，在报告中记录位置和必要指纹。现有原始证据仍保存在报告记载的 `~/.civ6-mcp/acceptance/` 等位置，本次仅整理仓库内文档，没有迁移或覆盖这些文件。

后续资料沿所属对局、轮次追加；可复用的机制、接口约束和操作方法整理回 `docs/`。历史报告内的旧分支状态、命令和待办属于当时记录，不构成启动旧地图、恢复旧检查点或重做游戏操作的授权。新实机测试仍遵守[受信基准与检查点规则](../docs/agent-recovery.md#检查点与测试轮次)。
