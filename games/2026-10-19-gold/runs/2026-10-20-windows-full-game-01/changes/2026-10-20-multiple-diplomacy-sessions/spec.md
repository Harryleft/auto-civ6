# 安全处理多个同时开放的外交会话

状态：已修复并验收。用户已明确认可测试入口，并进一步授权后续阻塞自行诊断、修复和测试后继续游戏，无需等待 implement-spec。公开 MCP／GameState 与实际 Lua 相关测试 300 项通过，本轮 Windows 实机已确认第 22 → 23 回合。

## 问题陈述（Problem Statement）

用户要求在 Windows 上实际运行一局神级游戏直到原生终局，并在程序阻塞时记录现场、生成修复规格，待 implement-spec 修复后继续同一轮次。

当前轮次第 22 回合同时遇见巴西和加拿大。公开外交工具连续返回 `UNKNOWN: MULTIPLE_SESSIONS`，没有可验证的对话或按钮，结束回合受阻。代理既无法正常作答，也不能根据猜测选择一个领袖、自动退出或强行推进。

## 解决方案（Solution）

当存在多个开放会话时，从原生证据确认当前可交互会话及其参与方，只向该会话展示、提交经验证的选项。处理完成后重新观察，再处理剩余会话。若原生证据仍不足，则保留 UNKNOWN 并解释具体缺失，禁止错配与隐式兜底。

修复完成后，在保留的第 22 回合现场验证两个会话可被依次处理，解决真实研究选择要求，确认可进入第 23 回合，再继续原对局。不得为了展示成功换到新开局。

## 用户故事（User Stories）

1. 作为对局操作者，我希望同时遇见两个文明时仍能读取当前外交对话，以便继续合法推进。
2. 作为对局操作者，我希望每组按钮都有经验证的会话和玩家归属，以便避免回应错误领袖。
3. 作为对局操作者，我希望只看到当前实际可选择的响应，以便依据真实提案作出决定。
4. 作为对局操作者，我希望处理第一个会话后重新读取第二个会话，以便不把旧按钮用于新对话。
5. 作为对局操作者，我希望会话选择不依赖枚举顺序，以便玩家编号或队列顺序变化时仍正确。
6. 作为对局操作者，我希望交易与普通对话共存时分别确认上下文，以便不会把缓存交易误读为当前要求。
7. 作为对局操作者，我希望原生证据不足时工具仍返回明确 UNKNOWN，以便不因修复而失去现有保护。
8. 作为对局操作者，我希望只读查询不产生选择、响应或关闭会话，以便观察不会改变游戏决策。
9. 作为对局操作者，我希望响应对象与当前会话不一致时拒绝操作，以便旧请求不会影响后来出现的对话。
10. 作为对局操作者，我希望响应结果不确定时只确认原请求，以便不会重复提交外交决定。
11. 作为对局操作者，我希望所有待处理会话完成前不能误报回合推进，以便回合状态保持可信。
12. 作为维护者，我希望单会话和真正歧义场景继续通过已有公开行为测试，以便不回归既有外交与交易能力。
13. 作为维护者，我希望测试执行实际生成的 Lua 并核对外部结果与副作用，以便避免仅检查代码文本的脆弱测试。
14. 作为 Windows 用户，我希望用当前实机阻塞现场验收，以便修复确实适用于此次运行环境。
15. 作为同时使用 Mac 和 Windows 的用户，我希望共享逻辑不增加单平台假设，以便保持双平台接口兼容。
16. 作为用户，我希望修复后继续本轮第 22 回合，以便已经完成的探索和建设得以保留。
17. 作为用户，我希望区分修复通过与整局结束，以便看到准确的完成状态和剩余问题。

## 实现决策（Implementation Decisions）

- 修改共享外交上下文解析、必要的模型与叙述，以及响应前的会话核验；优先保持现有公开 MCP 名称与调用约定。
- 多个开放会话本身不等于当前 UI 无法确定；只有原生证据能把当前可见视图、会话标识、参与方和响应选项唯一关联时，才允许将该会话标记为可操作。
- 实现前先核实游戏实际提供的会话／视图关联证据。若现有接口无法取得，提出最小必要的原生适配方式；不得伪造“当前会话”或直接选取候选列表首项。
- 当前会话、待处理候选集合和当前交易内容须有清楚边界。历史工作交易、相同文本、玩家编号、可见按钮本身均不足以独立证明会话归属。
- 响应必须验证调用对象与当前会话一致；视图切换、会话更换或对象不符时重新观察，不能继续使用旧选项。
- 每次明确提交只处理一个经确认的原生选择；没有明确授权的批量接受、退出或延迟自动选择不属于修复。
- 保留现有结果不确定请求的确认语义，不借新增会话处理绕过重复提交保护。
- 结束回合仍以原生状态确认；修复外交之后应继续识别真实科技选择等普通要求，不能把清除一个阻塞当作所有要求已完成。
- 不增加游戏资源、科技、胜利状态或隐藏信息的写入；不以重启、自动重载或自动关闭全部弹窗代替会话处理。
- 保持共享逻辑对 Mac 与 Windows 的兼容，不要求额外开展 Mac 模拟测试。

## 测试决策（Testing Decisions）

- 首选最高的现有入口：公开 MCP／GameState 外部行为测试，沿用现有执行生成 Lua 的测试设施。以返回状态、真实响应归属、调用次数及原生副作用作为断言，不检查源码字符串。
- 覆盖两个有效开放会话但只有一个当前视图可唯一关联的场景；改变枚举顺序仍应选对，处理一个后应能读取并处理另一个。
- 覆盖真正无法关联、参与方失效、UI 过渡、冲突视图、缓存交易与当前对话不一致等情况；保留 UNKNOWN，且不得提交响应或关闭会话。
- 覆盖对象不匹配、读写间会话切换和响应确认重试，验证没有错误对象操作与重复提交。
- 回归单会话对话、交易、结束回合等待与确认工作流；复用已有测试入口，避免为每种场景引入新的测试专用接口。
- 实机验收复用本轮 Windows 第 22 回合，记录处理两位领袖的原生前后状态及请求证据；选择合法下一科技后确认第 23 回合。存档重载是否恢复外交队列必须实测，不能因保存成功就认为成立。
- 无需为本次任务添加 Mac 模拟用例；修改须保持已有跨平台接口，所做验证与未做验证应如实报告。
