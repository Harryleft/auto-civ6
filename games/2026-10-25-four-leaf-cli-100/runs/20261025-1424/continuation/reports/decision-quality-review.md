# T225 决策质量复核

本局策略质量差的主因是任务控制器把功能验证替代了获胜决策。CLI 的真实缺陷增加了执行摩擦，但不能解释无城址仍反复生产开拓者、主动退回旧政体，以及发现能力差距后缺少应对。

2026-10-25 在 T225 停止原简化控制器，保留持续 CLI、游戏现场和检查点；没有为纠正战略失误回档。首次复核时为 3 城、33 人口、4 开拓者、3 建造者、6 骑士、2 弩手、1 大商人；单位维护费 30 金币/回合。苏美尔科研 88.2、文化 34.7，公开对手科研 245.7～304.4、文化 255.8～513.1。本方外交 9/20 点，作为当时尚可争取的路线重新评估；科技、文化与征服需要的准备远未形成。

## 决策错误及机制

| 问题 | 可核对事实与机制 | 归属 |
| --- | --- | --- |
| 功能验证替代争胜 | 临时控制器用固定科技、市政和生产优先表，未命中时取第一个候选；胜利进度没有进入这些选择的判断条件。排名虽读取，未持续驱动资源调整。 | 本任务的模型与控制器选择 |
| 政体回退 | T130 主动改君主制；T165 简化脚本遇政体提示，按旧兜底规则优先选古典共和。原请求 seq 8002，原生返回 seq 8003 为 `GOVERNMENT_CHANGE_STARTED`，无政府状态持续至 T168。T204 才改商人共和国。 | 客户端明确发出的错误选择，非 CLI 自行改政体 |
| 开拓者积压 | 早期生产兜底遍历单位／建筑候选并取首项，单位列表首项为开拓者。开拓者无近域城址即休眠；探索、全图候选、可达性和后续生产缺少联动，最终积压 4 名。 | 简化策略与反馈缺失 |
| 军备与发展失衡 | 战时按军队数量补兵；早期战斗主要比较血量，缺少兵种代差和交换收益判断。长期保留中世纪军队，科研、文化与产能设施投入偏晚。 | 模型的机会成本与战术判断不足 |
| 观察未转为反制 | 对手太空港、旅游与外交点数已公开，仍主要处理本地待办和静态建设，没有及时准备外交支持、间谍或其他有效干预。 | 未落实项目策略检查清单 |

## CLI 与规则的影响

- 政策部分提交、非斯使者确认失败属于已经复现并修复的运行层问题。修复后的 T102→T225 已确认连续推进 123 次，无重复区间、没有续推加载恢复；早期阻塞不能解释后续长期资源错配。
- T213 议会曾返回 `OUTCOME_UNKNOWN / CONTINUE_REQUESTED`。未重投；随后原生阶段读到 FINISHED，原推进确认到 T214，后续核对运行层 congress pending 为 false。该暂态必须计入执行报告。
- 伟人建议未返回资料，研究显示与原生研究待办不一致，生产队列出现零项目 hash 等仍需记录。它们影响事实获取和控制器健壮性；不能把明确由客户端选择的错误归给这些缺陷。
- 项目要求 CLI 唯一入口、变更预演、单次提交、未知时只读核对和保留检查点。这些规定不指定胜利路线、科技顺序或生产对象。
- 通用的持续推进要求不要求降低策略质量，也不要求以低质量脚本凑到终局。项目禁止新增强制反思／日记协议，与现有策略检查清单要求的局面判断并不冲突。

[策略检查清单](../../../../../../docs/agent-checklist.md)要求每个已确认回合更新目标与威胁，关键变化后重评，并形成当前优先目标、提前准备的能力和下一行动。本局进行了查询，但没有持续落实这三个决策结论。该轮可用于 CLI 行为验证，不能据此评价模型按完整战略流程对局的能力。

## 后续执行边界

原 `.scratch/end_driver.py` 控制器已停止，临时通用策略脚本和相关缓存已移除，不再用候选首项、固定数量阈值或旧政体兜底替代战略判断。保留当前失败积累，策略由模型依据公开局面决定，辅助脚本只承担无策略的操作与证据处理。原始基准、历史结果和运行层修复提交 `6e87e2a` 保持不变。

此后仅在同一 T225 调整市政、夺回非斯宗主权、进行四档未成交试价并激活大商人。用户随后明确结束本局，原续推至终局的计划随之取消；已另存收尾检查点、通过只读验收并正常退出 CLI，没有继续推进。

完整复核快照及政体原请求见 [decision-quality-snapshot.json](decision-quality-snapshot.json)，命令原始证据见 `../evidence/relay/cli/debug.jsonl`。已移除的临时控制器与生产兜底原位于 `.scratch/end_policy.py`、`.scratch/cli100_policy.py`；它们不是已提交的 CLI Runtime 策略，实际行为以保留的原请求为证据。
