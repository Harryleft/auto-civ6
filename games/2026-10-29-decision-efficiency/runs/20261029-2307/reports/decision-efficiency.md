# 决策效率与质量：实施及四叶草验证

同一局面的五项常用查询已合并为一次 `state decision`。七组实机对照的 35 份领域报告逐项一致；排除两个新 CLI 首次概览样本后，五组配对查询的 RPC 耗时中位数从 0.483172 秒降至 0.184889 秒，减少 61.7%。模型从 T1 净推进 10 回合至 T11，完成新单位、科研和市政完成后的选择及政策配置。没有编写策略循环或自动对局脚本。

## 架构中实际发现的问题

| 问题 | 当前证据 | 本次处理 |
| --- | --- | --- |
| 模型需要自行拼接多个工具返回的事实 | 原只读验收快照只有本方身份、概览、单位和城市；日常决策另查排名、威胁、通知与候选。`get_units` 还隐式读取威胁和商路 | `decision.py` 组合原有 getter，一个有界请求返回决策事实；按需补充研究、外交、贸易及指定城市的生产候选 |
| 结果中有完全重复的文本 | MCP `content[0].text` 与 `structuredContent.result` 相同，CLI 原样输出两份 | 可选 `debug --compact` 删除严格重复字段；错误、多媒体和其他结构化字段保留，原响应另存 |
| 机械提示替模型表达选择偏好 | T1 零科研产出时科技回合数为 `-1`，旧显示仍附 `GRAB THIS` | 负回合数显示 `turns unknown`，未知排在已知之后，删除科研／市政的固定推荐提示 |
| 原始事实分类错误 | T5 真实蛮族长矛兵被标成 `is_city_state=true` | 分开蛮族与城邦；T6 相同现场重新读取，修复后为 `false`；Lua 5.1 测试覆盖大国、交战城邦、蛮族和迷雾过滤 |
| 安全规则可产生机械成本，但不能随意取消 | 动作、回合、外交及存档各有原所有者和未决门禁 | 新入口在游戏 I/O 前拒绝全部 pending；不改变单次提交和原生确认，不另建状态所有者 |

实现位于 [decision.py](../../../../../src/civ_mcp/decision.py)、[CLI 输出](../../../../../src/civ_mcp/devtools/debug.py)及原有领域展示／查询。使用方式见[决策事实查询](../../../../../docs/cli.md#决策事实查询)。已有单项查询继续适用于只缺一项事实的决策，避免每次都重新取全套数据。

## 同局面对照

原路径：`state overview`、`unit list`、`city list`、`ranking show`、`notifications show`。新路径先用 `game decision --include trade --view structured` 取得数据，再用原有领域展示函数重建五份报告，逐项与原路径比较；紧接着读取默认简报以计时。两种路径均启用 `--compact`，使合并请求的收益与删除重复文本的收益分开。

| 回合／现场 | 旧五项 RPC 合计（秒） | 新默认简报（秒） | 报告一致 |
| --- | ---: | ---: | ---: |
| T1，未建城，首次概览 | 1.120647 | 0.173690 | 5/5 |
| T2，一城一勇士 | 0.487888 | 0.172740 | 5/5 |
| T4，城市增长 | 0.514358 | 0.172039 | 5/5 |
| T5，已发现蛮族长矛兵 | 0.468133 | 0.188164 | 5/5 |
| T6，分类修复后，新 CLI 首次概览 | 1.087536 | 0.169584 | 5/5 |
| T8，新侦察兵与生产待办 | 0.483172 | 0.187817 | 5/5 |
| T10，政策及市政待办 | 0.465870 | 0.184889 | 5/5 |

原始指标见 [comparison.json](comparison.json)。T1、T6 的首个概览会初始化既有回合差分基线，未纳入稳态中位数；其余五组命令数从 5 次降至 1 次。35/35 指本轮五类报告的完整文本一致，不代表所有游戏事实均已读全；本轮没有活动贸易路线。

完整结构化视图明显大于简报：本轮单次结果约 7.9–9.6 KB，简报约 4.1–5.0 KB，因此默认保留简报。对前 23 份决策响应按相同 JSON 序列化口径还原删除前后的结果，`--compact` 的结果字节降幅中位数为 48.2%；这只统计精确重复文本，不估算模型 token。

配对查询使用固定顺序，样本来自本机早期局面；RPC 时间不包含模型在命令之间的思考、Shell 或人工等待。完整测试时间还包含实施、测试和证据整理，不能据此推导整局总耗时减少 61.7%。

## 模型实际决策与回读

| 阶段 | 当前事实与模型选择 | 实际结果 |
| --- | --- | --- |
| T1 | 河流沿海起点，周边高粮低产，未见敌军；原地建城，研究畜牧业，生产侦察兵，勇士向西探查 | 原生建城、科研、生产及逐段移动确认；从零城变为乌鲁克 |
| T2–T5 | 按新揭露的地形调整探路；T5 看到 25 战斗力蛮族长矛兵 | 保留精确坐标、生命和所有者，没有因为出现攻击候选就自动攻击 |
| T6 | 勇士与长矛兵相邻，直接进攻缺少优势 | 明确驻防，原生确认 `FORTIFIED`；保存 T6 检查点 |
| T7 | 畜牧业完成、首都旁发现受伤蛮族侦察兵 | 改选箭术，调勇士回援；按路径估计与实际分段位置继续判断 |
| T8–T9 | 新侦察兵完成；军事基础弱、仍有蛮族风险 | 生产投石兵，侦察兵巡视南侧；发现香港后驻防山丘 |
| T10–T11 | 法典完成；空政策槽、生产偏低 | 纪律与城市规划确认；选择对外贸易；T11 城市产能由 3 回读为 4，政策槽回读正确 |

T8 的第一次回援以首都为目标，却忽略新侦察兵占据城中心，被原有 `STACKING_CONFLICT` 前置检查拒绝；移动侦察兵后才重新作出回援选择。它没有产生未知提交，但说明提供相同事实不保证模型正确使用事实。另有查询命令拼写／发现错误，保留在原证据中，不计作查询性能样本。

此次验证证明取数成本下降、所比较的输入保持一致、两个事实／提示缺陷已修复，且实际动作和回合推进仍可工作。没有做独立模型的盲测、长期胜率比较或完整终局，本轮不能证明策略质量提高。

## 下一步的改进次序

| 优先级 | 可改进处及依据 | 应实现的能力／验证条件 |
| --- | --- | --- |
| 高 | 稳定规则输出过大。T1 文明规则文本为 33,172 字节，吉尔伽美什规则为 171,594 字节，其中重复 profile 各 13,021 字节；领袖 rule 本体为 132,602 字节 | 提供保留能力、条件、限制、关联入口和来源标识的简洁规则视图，继承关系及原始证据按需展开；先对同一机制问题比较事实覆盖和读取量 |
| 高 | schema-only dry-run 不检查游戏前提；T8 堆叠错误实际发生。生产候选主要给成本／回合，模型仍要自行关联效果和条件 | 独立的原生只读候选／前提预览，可合并比较模型指定的几个方案，返回成本、资格、阻塞原因及证据时点；不排序、不自动选择。验证零提交、未知和状态变化，不能把现有 dry-run 偷换成游戏操作 |
| 中 | 部分 advisor 用固定权重及 Top-N 截断候选。`lua/map.py` 按粮产、资源和水源加权，落城只返回前 5／10 项；奇观报告直接推荐最低地块损失 | 将原始收益、风险和地块代价与启发式分数分开，允许展开其余合法候选。先核验有不同战略价值的真实候选是否被截掉，再决定替换范围 |
| 中 | 当前回合差分主要覆盖本方单位、城市、科研与库存；对手胜利与能力趋势仍需额外取数 | 先量化重复读取，再在同次采集内复用明确同范围的数据；输出原生变化及来源，不跨动作复用陈旧缓存，也不生成固定风险阈值或应对策略 |

这些后续项没有作为本次已完成能力交付。尤其不应通过减少世界身份检查、跳过动作确认、预排多个回合或编写生产／科研优先级来换取表面速度。
