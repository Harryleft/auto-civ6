# 规则知识精简视图验收约定

用户要求实施、测试和四叶草实测，并将实测重点扩展到历史 T50、T100、T150、T200。选择同一四叶草信仰对局的四个已确认检查点，文件与原登记逐一核对；每个起点建立独立测试轮次，原件、历史登记和旧验收结果保留。

## 验收标准

1. 原始 snapshot 和所有 rules JSON 字节不变。精简视图能够逐字段还原全部规则卡，覆盖负值、反向需求、空值／缺席、继承、条件目录未应用状态、重复记录、未知字段和来源；不截断记录、不评价策略。
2. 通过 CLI、内部真实 stdio 和可移植知识包读取同一条目。精简结果包含完整卡片指纹、原始资料版本和 profile 指纹；完整 profile 及原始证据可按入口展开。比较相同条目的完整／精简 UTF-8 读取量。
3. 四个真实阶段先读取当前公开局面，按具体选择读精简规则，写出候选行动与关键条件；随后展开完整规则核验。出现由遗漏或误读导致的选择变化时记录并修复，不把读取量下降单独当作质量通过。
4. 每阶段完成有原生回读的实际决策动作，并另存起点与结果。只推进当前已充分判断且可确认的回合，不为数字机械清除单位、忽略外交／宗教风险或套用生产循环。
5. 历史加载必须显式提供原轮次和精确 SHA-256，并在完整原生加载确认后新建轮次；默认加载继续拒绝跨轮检查点。没有直接 MCP、任意 Lua、内部 setter 或通用策略脚本。

本轮质量结论限于所覆盖的规则条件和实际决策点；不以短时操作或同模型复核证明长期胜率的统计非劣性。
