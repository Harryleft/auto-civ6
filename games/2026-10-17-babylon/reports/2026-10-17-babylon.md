## 约定

新建巴比伦文明、原始规则（不启用风云变幻）、王者难度、快速速度的对局。在第 1 回合、尚未执行游戏动作时保存固定基准，供后续重复验证；从该基准由 Codex 通过本机 stdio MCP 自主净推进 20 回合。游戏内决策由模型完成；每回合记录主要决策、结果、包含思考时间的完整耗时、异常与恢复。回退后重玩的回合不重复计数。

技术故障允许自动重连；必要时显式重启并读取已确认的检查点，每次故障最多一次完整恢复，最多回退 1 回合。不因战局不利读档。恢复后重新核对文明、种子和回合；没有符合回退范围的检查点时停止。

## 实机结果

尚未进入对局，净推进 0 回合。游戏启动后通过原生 FrontEnd API 提交一次巴比伦读档；游戏显示：

> 开始游戏时出现错误。建议禁用模组并重试。错误 - 一个或多个模组尚未购买。

游戏 `Modding.log` 同时记录 `There are ownership issues with the current configuration. Resorting to base config.`。这证明存档所需内容存在授权问题，不能仅凭本机存在 DLC 目录认定内容可用，随后通过原生 MainMenu API 查询 `Modding.GetInstalledMods()`，确认 `巴比伦包`（`8424840C-92EF-4426-A9B4-B4E0CB818049`）返回 `Allowance=false`。因此，切换原始规则也不能消除巴比伦文明本身的授权限制。

因此，保存后能否实际加载、重启恢复、最多回退 1 回合及自主推进 20 回合均未通过实机验收。没有改写存档依赖或切换其他文明。要求的新对局和第 1 回合固定基准尚未建立。

原始工具调用、响应、耗时、工具 schema 与服务日志保存在本机 `~/.civ6-mcp/acceptance/20261017-092321-babylon/`。该目录的 `status.json` 记录初次尝试的存档 SHA-256 和当前验收状态，`babylon-availability.json` 保存游戏原生 API 返回的文明包可用性。
