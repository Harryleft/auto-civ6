# 中期操作流程速度预登记

登记日期：2026-11-01。适用对局为本测试轮次 `0297ba4dfd64429b8fa4a9c97ab93099`，苏美尔／种子 `719665280`，来源为受信原始基准 `benchmark_turn_1`。本文件在 T60 测量开始前固定窗口和口径；后续结果另写报告，不用结果反改本协议。

## 能回答和不能回答的问题

比较同一修复后 Runtime 下，两种模型操作流程的真实墙钟耗时。A 使用既有人工 CLI 流程，B 使用合并预演执行和经当前事实判断为独立的显式命令。所有游戏策略继续由模型逐回合决定。

这是**保守的操作流程对照**，不能估计旧 Runtime 到新 Runtime 的全部收益。连续窗口的局势、单位数和外交事件不同；A–B–B–A 顺序只能部分平衡先后效应，不能使它成为无偏随机实验。某个窗口达到两倍，也不能单独证明整局两倍、战略质量不降或最终获胜。

## 两种流程及共同约束

| 项目 | A：既有人工 CLI 流程 | B：优化流程 |
| --- | --- | --- |
| 每次变更 | 独立 `--dry-run`；模型检查预演后，以另一条命令单次提交 | 使用 `--execute`，同一命令先静态预演再单次提交 |
| 模型工具往返 | 每个 CLI 命令单独一次模型工具调用，完成回读后继续 | 允许在一次模型工具调用中，顺序调用已由模型明确选择的独立命令 |
| 有依赖的操作 | 前一结果回读后再决定下一条 | 相同；不能把依赖动作预先排成批次 |

两组使用相同模型及配置、同一当前修复后 Runtime、同一持续 CLI 控制会话和证据格式。运行前固定源文件指纹及 relay 版本；窗口内不改代码、配置、输出口径或模型设置。A 不加入人为等待、不故意使用错误语法，也不恢复已知低效或错误的策略。

共同要求：

- 每回合先读取相同范围的 `game decision` 当前事实，按实际需要补充生产、科研、外交、地图和战斗查询。不能为了降低调用数省略必要事实、降低查询精度或把未知当不存在。
- 每个动作由模型依当前事实选择。B 同一工具内的顺序调用只承担无策略的传输；没有固定生产／科研／单位优先级循环，没有自动推进回合或自动外交回复。
- “独立”不等于“实体不同”：资源竞争、改变视野、阻塞解除和新敌情都可能改变后续动作。遇到会影响后续选择的新事实、拒绝、pending 或未知结果，停止该组后续提交，把已收到的证据交回模型重新判断。无法保证这一点时，B 也逐条往返。
- pending 期间沿原请求的只读核对及显式回应流程继续；不调用明知会被阻止的完整决策查询，不用普通身份查询／缓存刷新释放门禁，不重发未知操作。确认原回合请求不计为新的推进回合。
- 不以统一跳过单位、忽略战斗风险、放弃增长或省略外交决策来换速度；不要求不同局面采用相同动作。

## 计时边界

每个窗口的起点是该窗口首条 `game decision` 的 CLI `command` 事件开始，终点是确认进入目标回合的 `end_turn` 结果事件。墙钟值按这两个事件的 UTC 时间戳相减；同时保留 monotonic CLI 累计统计作交叉核对，不混用不同端点制造更大的比值。

窗口内计入全部模型决策、工具往返、查询、预演、执行、拒绝、外交／弹窗处理、确认等待及正常进度交流。不得暂停计时来处理困难选择，也不事后扣除慢命令、思考间隔或上下文整理。

边界检查点、工程和报告时间另列：

1. 开始窗口前，允许保存并核验该边界检查点、确认无 pending、记录源文件指纹；这些准备只做生命周期与证据工作，**不能在计时外提前分析下一窗口或规划其动作**。
2. 末回合确认后停止本窗口计时，再保存目标回合检查点。只保存本轮独立名称，保留原始基准及已有检查点。
3. 保存、核验和报告分别记录起止事件／时间及耗时；若必须为保存处理信息弹窗，同样记入边界工作，不伪装成窗口内策略收益。
4. 窗口内不中断做工程、代码审查或离线测试。若出现必须修复的问题，保留截至中断的全部记录，标记“协议中断”，另外记录工程时间；不得删掉该样本后悄悄重跑。后续变更须在下一次测量前另行登记，不能继续声称四段在相同版本下完成。
5. 若发生不可避免的宿主中断或上下文维护，其实际墙钟仍保留在主表，并注明事件；可给带明确标签的诊断拆分，但不取代主结果。

本协议边界与 [T48→T54 的历史诊断](t048-t054-timing.md) 不同；该历史诊断含窗口内保存，不能直接并入本实验的 A 或 B。

## 指标与质量记录

逐窗口记录起止事件 ID、源版本、净推进回合、墙钟、CLI／RPC 累计、命令外时间、模型工具往返数、命令数、工具调用数、预演次数、变更类别、阻塞／拒绝／未知状态及恢复过程。RPC 包含于 CLI 内，不相加；`error_count` 不涵盖所有 blocked／not_submitted 状态，另按结构化结果计数。

在相同回合事实范围内保留以下质量信息，不只记录成功项：

- 城市／人口、科研与文化产出、现金及净收入、生产队列、已完成科技／市政、实际胜利进度和已知对手公开进展。
- 单位数量、伤亡、濒危单位、城市得失、关键战斗预览与实际结果、未处理威胁和被放弃的机会；所有损失原样记录。
- 实际动作数量及类型、外交／交易选择、需要模型判断的复杂事件、未完成强制选择。不能将单位更多、战斗更多的窗口直接当作同等工作量。
- 每回合的简短策略理由与动作回读沿用已有证据；不新增强制日记、反思协议或后台观测服务。

速度对照以 A 两段总墙钟／B 两段总墙钟为主要观察比值；两组均计划十回合，另列每个窗口的秒／回合，避免只挑最快一段。若样本不完整，首先报告中断和实际覆盖，不把不同净回合数的总时长直接相比。按动作类型的耗时只用于解释，不能替代真实墙钟。

对 A、B 做质量复核时须结合局面和决策理由；伤亡或指标恶化不能被平均速度掩盖。即使观察比值达到 2.0，也只能报告本次流程对照结果及混杂因素。整局目标仍需要其他代表性阶段的证据以及原生胜利终局；本协议不预先承诺获胜或把短期质量指标等同于胜率。
