# 第 41～61 回合：跳过、待命与事实叙述

标签：ready-for-agent；本地 Markdown tracker；集成分支沿用 `codex/decision-repair-turn41`。审查基点 `04c2ee7`。工作项见[依赖图](2026-10-18-turn61-readiness-tickets.md)。

## Problem Statement

第 21～41 回合实测发现：skip 调用本机不存在的 GameCore `FinishMoves`；fortify 用历史驻防回合数误判当前就绪单位已待命；报告将单位消失断言为阵亡、国内贸易收益写给目的地、当前黄金时代与下一时代积分门槛混淆。这些错误妨碍推进和策略判断。证据见[前轮验收](../reports/2026-10-18-decision-repair-turn41.md)。

## Solution

先修单位跳过与待命入口，再修事实叙述。使用本机原生 UI 操作及当前状态，区分已提交、已确认、拒绝和未知；缺少原因证据时只报告单位不再出现。离线通过后，从本轮已验证 T41 检查点继续到 T61，按实际局面修正获胜路线，保留所有旧档、过程档和原始证据，不 push。

## User Stories

1. 作为游戏 Agent，我要通过原生跳过操作结束单位本回合行动，以便继续推进。
2. 作为游戏 Agent，我要跳过仅当前就绪单位，保留已待命、自动移动和贸易单位的任务。
3. 作为游戏 Agent，我要批量入口使用同一跳过资格和操作，避免第二套语义。
4. 作为游戏 Agent，我要批量处理如实报告部分失败或未知，不在异常后盲目继续提交。
5. 作为游戏 Agent，我要历史驻防加成与当前活动分离，自动恢复就绪后仍能重新待命。
6. 作为游戏 Agent，我要已经待命的单位保持现状，不被查询或重复操作唤醒。
7. 作为游戏 Agent，我要操作缺失或资格未知时明确失败，避免直接修改移动力作为兼容方案。
8. 作为游戏 Agent，我要未知回应保持门禁与单次提交约束，避免重复操作。
9. 作为游戏 Agent，我要单位消失报告不虚构阵亡、解散、被俘或正常消耗原因。
10. 作为游戏 Agent，我要国内贸易说明准确标注起点收益。
11. 作为游戏 Agent，我要当前时代状态与下一时代积分门槛分别呈现；原生年龄状态缺失时保留未知。
12. 作为验收者，我要 T41→61 净 20 回合以及保存、恢复的回读证据，以便确认修复可用于当前局面。
13. 作为项目维护者，我要现有存档和验收指纹不变，新成果独立归档，以便复查完整历史。

## Implementation Decisions

- 单位领域共用原生跳过资格、当前就绪／活动解释；本机操作表包含 `UNITOPERATION_SKIP_TURN`，通过 InGame 原生 CanStartOperation／RequestOperation 路径提交。提交返回不冒充后续完成。
- fortify 的无操作成功必须基于当前待命事实，历史 GetFortifyTurns 仅表示加成积累。当前就绪单位重新检查原生 fortify／sleep 资格。
- 单个与批量入口沿用现有 ActionLifecycle 与门禁。批量资格选择、已提交结果和未决状态可观察；异常后不自动重发或改用其他操作。现有可选战斗单位 fortify／heal 行为如保留，须明确与纯 skip 的职责及当前就绪边界。
- 差分快照只能证明单位不再出现，不新增死亡原因推测系统。国内贸易收益归属修正文案；时代积分明确为下一时代门槛，当前年龄只使用原生已知值。
- 保持工具接口及本机游戏范围，不引入固定策略、后台控制或额外测试驱动。常规恢复优先菜单换档，完整重启仅用于故障恢复。

## Testing Decisions

- 沿用用户此前确认的 GameState／FakeConn、原生 Lua 5.1 执行、内存流、快照差分、临时存档目录边界，无需新增测试边界。验证公共查询／动作与可观察提交、回读、门禁，不用源码文本断言替代行为。
- 回归覆盖：缺失 FinishMoves 的原生环境仍可 skip；单个／批量只处理当前就绪者；跳过资格拒绝、缺少 API、异常或异步未完成；历史驻防大于零但重新就绪；已待命 no-op；受伤 heal 与 full-health wake；单位消失原因未知；国内贸易起点；黄金／普通／未知年龄和下一时代门槛。
- 实施者逐项 red→green；集成执行锁定依赖、完整 pytest、compileall、diff 检查及双轴独立审查。
- 实机先核对本轮 T41 文件指纹、身份、回合、城市和单位，再续推到 T61。至少保存中途及最终结果，回读单位待命、推进和更正后的文本；最终菜单恢复比对关键状态。未在本轮自然出现的分支明确标为离线覆盖。
