# 建造者真实历史局面的三回合 Jev 影子对照

2026-11-02，隔离测试已完成 T70→T73，结果另存，并恢复受保护的 T106。Jev 只提供候选选择，没有游戏连接或执行权；游戏由主模型通过同一个 CLI 会话操作。长期整局提速目标保持暂停。

本轮证明了 Jev 在这些实际局面中能给出部分可采用的局部建议，也暴露出候选覆盖、取舍复核及现场资格检查的成本。**不能据此宣布决策质量不降、独立正确率或实际提速。**

## 来源、隔离与版本

按[预登记](protocol.md)，从 A2 的 T70 已确认检查点另开历史轮次 `bb50ed9ba0294fcc89abacc03ae5c92d`。来源轮次、精确存档指纹、另存起点及结果见[检查点证据](../evidence/checkpoints.json)。原始基准和旧检查点未覆盖。相同 Runtime、PID 和 CLI 所有者一直保留。

本次将实验请求从上轮固定版本选择改为官方 `jev-latest`。一次独立版本握手和四次业务请求均实际返回 `jev-1.14.0`；当前没有实测确认的更高稳定版本，不能把选择器更新说成模型权重升级。未修改本机 API Key、SDK 或旧实验结果。请求及实际版本分别保留在 [model-config.json](../evidence/model-config.json)、[version-check.json](../evidence/version-check.json)及各原始响应中。官方[模型说明](https://docs.typesafe.ai/models)也说明了别名与实际响应版本的区别。

## 对照方法

每个真实可行动回合读取当前概览、单位、城市、地图、工作地块、原生路径和必要领域事实，构造三名建造者的有限候选。主模型在查看对应 Jev 回答前，封存首选、合理替代和理由；独立审查者只看该轮请求，先给盲评，再查看结果。四份参考文件的 SHA-256、创建时间和封存标记均可核对，未发现把随后执行结果放入请求。

四份输入共含 15／15／16／19 条来源回执，正文和时间戳均与当时 CLI 记录一致且早于调用。主模型的目标、预留地块、任务和解释单列为人工计划，不能混称原生事实。候选包含等待、补查、改良、伐木和不同城市的任务，不只设置明显错误的干扰项。

Jev 只返回 Choice、概率分布和置信度，不生成推理解释。现场移动和施工是不同决定；主模型在移动回读后检查资格，必要时重新决定。不能把一次“前往检查”建议算作已经正确选择并完成后续施工。

## 实机结果与代价

三次推进分别有 #7275、#7390、#7548 原生完成回执。所有原有 11 个单位、5 座城市和三名建造者在 T73 保留；人口 23→25，科技 16→18，科研 35.6→40.4，文化 28.0→31.2。未观察到本轮城市、单位或人口损失；这不等于所有选择最优或胜率已验证。

建造者次数分别为 `1441792：1→1`、`1572865：5→3`、`1638409：5→2`。每一次减少均有牧场、移除森林、采石场、农场或矿山的原生回执；维修没有消耗次数。

## 恢复、审计与结论

T73 另存 `jev_20261102_shadow_t073`，SHA-256 `509cf286b168fcb1e1616dfee030266c8a288d8dc489c6a8120e7de27dfe386e`。随后通过带原轮次与精确 SHA 的历史加载入口恢复 `jev_20261102_preserve_a2_t106`。#7574、#7577、#7580 分别回读概览、单位、城市；#7582 所有 pending=false、`transport_unknown=null`，Runtime 与 PID 保持不变，恢复后没有再推进。

恢复流程通过，但不能宣称全部状态逐字段相等：原生总分 358→365、分类分数不变，科研 92.8→95.0；文件、文明、种子、回合和实体核对通过，不会把这些差异隐去。完整世界状态等价未证明。

独立只读审查核验了原始来源、参考封存、请求哈希、版本、计数、动作确认、次数变化、计时和末次恢复。当前 103 个冻结源码／依赖文件 SHA 全部一致，游戏源码没有修改；未为纯实验报告重跑无关离线测试。

当前较合适的分工仍是：主模型负责目标、候选覆盖、跨单位协调和风险取舍；Jev 给有限下一步建议；主模型复核后，Runtime 按原生资格单次执行和确认。明确的维修任务可减少部分重复判断，但真实取舍仍有低置信度、升级和改判，本轮没有证明总成本已经减少。优先改进可引用的候选覆盖、精简输入和具体补查问题，再考虑新的不中断对照；不增加通用策略或自动推进脚本。
